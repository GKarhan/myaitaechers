PART 2 — SOURCE BLOCK / PASS 1 TRACE
═══════════════════════════════════════════════════

Պարզիր՝ extraction-ը ստեղծո՞ւմ է source blocks։

* sourceText
* sourcePage
* sourceParagraph
* sourcePosition
* sourceBoundingBox
* blockType
* block index / ID
* source order
* exercise blocks
* question blocks
* example blocks
* definition/rule/explanation blocks
* table blocks
* activity/project/homework blocks

Պարզիր.

1. AI-ին պարտադրվա՞ծ է բոլոր source blocks-ը պահպանել։
2. Կա՞ source coverage gate։
3. Կա՞ unmapped block validation։
4. Կարո՞ղ է Pass 2-ը պարզապես չօգտագործել extraction-ի block-ը։
5. Որտե՞ղ է պահվում extracted block-ը։
6. DB-ում առանձին source-block storage կա՞։
7. Եթե չկա՝ source block-ի տվյալները ինչպե՞ս են պահպանվում։

Հատուկ trace արա Lesson 101-ի համար.

mapping job = 15

Եթե mapping metadata-ն ասում է՝

pass1BlocksExtracted = 25

ապա պարզիր՝ այդ 25 block-երը իրականում որտե՞ղ են։

Տուր.

25 extracted blocks
→ քանի՞սն են մտել Pass 2
→ քանի՞սն են կապված node-ի հետ
→ քանի՞սն են կապված exercise-ի հետ
→ քանի՞սն են մնացել unmapped
→ վերջնական DB-ում դրանց trace կա՞, թե ոչ

Եթե 25 block-ից որևէ block կորչում է՝ ցույց տուր կոնկրետ block index-ը և կորելու փուլը։

═══════════════════════════════════════════════════
PART 3 — FIELD-BY-FIELD 6-STEP TRACE
═══════════════════════════════════════════════════

Յուրաքանչյուր field-ի համար պատասխանիր հետևյալ 6 հարցին։

1. PROMPT
   Automatic Mapping-ի իրական ներկայիս AI prompt-ում այս field-ը պահանջվո՞ւմ է։

Եթե այո՝ paste արա exact prompt հատվածը։

2. AI SCHEMA
   AI response schema-ն թույլ տալի՞ս է այս field-ը վերադարձնել։

Ցույց տուր exact schema/interface հատվածը։

3. AI RESPONSE
   Իրական AI response-ում field-ը կա՞։

Եթե production raw response կա՝ օգտագործիր այն։

Եթե raw response չկա՝ կարող ես կատարել READ-ONLY test mapping run։

Բայց test run-ի ժամանակ.

⚠️ ոչ մի DB write
⚠️ ոչ մի code change
⚠️ ոչ մի persistent data change

Ցույց տուր raw response-ի համապատասխան հատվածը։

Եթե հնարավոր չէ ստանալ real response՝ գրիր `NOT VERIFIED`։

4. MAPPER
   AI response-ից դեպի DB transformation layer-ում field-ը փոխանցվո՞ւմ է։

Ցույց տուր exact code։

5. DB
   Իրական DB query-ով ստուգիր Lesson 101-ի տվյալը։

Ցույց տուր actual stored value-ը։

6. UI
   Եթե DB-ում արժեք կա՝ ստուգիր արդյոք UI-ն այն կարդում և ցուցադրում է։

Եթե DB-ում արժեք կա, բայց UI-ում չկա՝ դա առանձին root cause է։

PART 4 — CLASSIFICATION
═══════════════════════════════════════════════════

Յուրաքանչյուր field-ի համար վերջում տուր հետևյալ classification-ը.

A — Chain complete / DB-ում ճիշտ կա

B — Prompt gap
Prompt-ը field-ը չի պահանջում

C — Schema gap
Prompt-ը պահանջում է, բայց AI response schema-ն field-ը չի թույլատրում

D — Mapper/Transformation bug
AI response-ում field-ը կա, բայց DB insert/update object-ում չի փոխանցվում

E — Architecture/DB gap
DB schema-ում field-ը ընդհանրապես գոյություն չունի

F — UI gap
DB-ում field-ը կա և արժեք ունի, բայց UI-ն չի կարդում կամ չի ցուցադրում

G — AI generation gap
Prompt + schema-ում field-ը կա, բայց իրական AI response-ում field-ը չի վերադարձվում

H — DB write/storage gap
Mapper-ը field-ը փոխանցում է, բայց DB-ում վերջնական արժեք չկա

Մի՛ ընտրիր classification-ը առանց evidence-ի։
