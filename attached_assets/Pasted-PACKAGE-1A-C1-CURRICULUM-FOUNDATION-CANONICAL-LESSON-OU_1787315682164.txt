PACKAGE 1A — C1 CURRICULUM FOUNDATION
CANONICAL LESSON OUTCOMES + OUTCOME↔MICRONODE ALIGNMENT
+ C1→C2 REQUIRED COGNITIVE DEPTH

IMPLEMENTATION TASK — CONTROLLED ADDITIVE MIGRATION

GOAL

Implement the minimum safe C1 curriculum foundation identified by the
Package 0 read-only audit.

We are NOT rebuilding Mapping.
We are NOT rebuilding Cognitive Path.
We are NOT changing Evidence, Learner Model, Knowledge Tree, Quiz,
AI Teacher runtime behavior, recommendations, or school operations.

The purpose of this task is to establish a durable curriculum chain:

Lesson Goal
→ Lesson Outcomes
→ Topic
→ MicroNode
→ required cognitive depth
→ existing MicroNode Cognitive Path

After this task, a lesson outcome must be a durable curriculum object,
not merely an anonymous string inside lessonOutcomes JSON.

Every approved curriculum MicroNode must be able to explicitly support
one or more Lesson Outcomes.

The Outcome↔MicroNode relation must express:

- REQUIRED
- SUPPORTING
- required cognitive depth

Existing lessons and existing Cognitive Paths MUST continue working.

════════════════════════════════════════════════════
3 — OUTCOME ↔ MICRONODE RELATION
════════════════════════════════════════════════════

Implement an explicit persistent relation between:

Lesson Outcome
↔
MicroNode / lesson_node

A MicroNode may support MORE THAN ONE Outcome.

An Outcome may require MORE THAN ONE MicroNode.

Therefore do NOT implement a single outcomeId directly on lesson_nodes
unless repository evidence proves that it can safely represent the
many-to-many contract.

The relation must support:

A. role

Allowed values:

REQUIRED
SUPPORTING

Meaning:

REQUIRED
= this MicroNode is necessary for confirming the Outcome.

SUPPORTING
= this MicroNode contributes to the Outcome but is not independently
required for Outcome confirmation.

B. required cognitive depth

The relation must identify the cognitive depth required from this
MicroNode for THIS Outcome.

Example:

Outcome O1
→ MicroNode MN1
→ REQUIRED
→ required depth = UNDERSTAND

Outcome O1
→ MicroNode MN2
→ REQUIRED
→ required depth = APPLY

Outcome O2
→ MicroNode MN2
→ SUPPORTING
→ required depth = UNDERSTAND

Do not store this as uncontrolled display text if an existing Cognitive
Level identity can be safely referenced.

Prefer referencing the existing Cognitive Path / cognitive-level model
where technically appropriate.

But avoid creating a fragile FK if Cognitive Path rows can be
regenerated/deleted during teacher editing.

You MUST inspect this lifecycle before choosing the exact FK design.

The persisted curriculum requirement must survive ordinary Cognitive
Path editing safely.

════════════════════════════════════════════════════
4 — IMPORTANT C1 ↔ C2 RULE
════════════════════════════════════════════════════

Do NOT merge Lesson Outcomes and Cognitive Paths.

They have different responsibilities.

C1 says:

WHAT curriculum outcome must be achieved?

C2 says:

HOW DEEP must this MicroNode be demonstrated and through what cognitive
path?

Canonical ownership:

Lesson Outcome
↔ MicroNode
↔ required cognitive depth

MicroNode
→ its existing ordered Cognitive Path

The current Cognitive Path remains MicroNode-scoped.

Do NOT duplicate the entire Cognitive Path per Outcome.

If one MicroNode supports multiple Outcomes with different required
depths, the Outcome↔MicroNode relation stores the relevant required
depth.

Example:

MN7 Cognitive Path:

Remember
→ Understand
→ Apply
→ Analyze

O1 requires MN7 through Apply.

O2 uses MN7 only as Supporting through Understand.

This must be representable without duplicating MN7 or its Cognitive Path.

════════════════════════════════════════════════════
5 — TARGET COGNITIVE LEVEL CONSISTENCY
════════════════════════════════════════════════════

The current system already has target ceiling / target Cognitive Path
semantics.

Do NOT redesign them in this task.

However, after introducing Outcome-required depth, detect semantic
inconsistencies.

Example:

MicroNode Cognitive Path target ceiling = UNDERSTAND

but a REQUIRED Outcome relation says:

required depth = APPLY

This is invalid.

Implement validation/warning using the safest current project pattern.

Required rule:

For every REQUIRED Outcome↔MicroNode relation:

MicroNode approved/target Cognitive Path must be capable of reaching
the required cognitive depth.

Do NOT automatically raise the target.

Do NOT let AI silently change it.

Teacher must resolve the inconsistency.

SUPPORTING relation should also reference a valid existing/allowed
cognitive depth, but it does not independently determine Outcome
mastery.
