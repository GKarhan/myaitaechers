# PART 4.1 — QUESTION-LEVEL FEEDBACK / EXPLANATION

Թեստի արդյունքների էջում յուրաքանչյուր հարցի համար պետք է ավելացվի **պատասխանի մանկավարժական վերլուծություն**։

Նպատակը ոչ միայն ցույց տալն է՝ ճիշտ է կամ սխալ, այլ աշակերտին հասկացնելը՝ **ինչու է պատասխանը ճիշտ կամ սխալ, և որն է ճիշտ պատասխանը ու ինչու**։

---

## 1. ՃԻՇՏ ՊԱՏԱՍԽԱՆԻ ԴԵՊՔ

Եթե աշակերտը ճիշտ է պատասխանել, ցուցադրել.

### Ինչու է ճիշտ

Կարճ, պարզ և երեխային հասկանալի բացատրություն, որը հիմնված է դասի իրական բովանդակության վրա։

Օրինակ՝

**✅ Ճիշտ պատասխան**

**Ինչու է ճիշտ․**
Հազարների դասում գրված թիվը ցույց է տալիս, թե քանի հազար կա տվյալ թվի մեջ։

Չպետք է պարզապես գրել.

> «Ճիշտ է»։

Պետք է բացատրել **ինչ կանոնի կամ գիտելիքի հիման վրա է ճիշտ**։

---

## 2. ՍԽԱԼ ՊԱՏԱՍԽԱՆԻ ԴԵՊՔ

Եթե աշակերտը սխալ է պատասխանել, ցուցադրել առնվազն երեք բաղադրիչ.

### ① Քո պատասխանը

Ցույց տալ աշակերտի ընտրած պատասխանը։

### ② Ինչու է այն սխալ

Բացատրել կոնկրետ սխալը։

### ③ Ճիշտ պատասխանը

Ցույց տալ ճիշտ տարբերակը։

### ④ Ինչու է ճիշտ

Բացատրել, թե ինչ կանոնի կամ գաղափարի հիման վրա է ճիշտ պատասխանը։

Օրինակ՝

**❌ Սխալ պատասխան**

**Քո պատասխանը՝** Ձախից աջ

**Ինչու է սխալ․**
Թիվը դասերի բաժանելիս սկսում ենք աջ կողմից, քանի որ առաջին դասը միավորների դասն է։

**Ճիշտ պատասխանը՝** Աջից ձախ

**Ինչու է ճիշտ․**
Թվերը դասերի բաժանելիս աջից սկսում ենք առանձնացնել երեքական թվանշաններով։

---

# 3. ՉՀՈՐԻՆԵԼ ԲԱՑԱՏՐՈՒԹՅՈՒՆ

Բացատրությունը պետք է հիմնված լինի միայն վստահելի source-ի վրա։

Օգտագործել առաջնահերթությամբ.

1. Question-specific explanation, եթե արդեն կա
2. Տվյալ question-ի source/theory content
3. Դրան համապատասխան lesson node-ի հաստատված բացատրություն
4. `childFriendlyExplanation`
5. `commonMisconception`

Եթե վստահելի բացատրություն չկա՝

**չհորինել AI-generated explanation-ը որպես փաստ**։

Այդ դեպքում feedback-ը թողնել NULL/չցուցադրել։

---

# 4. ՃԻՇՏ ԵՎ ՍԽԱԼ ՊԱՏԱՍԽԱՆՆԵՐԸ ՉՇՓՈԹԵԼ

Յուրաքանչյուր question-ի feedback-ը պետք է կապված լինի հենց այդ question-ի հետ։

Օրինակ՝

```text
questionId
studentAnswer
correctAnswer
feedback
```

Չպետք է հնարավոր լինի մեկ հարցի explanation-ը ցուցադրել մեկ այլ հարցի տակ։

---

# 5. API STRUCTURE

Յուրաքանչյուր question-ի result-ում պահել մոտավորապես այս կառուցվածքը.

```json
{
  "questionId": 179,
  "isCorrect": false,
  "studentAnswer": "2",
  "correctAnswer": "3",
  "feedback": {
    "whyWrong": "Դասը կազմվում է երեք հաջորդական կարգից, ոչ թե երկուսից։",
    "whyCorrect": "Ճիշտ պատասխանը 3-ն է, որովհետև մեկ դասում ընդգրկվում է երեք կարգ։"
  }
}
```

Ճիշտ պատասխանի դեպքում.

```json
{
  "questionId": 182,
  "isCorrect": true,
  "studentAnswer": "Հազարների քանակը",
  "correctAnswer": "Հազարների քանակը",
  "feedback": {
    "whyCorrect": "Հազարների դասում գրված թիվը ցույց է տալիս հազարների քանակը։",
    "whyWrong": null
  }
}
```

Սխալ պատասխանի դեպքում `whyWrong`-ը պարտադիր վերաբերում է **աշակերտի ընտրած կոնկրետ սխալ տարբերակին**, իսկ `whyCorrect`-ը՝ ճիշտ տարբերակին։

---

# 6. FRONTEND DISPLAY

Յուրաքանչյուր հարցի տակ ավելացնել համապատասխան բացատրության հատված։

### Ճիշտ պատասխանի դեպքում

```text
✅ Ճիշտ պատասխան

Քո պատասխանը՝ Հազարների քանակը

💡 Ինչու է ճիշտ

Հազարների դասում գրված թիվը ցույց է տալիս հազարների քանակը։
```

### Սխալ պատասխանի դեպքում

```text
❌ Սխալ պատասխան

Քո պատասխանը՝ Ձախից աջ

Ինչու է սխալ

Դասերի բաժանումը սկսում ենք աջ կողմից։

Ճիշտ պատասխանը՝ Աջից ձախ

Ինչու է ճիշտ

Թիվը դասերի բաժանելիս սկսում ենք աջից և թվանշանները խմբավորում ենք երեքական։
```

Բոլոր label-ները պետք է լինեն հայերեն։

---

# 7. IMPORTANT — EXPLANATION QUALITY

Բացատրությունները պետք է լինեն.

* կարճ
* պարզ
* երեխային հասկանալի
* կոնկրետ
* տվյալ հարցին համապատասխան
* հիմնված դասի նյութի վրա

Չօգտագործել չափազանց ակադեմիական կամ բարդ լեզու։

Չգրել երկար ընդհանուր դասախոսություն։

Նպատակն է, որ աշակերտը տվյալ հարցի սխալից հասկանա՝ **ինչ պետք է իմանար կամ ինչ կանոն էր պետք կիրառել**։

---

# 8. DO NOT CHANGE SCORING

Այս փոփոխությունը միայն feedback/explanation layer է։

Չփոխել.

* score
* correct/incorrect determination
* mastery
* confidence
* Knowledge Tree
* evidence events
* student analysis
* recommendation algorithm

Միայն ավելացնել/ցուցադրել բացատրական տվյալը։

# 9. VERIFICATION

Պարտադիր ստուգել առնվազն.

### Case A — ճիշտ պատասխան

Պետք է երևա.

* Ինչու է ճիշտ

և **չպետք է երևա սխալ պատասխանի բացատրություն**։

### Case B — սխալ պատասխան

Պետք է երևա.

* աշակերտի պատասխանը
* ինչու է սխալ
* ճիշտ պատասխանը
* ինչու է ճիշտ

### Case C — explanation չկա

Եթե վստահելի explanation source չկա՝

* չհորինել
* չցուցադրել դատարկ կամ կեղծ բացատրություն

### Case D — 10 հարց

Բոլոր 10 հարցերի explanation-ը պետք է կապված լինի հենց համապատասխան question-ի հետ։

### Case E — նույն Node-ի բազմաթիվ հարցեր

Նույն Node-ի տակ գտնվող տարբեր questions-ը պետք է ունենան **առանձին feedback** և չպետք է իրար explanation-ները խառնվեն։

# FINAL REQUIREMENT

Թեստի արդյունքների էջում աշակերտը պետք է կարողանա յուրաքանչյուր հարցի համար հասկանալ.

> **Ի՞նչ պատասխանեցի ես։
> Ճի՞շտ էր, թե՞ սխալ։
> Եթե սխալ էր՝ ինչո՞ւ էր սխալ։
> Ո՞րն էր ճիշտ պատասխանը։
> Ինչո՞ւ էր ճիշտ պատասխանը ճիշտ։**

Սա պետք է իրականացվի որպես **Question-Level Feedback**, ոչ թե ընդհանուր Test-Level explanation։
