The forensic audit of mapping job 187 established:

Nevertheless, five clean candidates became:

The decisive cause was deterministic post-processing:

detectCompoundLO(learningObjective) !== null

The current helper detects connectors such as:

և / եւ / ու / կամ / and / or

and uses broad suffix-based Armenian “verb-like” detection.

This can create false positives.

Example:
“չափի և քանակի”

can be interpreted as compound because a noun ending in “-ի” can look verb-like to the heuristic.

It also creates false negatives:
genuinely compound objectives can pass if the heuristic does not recognize the second action.

Therefore:

detectCompoundLO() may remain as an ADVISORY SIGNAL if useful,
but it MUST NOT independently determine terminal atomicity or block promotion.

Do not simply delete all atomicity protection.

Replace the weak terminal heuristic with a structured semantic decision contract.

==================================================
B. FUNDAMENTAL KNOWLEDGE MODEL
==================================================

Mapping Core answers:

“WHAT independently teachable and assessable knowledge exists in the curriculum?”

Cognitive Path answers:

“WHAT cognitive operations/depth are needed to learn or demonstrate that knowledge?”

These MUST remain separate.

Multiple verbs or cognitive operations do NOT automatically mean multiple MicroNodes.

Examples:

recognize X
explain X
give examples of X
apply X

may represent different cognitive operations over ONE knowledge target.

Conversely:

knowledge A + independently assessable knowledge B

may require separate MicroNodes.

The decision must therefore be based on KNOWLEDGE IDENTITY and independent teachability/assessability, not merely the number of verbs or connectors.

==================================================
D. DECISION SEMANTICS
==================================================

1. KEEP_ATOMIC

Use when the candidate represents one coherent, independently teachable and assessable knowledge target.

Several verbs/actions are allowed if they operate on the SAME knowledge identity.

Examples:

“recognize and give examples of time adverbs”

does NOT automatically imply two MicroNodes.

“explain what manner adverbs are and what they indicate”

does NOT automatically imply two MicroNodes.

The decision must be based on whether the underlying curriculum knowledge is independently separable.

--------------------------------------------------

2. SPLIT_REQUIRED

Use only when the candidate contains two or more genuinely independent knowledge targets that can be taught and assessed separately.

A split MUST NOT be accepted merely because:
- there are two verbs,
- there is “և”,
- Bloom demands differ,
- an exercise has multiple steps.

Automatic split is allowed ONLY if deterministic validation proves:

a. at least 2 children,
b. each child has a distinct observable success criterion,
c. each child has direct verified source support,
d. child core-source sets form an exact partition of the parent core-source set,
e. partitions are disjoint,
f. no child is source-less,
g. no source ownership duplication is introduced,
h. exercises are deterministically preserved/reassigned,
i. existing source coverage/alignment/ownership validation still passes.

If these conditions cannot be proven:

REVIEW_REQUIRED

Do NOT guess a split.

--------------------------------------------------

3. MERGE_OR_SUPPORT_EXISTING

Use when the candidate does not represent a new independent knowledge identity but its source/practice evidence belongs to an existing candidate.

Examples may include:
- examples supporting an already discovered concept,
- practice material,
- redundant explanation of an existing knowledge target.

Requirements:

- targetCandidateId must exist and be unambiguous,
- source provenance must be preserved,
- exercise provenance must be preserved,
- source transfer must use existing ownership-safe mechanisms,
- activity ownership reconciliation must remain authoritative,
- original candidate must remain observable through M3-1 diagnostics,
- never silently delete candidate evidence.

If target candidate is ambiguous:

REVIEW_REQUIRED

--------------------------------------------------

4. COGNITIVE_PATH_VARIATION

Use when the candidate primarily represents another cognitive operation over the SAME underlying knowledge target.

Examples:

recognition,
recall,
explanation,
example generation,
application,
classification practice,

when these do not introduce a separate independently teachable curriculum knowledge identity.

IMPORTANT:

This does NOT create a new canonical learner-state target merely because cognitive demand differs.

Preserve the evidence and diagnostic relation to the underlying candidate.

Do NOT generate Cognitive Path rows here.

C2 remains responsible for cognitive-path generation after canonical mapping.

--------------------------------------------------

5. REVIEW_REQUIRED

Use whenever semantic evidence is insufficient, contradictory, ambiguous, or deterministic validation cannot safely execute the proposed semantic action.

Fail closed.

Preserve the candidate through M3-1 review artifacts.
