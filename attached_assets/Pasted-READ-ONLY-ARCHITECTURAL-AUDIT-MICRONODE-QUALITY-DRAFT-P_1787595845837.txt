IMPORTANT PRODUCT DECISION

We are changing the fundamental behavior of mapping quality review.

==================================================
CORE PRINCIPLE
==================================================

IF THE MAPPING IS STRUCTURALLY SAFE,
THE GENERATED MAPPING MUST BE SAVED AS A DRAFT.

Pedagogical quality concerns must NOT destroy an otherwise structurally
valid generated mapping.

The teacher is the final authority.

Examples of PEDAGOGICAL REVIEW concerns:

- possible duplicate MicroNodes
- possible over-fragmentation
- possible under-fragmentation
- weak learning objective
- questionable Topic assignment
- questionable outcome alignment
- semantic similarity between MicroNodes
- semantic-review uncertainty
- duplicate-review model failure/rejection

These should become:

SAVE DRAFT + REVIEW WARNING

NOT:

DISCARD ENTIRE MAPPING

The teacher must later be able to:
- keep the MicroNode
- edit it
- delete it
- merge it
- split it
- move it
- reorder it
- approve it

==================================================
HARD BLOCKERS MUST REMAIN HARD
==================================================

Do NOT weaken structural/source/data-integrity protections.

Examples that should still block persistence if they cannot be safely
repaired:

- invalid source block index
- missing required source placement
- contradictory source ownership
- invalid references
- malformed canonical structure
- parser/schema corruption
- source fidelity failure that makes persistence unsafe
- database integrity failure

Existing deterministic safe repairs should remain.

==================================================
MICRONODE QUALITY MODEL
==================================================

Audit whether the current implementation correctly distinguishes:

1. DUPLICATE
Two MicroNodes represent substantially the same atomic knowledge/objective.

2. OVER-FRAGMENTATION
One natural atomic knowledge unit has been unnecessarily split into multiple
MicroNodes.

3. UNDER-FRAGMENTATION
One MicroNode contains multiple independently teachable/testable learning
objectives and should probably be split.

These are pedagogical quality findings, not automatically structural
corruption.
