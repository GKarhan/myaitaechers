STEP 1 — Backend: new manual-mapping endpoint
═══════════════════════════════════════════════════

Add POST /lessons/:id/manual-map, same file/pattern as the auto-map route.

Request body: { rawText: string }

Processing:

1. Strip ```json / ``` fences from rawText if present.
2. Compute rawTextHash = hash(rawText). Check mappingImportLog for an
   existing row with this lessonId + hash — if found, return that
   existing import's result instead of re-processing (idempotency: guards
   against accidental double-click / double-submit before the first
   request finishes).
3. JSON.parse the result.
   - On failure: 400, Armenian message: "AI պատասխանը թերի կամ սխալ
     ձևաչափով է։ Փորձիր կրկին կամ մասերով ուղարկիր ավելի քիչ էջ։"
     No partial DB write.
4. normalizeIncomingMapping() — a tolerant pre-validation pass that
   accepts minor shape variance from the external AI without rejecting
   outright: e.g. learningObjective as a plain string → wrap as
   {text: str, origin: "DERIVED_FROM_TEXTBOOK"}; missing optional arrays
   → default to []. Only normalize fields where the safe interpretation
   is unambiguous — never guess at missing required content.
5. Schema validation — reuse the Step 0.6 helper. Every microNode needs:
   microNodeId, title, microNodeType, learningObjective (.text + .origin),
   sourceBlockIds (non-empty), exerciseIds. Failing items excluded from
   the write and logged as review items (not silently dropped).
6. Source-integrity check — for each sourceBlockId/sourcePage, confirm it
   exists in the lesson's real stored source blocks (Step 0.4). If this
   lesson has no stored source blocks (never auto-mapped), fall back to
   page-range check only and flag every microNode as
   "sourcePage-unverified" review items — do not silently treat range-only
   as verified.
7. Duplicate check — normalize each title (lowercase/trim/collapse
   whitespace) and compare via Levenshtein similarity >0.9 ONLY against
   other microNodes under the SAME parent Node in this lesson (not
   lesson-wide) — avoids false positives between genuinely distinct
   same-named MicroNodes under different Nodes. Matches are not created;
   flagged: "Կրկնվող կամ նման MicroNode վերնագիր՝ [title]".
8. On success, write to the tables confirmed in Step 0.2, setting on
   every created row: contentSourceType='manual', createdBy='teacher',
   status='needs_review', confidenceScore=null, sourceText=verbatim block
   text from the parsed JSON.
9. Write one mappingImportLog row: lessonId, source='manual',
   mappingMode='MANUAL_AI_JSON', rawInput=rawText, rawTextHash,
   mappingSchemaVersion="1.0", importedAt, importedBy.
10. Write one row per flagged issue to mapping_review_items: lessonId,
    entityId, issueType, severity, description, status='open' — persisted,
    not just returned in the response, so the review dashboard can show
    a running "⚠ N unresolved mapping issues" count later.
11. Return created IDs + review items, in the SAME shape as GET
    /lessons/:id/mapping-report (Step 0.3), plus one addition:
    "mappingOrigin": "manual" — for frontend badging, no new response
    format.
