### Problem

Current behavior is technically valid but pedagogically weak.

The AI sometimes creates temporary exercise-only MicroNodes with empty `sourceBlockIndices`. The safety-net correctly strips those MicroNodes and moves their exercises to `additionalExercises`.

This means exercises remain in the database, but they lose their MicroNode relationship.

Example from Lesson 104:

* MicroNode: `Անհայտ նվազելիի գտնելը` → exercises 114, 115
* MicroNode: `Անհայտ հանելիի գտնելը` → 0 exercises
* MicroNode: `Անհայտ գումարելիի գտնելը` → 0 exercises

* exercises 116–121 → `additionalExercises`
* only exercise 122 is genuinely defensible as lesson-level/cross-node activity

The goal is to make Pass2 use the **existing theory MicroNodes much more effectively**.

# Required prompt change

Find `PASS2_STEP2_SYSTEM` in:

`artifacts/api-server/src/services/lesson-mapping.ts`

Strengthen the rules governing EXERCISE / ACTIVITY / HOMEWORK placement.

Add the following conceptual rules to the prompt.

### 1. Existing MicroNode gets priority

For EVERY EXERCISE / ACTIVITY / HOMEWORK block:

First inspect all existing MicroNodes in the current topic.

Ask:

> Which existing MicroNode has the closest Learning Objective (LO) to the skill this activity actually practices?

If there is a reasonable semantic match, **assign the block to that existing MicroNode's `exercises[]`**.

Do NOT create another MicroNode merely because the exercise is phrased differently or requires a different problem format.

The exercise does NOT need to look like the theory text.

A MicroNode represents the underlying learning objective/skill, not a particular exercise format.

---

### 2. Exercise format must NOT determine MicroNode ownership

Explicitly add:

> Do not create a new MicroNode because an exercise is a word problem, interpretation task, multi-step problem, fill-in-the-blank, discussion question, computation drill, or real-world application.
>
> These are exercise formats, not necessarily different learning objectives.

Example:

An exercise asking a student to interpret what a difference means still belongs to the existing MicroNode whose LO teaches the meaning/relationship of subtraction.

A word problem requiring the student to find an unknown component can belong to the corresponding existing unknown-component MicroNode even if the exercise itself contains several operations.

---

### 3. Multi-skill exercises

Strengthen the existing multi-skill rule:

> When an exercise uses multiple skills, identify its PRIMARY learning objective.
>
> Assign it to the existing MicroNode whose LO best represents that primary objective.
>
> If several MicroNodes are relevant, use the MicroNode representing the most central / most advanced prerequisite skill actually being assessed.
>
> Do not create a new MicroNode solely because the exercise combines multiple operations.

Only use `additionalExercises[]` when no existing MicroNode provides a defensible owner.

---

### 4. Strong prohibition on exercise-only MicroNodes

Add an explicit rule:

> NEVER create a MicroNode whose only purpose is to group exercises by exercise type.
>
> NEVER create a MicroNode with empty `sourceBlockIndices` in order to give exercises a home.
>
> Examples of invalid MicroNode concepts:
>
> * "Word problems"
> * "Interpretation exercises"
> * "Practice exercises"
> * "Class exercises"
> * "Mixed exercises"
> * "Application exercises"
>
> These are activity categories, not learning objectives.
>
> If an exercise does not justify a new theory/source MicroNode, assign it to the closest existing MicroNode or put it in `additionalExercises[]`.
