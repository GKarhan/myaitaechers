# STEP 5 — FILTER CLASS EXERCISES BY ACTIVE COGNITIVE LEVEL

## GOAL

Fix one confirmed runtime bug:

> AI Teacher currently receives all approved CLASS exercises for the current MicroNode, even when only some of them are linked to the active Cognitive Path level.

For the current test node:

`2107 — Մոլեկուլների շարժումը`

DB linkage is already correct:

* `remember` level 136 → EX-579-1, EX-579-2
* `understand` level 137 → EX-579-3, EX-579-4, EX-579-5

But `chat.ts` currently loads all 5 node exercises and injects all 5 into `CLASS_EXERCISES`.

Fix ONLY this.

---

# REQUIRED BEHAVIOR

When an active Cognitive Path level exists:

`current MicroNode`
→ `active Cognitive Level`
→ exercises linked to that level
→ `CLASS_EXERCISES`

For node 2107:

### When `remember` is active

AI context must contain only:

* EX-579-1
* EX-579-2

### When `understand` is active

AI context must contain only:

* EX-579-3
* EX-579-4
* EX-579-5

Do NOT hardcode IDs, lesson ID, node ID, or cognitive level names.

---

# EXISTING DATA MODEL

The previous audit confirmed:

`lesson_node_cognitive_tasks.lesson_exercise_id`

is the FK/link to the lesson exercise.

Use the existing Cognitive Path/task linkage.

No schema changes are required.

---

# REQUIRED CHANGE

Primary file:

`artifacts/api-server/src/routes/chat.ts`

Use the existing `_activeCognitiveLevelRow`.

Do not introduce a new cognitive-state system.

Apply the smallest possible filtering logic to the existing `classExercises` path.

Preferred logic:

1. Load the current node's approved CLASS exercises as today.
2. If `_activeCognitiveLevelRow` exists:

   * obtain the exercise IDs linked to that active cognitive level from the existing cognitive-task table;
   * if linked exercise rows exist for that level, filter `classExercises` to those exercise IDs only.
3. Use the filtered result when building `CLASS_EXERCISES`.

---
