Each MicroNode may now have a teacher-confirmed Cognitive Path:

remember
→ understand
→ apply
→ analyze
→ evaluate
→ create

but only the levels pedagogically justified for that MicroNode.

Example:

Հիշել → Հասկանալ → Կիրառել

Կիրառել

WHAT cognitive depth the learner is expected to reach.

WHAT learner evidence is required to demonstrate each cognitive level.

============================================================
2. CORE PHASE 2B PRINCIPLE
============================================================

A correct answer alone is NOT enough information.

Current evidence may effectively say:

correct = true

Future cognitive evidence must be able to answer:

- Which learner?
- Which MicroNode?
- Which cognitive level was being tested?
- Which task produced the evidence?
- What kind of cognitive demand did the task require?
- What interaction format was used?
- Was the task source / AI-generated / teacher-authored?
- Was the attempt independent?
- Did the learner request help?
- What kind/degree of help was used?
- Was the answer correct?
- When was the evidence produced?

We are NOT implementing this yet.

Audit whether the existing architecture can support it.

============================================================
3. COGNITIVE EVIDENCE SEMANTICS
============================================================

Use these as conceptual examples, NOT mechanical mappings:

REMEMBER
Possible evidence:
- recognition
- recall
- identification

UNDERSTAND
Possible evidence:
- explanation
- classification
- matching concepts
- distinguishing examples/non-examples

APPLY
Possible evidence:
- application in a new situation
- independent problem solving
- using a rule/procedure with changed data

ANALYZE
Possible evidence:
- compare
- classify by relevant properties
- identify relationships
- reason about parts/structure

EVALUATE
Possible evidence:
- judgment against criteria
- justification
- selecting and defending a decision

CREATE
Possible evidence:
- generating a new example
- constructing a solution
- producing/designing something new

IMPORTANT:

Do NOT assume:

multiple_choice = remember

or:

written_answer = analyze/create.

COGNITIVE DEMAND and INTERACTION FORMAT are separate dimensions.

============================================================
4. MINIMUM-EFFORT INTERACTION PRINCIPLE
============================================================

LOCKED PRODUCT PRINCIPLE:

MINIMUM-EFFORT INTERACTION,
MAXIMUM-VALID EVIDENCE.

The learner should type as little as reasonably possible.

Possible interaction formats include:

- multiple choice
- multi-select
- true/false
- matching
- classification
- ordering
- numeric answer
- short answer
- constructed response
- independent problem solving followed by final-answer entry
- independent problem solving followed by final-answer selection

But the interaction must still produce VALID evidence for the intended
cognitive level.

Example:

An APPLY task may require the learner to independently solve a physics
problem, but the system may ask only for the final numeric answer or a
multiple-choice final result.

That can still be APPLY evidence if the task itself genuinely requires
application.

Audit whether the current task/quiz architecture can represent this
separation.

============================================================
5. HELP / HINT ARCHITECTURE — CRITICAL
============================================================

Help usage is a REQUIRED future evidence dimension.

Future learner UX should support a task-level action such as:

💡 Օգնություն

The learner can request help when they cannot proceed or are unsure.

IMPORTANT:

The first help action should NOT simply reveal the answer.

Conceptually we want progressive assistance, for example:

Level 0:
No help — independent attempt

Level 1:
Light directional hint

Level 2:
More explicit conceptual/procedural hint

Level 3:
Guided/step-by-step support

Possibly later:
worked explanation / answer reveal

DO NOT implement these levels in this audit.

Audit what the current system already records that could support this.

We need eventually to distinguish:

correct + no help

from:

correct + light hint

from:

correct + substantial guided support

These must NOT automatically become equal-strength evidence.

However:

DO NOT invent Confidence weights.

DO NOT implement formulas such as:

1 hint = -20%

Confidence Model V2 comes later.

Phase 2B must first make the FACTS observable and persistable.
