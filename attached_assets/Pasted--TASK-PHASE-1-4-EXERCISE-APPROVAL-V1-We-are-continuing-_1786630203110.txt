# PART 3 — APPROVE ALL EXERCISES

Teacher Review must provide a lesson-level action:

`Հաստատել բոլոր վարժությունները`

Scope:

ONLY exercises belonging to the current Lesson.

Behavior:

* find all non-approved exercises in current Lesson
* mark them `approved`
* already-approved exercises remain unchanged
* exercises from other Lessons MUST NOT be affected

Prefer a backend bulk operation/transaction if current architecture supports it cleanly.

Do NOT implement this as an unsafe sequence of unrelated client requests if a partial failure could leave an unpredictable state.

If a bulk endpoint is needed, keep it narrow and lesson-scoped.

Example:

Before:

`draft = 7`
`approved = 8`

Teacher clicks:

`Հաստատել բոլոր վարժությունները`

After:

`draft = 0`
`approved = 15`

Total exercises:

`15 → 15`

No exercise is created or deleted.

This is the most important part of Phase 1.4.

Audit every backend path by which AI Teacher can obtain or select a real lesson exercise.

Do NOT assume there is only one path.

* lesson exercise loading
* strong-evidence exercise selection
* exercise injection into lesson context
* fallback exercise selection
* any code that supplies textbook exercises to `chat.ts` / AI Teacher

Identify the authoritative runtime path(s).

Then enforce:

`status === "approved"`

at the SERVER/DATA-SELECTION boundary.

Do NOT rely only on frontend hiding.

Do NOT rely on the prompt telling the model not to use draft exercises.

Draft exercises must not enter the AI Teacher's eligible exercise pool.

---

# PART 6 — FAIL-CLOSED RULE

The filter must be explicit.

Correct principle:

`eligible = status === "approved"`

Avoid logic such as:

`status !== "draft"`

because unknown/null/legacy values could then become learner-visible accidentally.

If status is:

* draft
* null
* unknown
* unsupported legacy value

then it must NOT be learner-eligible unless existing documented semantics explicitly prove otherwise.

# PART 10 — ADDITIONAL EXERCISES

Eligibility normally requires BOTH:

* correct structural assignment/scope
* `status === approved`

Do not change Phase 1.3 assignment semantics.
