THE OBSERVED FAILURE PATTERN
═══════════════════════════════════════════════════

In previous real Math 5 mapping tests, the system sometimes produced too
many MicroNodes or semantically questionable MicroNodes.

Example lesson:

Մաթեմատիկա 5
Սմբատ Գոգյան
«Շենքերի համարակալումը»
physical textbook scope around pages 11–12.

After teacher review, the pedagogically meaningful structure appeared to
be approximately:

1. Շենքերի հասցեների կարևորությունը
2. Նոր շենքերի համարակալումը
3. Շենքերի համարակալման սկզբունքները

The teacher manually removed additional generated nodes that did not
represent independent pedagogically atomic learning objectives.

IMPORTANT:
Do NOT hard-code “3 MicroNodes” for this lesson.

The correct number must emerge from the instructional content.

The issue is that source coverage must NOT be achieved by creating one
MicroNode per source block, paragraph, image caption, exercise, narrative
fragment, or arbitrary semantic fragment.

At the same time, meaningful instructional content must NOT disappear
just because several source blocks belong to one MicroNode.

═══════════════════════════════════════════════════
CANONICAL MICRONODE RULE
═══════════════════════════════════════════════════

A MicroNode represents ONE pedagogically atomic learnable objective.

It is NOT:

- one source block;
- one paragraph;
- one page;
- one image;
- one caption;
- one exercise;
- one story fragment;
- one Outcome;
- one arbitrary concept noun.

Multiple source blocks MAY belong to the same MicroNode.

One source block must have canonical instructional ownership according
to the accepted ownership rules, while supporting relations may exist
where the current contract explicitly permits them.

Do NOT create additional MicroNodes merely to make source coverage reach
100%.

Coverage must be achieved by correct semantic ownership, not node
inflation.

═══════════════════════════════════════════════════
PART C — AUDIT SOURCE GROUNDING
═══════════════════════════════════════════════════

For every generated MicroNode, determine how the server proves that its
learning objective is actually supported by the assigned validated
source blocks.

We need to distinguish:

A. DIRECT INSTRUCTIONAL SUPPORT
The source actually teaches the MicroNode objective.

B. SUPPORTING CONTEXT
The source supports understanding but does not independently teach the
objective.

C. STRUCTURAL / VISUAL MATERIAL
Heading, navigation, decorative material, diagram/image support, etc.

D. EXERCISE / ACTIVITY
Must remain an exercise/activity unless it contains genuinely separate
instructional content under the accepted contract.

E. UNSUPPORTED
The MicroNode objective cannot be justified from the validated source.

Check whether current code can accidentally accept:

- title-only similarity;
- generic Armenian terms;
- action-verb similarity;
- same-page proximity;
- same-topic proximity;
- weak lexical overlap;
- Outcome similarity without textbook support;

as sufficient source grounding.

Outcome alignment MUST NOT substitute for source grounding.
