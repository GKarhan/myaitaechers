==================================================

source exercise answer
→ authoritative CORRECT / STRONG
→ Decision Engine = CONTINUE_COGNITIVE_LEVEL
→ deriveTurnProgress() writes VERIFIED
→ active task cleared
→ FEEDBACK
→ Stage 5 continuation not invoked
→ dead end

- same cognitive level still requires evidence
- no active task exists
- learner has nothing to answer
- Stage 5 contract says stop only when real learner input is required

CONTINUE_COGNITIVE_LEVEL
+

or another already-existing explicit server-owned continuation-safe state,

but derive it from the current architecture.

PART 3 — CONTINUATION INVOCATION
==================================================

After authoritative evaluation + Decision Engine + FEEDBACK:

if the resulting server state/action does not require learner input,
Stage 5 continuation must continue automatically.

Do NOT solve this by simply making every DELIVER_FEEDBACK or REMEDIATE action
non-blocking.

Instead, explicitly derive the post-feedback next server action/state.

Required sequence:

ANSWER
→ authoritative evaluation
→ Decision Engine
→ FEEDBACK
→ derive post-feedback server action
→ continue only if learner input is NOT required
→ stop at next active learner-answerable task

PART 4 — FEEDBACK CORRECTNESS AUTHORITY
==================================================

Bounded FEEDBACK receives authoritative evaluation but currently has no
semantic polarity enforcement.

The learner-facing correctness acknowledgement must be consistent with the
authoritative result.

Required invariant:

authoritative CORRECT
→ feedback must not claim the learner is incorrect

authoritative INCORRECT
→ feedback must not claim the learner is correct

Do NOT make FEEDBACK AI authoritative for correctness.

==================================================
PART 5 — SERVER-OWNED CORRECTNESS ACKNOWLEDGEMENT
==================================================

Prefer the smallest robust architecture:

server owns the correctness acknowledgement

and AI supplies only explanation/remediation wording.

For example, conceptually:

CORRECT
→ server-controlled positive acknowledgement
→ bounded FEEDBACK explanation

INCORRECT
→ server-controlled corrective acknowledgement
→ bounded FEEDBACK explanation/remediation

Do not hard-code awkward full feedback paragraphs if a smaller compatibility
mechanism is possible.

The key requirement is that the model cannot reverse correctness polarity.

If current response composition makes server-owned acknowledgement unsafe,
use a strict bounded FEEDBACK semantic validator instead.

Choose the smallest repository-compatible solution and explain why.
