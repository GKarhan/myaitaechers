## ONE CLEAR LEARNING OBJECTIVE

Յուրաքանչյուր MicroNode պետք է ներկայացնի **մեկ հստակ սովորելի նպատակ**։

MicroNode-ը չպետք է լինի պարզապես թեմայի մի հատված կամ source blocks-ի պատահական խումբ։

Այն պետք է ունենա մեկ հստակ learning objective, որը learner-ը կարող է սովորել, հասկանալ, կիրառել կամ ստուգել որպես մեկ coherent learning unit։

# 2. GRANULARITY-Ի ԵՐԵՔ ՀԻՄՆԱԿԱՆ ՎԻՃԱԿ

Յուրաքանչյուր իրական MicroNode գնահատիր հետևյալ երեք կատեգորիաներից մեկով.

### A. CORRECT GRANULARITY

MicroNode-ը ճիշտ չափի է։

Այն ունի.

* մեկ հստակ learning objective
* մեկ coherent concept/skill
* source blocks-ը բնականորեն վերաբերում են նույն objective-ին
* exercises-ը ստուգում են նույն հիմնական objective-ը
* բաժանելու անհրաժեշտություն չկա
* միավորելու անհրաժեշտություն չկա

Սա PASS է։

---

### B. MEGA-NODE / UNDER-SPLIT

MicroNode-ը չափազանց մեծ է։

Մեկ MicroNode-ի մեջ միավորված են երկու կամ ավելի իրական learning objectives։

Հատկապես ուշադրություն դարձրու այն դեպքերին, երբ տարբեր մասերը պահանջում են տարբեր **cognitive operations**։

Օրինակ՝

* ճանաչել + դասակարգել
* սահմանել + կիրառել կանոնը
* տարբերակել + փոխակերպել
* կանոնը հասկանալ + բացառությունները կիրառել
* concept A հասկանալ + անկախ concept B սովորել

Եթե learner-ը պետք է երկու տարբեր բան սովորի, որպեսզի MicroNode-ը ամբողջությամբ յուրացրած համարվի, մեծ հավանականությամբ պետք է լինի երկու MicroNode։

Նշիր.

* ինչ objectives են միավորված
* ինչ source blocks են միավորված
* ինչու դրանք մեկ objective չեն
* որտեղ պետք է բաժանվի
* առաջարկվող MicroNode-ների քանակը

### C. OVER-SPLIT

Mapper-ը նույն learning objective-ը բաժանել է մի քանի MicroNode-ի, չնայած դրանք իրականում մեկ coherent learning unit են։

Օրինակ՝ նույն կանոնի.

* definition
* rule
* immediate example

առանձին MicroNode դարձնելը, եթե դրանք միասին ներկայացնում են մեկ սովորելի objective։

Կամ նույն skill-ի շատ փոքր քայլերը բաժանել այնպես, որ learner-ը ստիպված լինի դրանք առանձին node-ներով անցնել, չնայած cognitive objective-ը մեկն է։

Նշիր.

* որ MicroNode-ներն են արհեստականորեն բաժանված
* ինչն է ցույց տալիս, որ դրանք նույն objective-ն ունեն
* ինչու պետք է merge անել
* առաջարկվող merged MicroNode-ը

# 3. COGNITIVE OPERATION TEST

Յուրաքանչյուր MicroNode-ի համար կատարիր այս test-ը։

Հարց.

> Learner-ը այս MicroNode-ը յուրացնելու համար կատարո՞ւմ է մեկ հիմնական cognitive operation, թե՞ մի քանի տարբեր։

Օրինակներ՝

### Մեկ operation

* identify
* define
* distinguish
* classify
* apply one rule
* calculate using one method
* transform using one rule
* explain one concept

→ սովորաբար մեկ MicroNode։

### Տարբեր operations

Օրինակ՝

> «Սովորել գոյականի սահմանումը և հետո սովորել դրա հոլովումը»

Սրանք կարող են պահանջել տարբեր cognitive operations։

Կամ՝

> «Տարբերել գոյականը և ածականը + կիրառել հոլովման կանոնը»

Եթե երկրորդ մասը անկախ skill է, պետք է ստուգել՝ արդյոք երկու MicroNode է անհրաժեշտ։

Մի բաժանիր մեխանիկորեն միայն այն պատճառով, որ source-ում երկու paragraph կա։

**Source structure ≠ learning structure։**

# 5. OBJECTIVE COUNT TEST

Համեմատիր նաև source evidence-ը։

### Source coherence

Բոլոր `sourceBlockIndices`-ը վերաբերում են նույն concept/skill-ին՞։

Եթե ոչ՝ ինչու։

### Source completeness

Եթե MicroNode-ը ներկայացնում է objective X, source-ում X-ի համար անհրաժեշտ material-ը ամբողջությամբ ներառվա՞ծ է։

### Source fragmentation

Նույն objective-ի source blocks-ը անիմաստ կերպով բաժանվա՞ծ են տարբեր MicroNode-ների։

# 8. PASS 2 PROMPT AUDIT

Ուսումնասիրիր Mapper-ի այն prompt-ը/logic-ը, որը ստեղծում է MicroNodes։

Փնտրիր.

* ինչպես է սահմանվում MicroNode-ը
* կա՞ explicit "one clear learning objective" rule
* կա՞ over-splitting protection
* կա՞ mega-node protection
* կա՞ cognitive-operation criterion
* AI-ին տրվո՞ւմ է split/merge decision rule

* AI-ն ստիպվա՞ծ է reasoning անել objective count-ի շուրջ
* server-side validator կա՞
* granularity validation deterministic է՞, թե՞ միայն prompt-level

Հատկապես տարբերակիր.

### Prompt guarantee

AI-ին ասվում է, որ պետք է ճիշտ granularity պահի։

և

### System guarantee

Server-ը փաստացի ստուգում է, որ output-ը համապատասխանում է այդ պահանջին։

# 10. DO NOT CONFUSE THESE CONCEPTS

Հատուկ զգույշ եղիր.

### Topic ≠ MicroNode

Մեկ topic-ը կարող է ունենալ բազմաթիվ MicroNode-ներ։

### Source block ≠ MicroNode

Մեկ MicroNode-ը կարող է ունենալ բազմաթիվ source blocks։

### Paragraph ≠ MicroNode

Paragraph-ի սահմանները չեն որոշում learning unit-ի սահմանները։

### Exercise ≠ MicroNode

Յուրաքանչյուր exercise-ը առանձին node չէ։

### Definition + Rule + Example ≠ automatically 3 MicroNodes

Եթե դրանք միասին սովորեցնում են մեկ objective, դրանք կարող են լինել մեկ MicroNode։

### Different cognitive operation ≠ automatically separate node

Պետք է ստուգել՝ դա նույն skill-ի բնական ենթաքայլ է, թե անկախ learning objective։

# 13. SEVERITY

Գնահատիր.

### CRITICAL

Granularity failure-ը կարող է հանգեցնել նրան, որ AI Teacher-ը մեկ node-ում սովորեցնի մի քանի անկախ objectives և learner-ի mastery-ը սխալ գնահատվի։

### HIGH

Mega-node կամ over-splitting-ը պարբերաբար հանդիպում է իրական mappings-ում։

### MEDIUM

Prompt-ում կան granularity կանոններ, բայց դրանք server-side չեն enforced։

### LOW

Minor edge cases կամ cosmetic granularity issues։
