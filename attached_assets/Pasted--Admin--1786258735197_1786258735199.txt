Ադմին էջում ուսուցչի ջնջումը չի աշխատում։ Կարգավորիր սա ամբողջությամբ։

### Նպատակ

Admin-ը պետք է կարողանա Admin էջից ուսուցչին ջնջել **մեկ գործողությամբ**, առանց ձեռքով կապված տվյալները նախապես ջնջելու։

### Պահանջներ

1. Գտիր Admin էջի teacher/user list-ում գործող **Delete Teacher / Ջնջել ուսուցչին** գործողության frontend և backend ամբողջ flow-ը։

2. Պարզիր՝ ինչու հիմա ջնջումը չի կատարվում.

   * frontend event/button
   * API request
   * backend route/controller
   * authentication/authorization
   * database constraints
   * կապված տվյալների foreign-key/dependency խնդիրներ
   * error handling

3. Իրականացրու **կասկադային/անվտանգ deletion flow**.

   Երբ Admin-ը ջնջում է ուսուցչին, համակարգը պետք է ճիշտ կերպով հեռացնի կամ orphan չթողնի այդ ուսուցչին պատկանող բոլոր անհրաժեշտ տվյալները՝ հաշվի առնելով տվյալների բազայի իրական schema-ն։

   Նախ ուսումնասիրիր՝ ինչ tables/entities են կապված teacher-ի հետ։ Չջնջես պատահական տվյալներ, որոնք պատկանում են այլ օգտատերերի։

4. Եթե ուսուցչին պատկանող դասերը, lesson mapping-ները, knowledge nodes-ը, sessions-ը, exercises-ը, messages-ը կամ այլ տվյալներ պետք է ջնջվեն, որոշիր դա schema-ի և գործող application logic-ի հիման վրա և իրականացրու անվտանգ կարգով։

5. Եթե որևէ տվյալ պետք է պահպանվի audit/history-ի համար, մի ջնջիր այն պարզապես cascade-ի պատճառով։ Օգտագործիր նախագծի արդեն գոյություն ունեցող տվյալների պահպանման տրամաբանությունը։

6. Frontend-ում ջնջելուց առաջ ավելացրու confirmation dialog, օրինակ՝
   **«Վստա՞հ եք, որ ցանկանում եք ջնջել այս ուսուցչին։ Կապված տվյալները նույնպես կարող են հեռացվել»**

   Confirmation-ը պետք է լինի իրական գործողության արգելակ, ոչ թե պարզապես UI։

7. Ջնջման ժամանակ ցույց տուր loading state, որպեսզի Admin-ը չկարողանա մի քանի անգամ սեղմել Delete։

8. Հաջող ջնջումից հետո teacher-ը պետք է անմիջապես անհետանա Admin list-ից՝ առանց էջը ձեռքով refresh անելու։

9. Սխալի դեպքում Admin-ին ցույց տուր հասկանալի error message, իսկ developer console/server logs-ում պահիր իրական տեխնիկական պատճառը։

10. Ստուգիր նաև authorization-ը.

    * սովորական user/teacher-ը չպետք է կարողանա օգտագործել Admin delete endpoint-ը
    * միայն համապատասխան Admin permission ունեցող user-ը կարողանա ջնջել teacher

### Կարևոր

Մի սահմանափակվիր frontend-ի կոճակը սարքելով։ Գտիր իրական root cause-ը և ուղղիր ամբողջ CRUD flow-ը՝ UI → API → backend → database։

### Աշխատանքի կարգը

Նախ ուսումնասիրիր project-ի իրական schema-ն և teacher-ի հետ կապված բոլոր տվյալները։

Հետո՝

1. բացահայտիր root cause-ը,
2. փոխիր անհրաժեշտ ֆայլերը,
3. պահպանիր գոյություն ունեցող architecture/style-ը,
4. մի կոտրիր teacher-ի ստեղծումը, edit-ը կամ list-ը,
5. ստուգիր deletion flow-ը,
6. ստուգիր authorization-ը,
7. վերջում ինձ գրիր՝

   * որ ֆայլերն ես փոխել,
   * ինչն էր խնդիրը,
   * ինչ լուծում ես արել,
   * ինչ կապված տվյալներ են ջնջվում,
   * ինչպես ես ստուգել, որ աշխատում է։

**Մի փոխիր այլ ֆունկցիոնալություն, եթե դրա կարիքը չկա։**
