════════════════════════════════════════════════════
13. STRICT OVER-SPLITTING / UNDER-SPLITTING GATE
════════════════════════════════════════════════════

Source coverage MUST NOT be achieved by creating unnecessary MicroNodes.

The mapper must aim for:

THE SMALLEST PEDAGOGICALLY COMPLETE SET OF ATOMIC MICRONODES

that fully represents the lesson's instructional knowledge.

Important:

“smallest” does NOT mean arbitrarily few nodes.

It means:

no two MicroNodes should remain separate if they represent the same
underlying teachable/assessable objective.

Before persistence, run a granularity sanity pass.

For every proposed pair/group of MicroNodes ask:

1. Do they teach the same core concept/rule/skill?

2. Do they differ only because the source appears in different:
   - paragraphs
   - examples
   - tables
   - story fragments
   - source blocks
   - representations?

3. Would they normally be taught together?

4. Would they normally be assessed together?

5. Would mastering one substantially demonstrate the other?

6. Are their learningObjectives near-duplicates?

7. Is one merely a narrow fragment/example/context of the other?

If YES:

merge them unless there is a clear pedagogical reason to keep them
separate.

Conversely:

split a MicroNode when it contains multiple independently teachable and
independently assessable objectives.

Examples, stories, representations, headings, and contextual fragments
normally SUPPORT a MicroNode.

They must NOT automatically become MicroNodes.

Do NOT create a MicroNode merely to give a source block an owner.

Coverage is measured through SOURCE OWNERSHIP,
not by maximizing MicroNode count.
