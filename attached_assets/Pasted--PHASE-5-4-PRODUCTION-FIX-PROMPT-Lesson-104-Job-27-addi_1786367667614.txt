# PHASE 5.4 — PRODUCTION FIX PROMPT

## Lesson 104 / Job 27 — `additionalExercises.blockIndex = null` և missing EXERCISE blocks

Դու աշխատում ես արդեն audited production codebase-ի վրա։ **Մի վերադարձրու ընդհանուր վերլուծություն և մի վերագրիր Phase 5 report-ը։** Պետք է ուղղես կոնկրետ production failure-ը, որը հաստատվել է Lesson 104 / Job 27 re-map-ով։

### 1. Հաստատված production failure

Lesson 104 / Job 27-ում Pass 1-ը տվել է 18 block.

* `0` OBJECTIVE
* `1–3` RULE
* `4–6` EXAMPLE
* `7` TABLE
* `8` RULE
* `9–16` EXERCISE
* `17` ACTIVITY

P5.6-ից հետո EXERCISE-ները այլևս սխալ կերպով `sourceBlockIndices` չեն գնացել։ Սա **ճիշտ է և չպետք է հետ վերադարձնել**։

Սակայն AI Pass 2-ը blocks `9–16`-ի համար ստեղծել է `additionalExercises`, բայց տվել է.

```text
blockIndex: null
```

արդյունքում՝

```text
categoryCounts.additionalExercises = 8
missingIndices = [9,10,11,12,13,14,15,16]
```

իսկ insertion-ում՝

```ts
const block = pass1Blocks[exercise.blockIndex];
if (!block) continue;
```

քանի որ `blockIndex === null`, `block === undefined`, և այդ 8 իրական textbook exercise-ները **ընդհանրապես չեն մտել `lesson_exercises`**։

Այսինքն՝ P5.1/P5.6-ը աշխատել են, բայց առաջացել է նոր HIGH-severity failure։

# 2. Գլխավոր նպատակ

Ստեղծել **hard activity preservation invariant**.

> Եթե Pass 1-ում կա `EXERCISE`, `ACTIVITY` կամ `HOMEWORK` block, ապա Pass 2-ից հետո այդ block-ը երբեք չպետք է անհետանա։

Այն պետք է հայտնվի առնվազն մեկ անվտանգ destination-ում.

1. MicroNode `exercises[]`
2. `additionalExercises[]`՝ **ճիշտ `blockIndex`-ով**
3. automated rescue-ի միջոցով `additionalExercises[]`
4. եթե AI output-ը սխալ է կամ block-ը լրիվ բացակայում է՝ deterministic post-processing rescue

Բայց **երբեք չպետք է silently drop լինի**։

# 3. FIX #1 — `additionalExercises.blockIndex` պարտադիր դարձնել

Գտիր `PASS2_STEP2_SYSTEM` prompt-ը և `additionalExercises` schema/contract-ը։

Փոխիր այնպես, որ `additionalExercises[].blockIndex`-ը լինի **պարտադիր integer**։

Ավելացրու հստակ կանոն.

```text
ABSOLUTE ACTIVITY PRESERVATION RULE:

Every EXERCISE, ACTIVITY, or HOMEWORK block from Pass 1 MUST be represented
in exactly one of:

1. microNode.exercises[]
2. additionalExercises[]
3. a deterministic rescue destination created by the server.

Every such object MUST contain the exact original Pass 1 blockIndex.

NEVER output null, missing, undefined, guessed, or synthetic blockIndex.

The blockIndex MUST be copied exactly from the input block.
Do not renumber blocks.
Do not use exercise sequence numbers as blockIndex.
Do not use null.
Do not omit blockIndex.
```

Հատկապես ընդգծիր.

```text
Example:
Pass1 block index 12 → additionalExercises item MUST have blockIndex: 12.

"Exercise 117" does NOT mean blockIndex 117.
The only valid blockIndex is the Pass1 array index.
```

# 4. FIX #2 — Server-side validation of null/invalid blockIndex

Մի վստահիր միայն LLM prompt-ին։

`runPass2Pipeline()`-ում կամ Pass 2 result normalization layer-ում ավելացրու deterministic validation։

Եթե ունենք.

```ts
additionalExercises: [
  {
    blockIndex: null,
    ...
  }
]
```

ապա դա պետք է համարվի invalid AI output։

Ստեղծիր/օգտագործիր helper, օրինակ՝

```ts
isValidBlockIndex(blockIndex, pass1Blocks)
```

պայմանները.

* integer է
* `>= 0`
* `< pass1Blocks.length`
* համապատասխան block-ը գոյություն ունի
* եթե destination-ը activity destination է, block-ի type-ը պետք է լինի `EXERCISE | ACTIVITY | HOMEWORK`

Invalid `blockIndex`-ը **երբեք չպետք է անցնի DB insertion**։

# 5. FIX #3 — Deterministic missing-activity rescue

Սա ամենակարևոր fix-ն է։

P5.4 rescue-ը հիմա աշխատում է միայն.

```text
unmappedBlockIndices
```

վրա։

Դա բավարար չէ։

Ավելացրու երկրորդ՝ վերջնական activity-preservation scan։

### Scan-ը պետք է աշխատի Pass 2-ի ամբողջ result-ի վրա

Ստեղծիր.

```ts
collectReferencedBlockIndices(pass2Result)
```

որը հավաքում է բոլոր block indices-ը՝ անկախ destination-ից.

* `sourceBlockIndices`
* `microNode.exercises[].blockIndex`
* `microNode.additionalExercises[].blockIndex`
* topic-level `additionalExercises[].blockIndex`
* `unmappedBlockIndices`

Հետո հաշվիր.

```text
allPass1ActivityBlocks
    MINUS
allReferencedBlockIndices
```

որտեղ `allPass1ActivityBlocks`-ը բոլոր այն Pass 1 blocks-ն են, որոնց type-ը.

```text
EXERCISE
ACTIVITY
HOMEWORK
```

### Եթե որևէ activity block չի գտնվել

Այդ block-ը **automatically rescue արա** դեպի:

```ts
additionalExercises
```

ճիշտ index-ով.

Օրինակ՝ եթե.

```text
Pass1:
block 12 = EXERCISE
```

և Pass2-ում block 12-ը ոչ մի valid destination-ում չկա, server-ը պետք է ստեղծի.

```ts
additionalExercises.push({
  blockIndex: 12,
  ...
});
```

և դրա `sourceText`-ը վերցնի **ուղիղ Pass1 block-ից**։

Այս rescue-ը պետք է լինի deterministic և չպետք է կախված լինի AI-ի նոր որոշումից։

# 7. FIX #5 — Չթողնել duplicate activity placement

Rescue-ից առաջ ստուգիր, որ block-ը արդեն valid destination-ում չկա։

Օրինակ՝ եթե block 17 արդեն կա.

```text

```

ապա այն չպետք է երկրորդ անգամ ավելացվի `additionalExercises`։

Invariant:

```text
Every EXERCISE / ACTIVITY / HOMEWORK block
must have exactly ONE valid activity destination.
```

Կարևոր տարբերակում.

`sourceBlockIndices`-ում հայտնվելը **activity destination չէ**։

Եթե EXERCISE-ը հայտնվում է միայն `sourceBlockIndices`-ում, դա պետք է մնա P5.1-ի `ACTIVITY_IN_THEORY` finding։

# 8. FIX #6 — Coverage validator-ը պետք է հաշվի ճիշտ placement-ը

Սա ճիշտ behavior է։

Պահիր այդ սկզբունքը։

**Never record `null` as a block index.**

Coverage validator-ում.

```ts

   // do NOT record null
```

Եթե rescue-ը հաջող է, դա կարող է լինել warning/review item, բայց coverage-ը պետք է վերջնական state-ով ճիշտ հաշվվի։

# 11. FIX #9 — Final invariant before DB persistence

DB insert-ից անմիջապես առաջ պետք է լինի final activity audit։

Pseudo-logic.

```ts
const activityBlocks = pass1Blocks.filter(
  b =>
    b.blockType === "EXERCISE" ||
    b.blockType === "ACTIVITY" ||
    b.blockType === "HOMEWORK"
);

const placementMap = collectActivityPlacements(pass2Result);

for (const block of activityBlocks) {
  const placements = placementMap.get(block.index) ?? [];

  if (placements.length === 0) {
    rescueAsAdditionalExercise(block);
  }

  if (placements.length > 1) {
    addDuplicateActivityFinding(block, placements);
  }
}
```

Հետո նոր.

```text
validateSourceCoverage()
→ activity validation
→ DB insertion
```

Այս հերթականությունը պահիր տրամաբանական և deterministic։
