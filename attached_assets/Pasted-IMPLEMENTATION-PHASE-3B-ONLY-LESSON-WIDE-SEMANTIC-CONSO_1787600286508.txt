2. FUNDAMENTAL IDENTITY QUESTION
════════════════════════════════════════════════════════════

For every pair/group of promoted or promotion-eligible candidates, the system
must conceptually answer:

"DO THESE REPRESENT THE SAME UNDERLYING LEARNER KNOWLEDGE STATE?"

This is the canonical semantic identity question.

NOT:

"Do the titles look similar?"

NOT:

"Are they in the same Topic?"

NOT:

"Do they use the same verb?"

NOT:

"Are they both about multiplication?"

NOT:

"Did Jaccard similarity exceed 0.4?"

The question is:

Would the learner need SEPARATE mastery states for these two things?

If NO:
they belong to the same canonical knowledge unit.

If YES:
they remain distinct MicroNodes.

════════════════════════════════════════════════════════════
3. MICRONODE IDENTITY CONTRACT
════════════════════════════════════════════════════════════

A canonical MicroNode represents ONE independently trackable knowledge state.

Two candidate appearances should normally consolidate when:

- they teach the same underlying concept/skill,
- their differences are explanation/example/representation differences,
- their differences are only cognitive-depth differences,
- one restates the other,
- one elaborates the other without adding a separate assessable target,
- one is a recap of the same knowledge,
- they appear in different provisional Topics but mastery is still one state.

They should remain distinct when:

- each has an independently assessable learning target,
- a learner can genuinely master one without mastering the other,
- they require meaningfully separate evidence,
- they represent prerequisite vs dependent knowledge,
- they use similar vocabulary but different conceptual relationships,
- one introduces an additional rule/condition/procedure that deserves its own
  learner state.

════════════════════════════════════════════════════════════
4. BLOOM / COGNITIVE DEPTH MUST NOT DEFINE IDENTITY
════════════════════════════════════════════════════════════

Mandatory invariant:

Remember / Understand / Apply / Analyze / Evaluate / Create

DO NOT define separate MicroNode identity.

Example:

Candidate A:
"State the rule for determining the sign of a product."

Candidate B:
"Explain why the number of negative factors determines the sign."

Candidate C:
"Apply the sign rule to determine the sign of a product."

These may all refer to ONE underlying knowledge unit:

"Determining the sign of a product"

The later Cognitive Path will model depth.

Do NOT preserve multiple MicroNodes merely because learningObjective verbs differ.

However:

if the candidates actually represent different underlying knowledge, they remain
separate even if Bloom levels are similar.

7. SEMANTIC REVIEW — BOUNDED, NOT PER PAIR
════════════════════════════════════════════════════════════

Do NOT add an AI call for every pair.

Reuse the existing bounded semantic review architecture if possible.

Preferred architecture:

1. deterministic candidate retrieval finds plausible overlap groups
2. obvious non-overlaps are skipped
3. obvious safe cases may be resolved deterministically only where evidence is
   genuinely sufficient

Target cost:

NOT O(n²) provider calls.

grouping strategy.

════════════════════════════════════════════════════════════
9. GROUP CONSOLIDATION — NOT JUST PAIRWISE DELETION
════════════════════════════════════════════════════════════

Avoid a fragile implementation such as:

A matches B → delete B
B matches C → delete C

without canonical group reasoning.

Consolidation should support semantic groups.

Example:

A = same as B
B = same as C

Then the system should be able to form:

Canonical Group {A, B, C}

provided there is no contradictory evidence.

Be careful with transitivity.

If:

A same B
B same C
A distinct C

that is a semantic conflict.

Do NOT silently merge all three.

Mark the conflicting group REVIEW_REQUIRED.

Implement deterministic conflict detection.
