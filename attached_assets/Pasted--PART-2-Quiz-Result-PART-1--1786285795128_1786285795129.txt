## PART 2 — Quiz Result-ի ամբողջական հայաֆիկացում + յուրաքանչյուր հարցի բացատրություն

PART 1-ը և Evidence Mapping Audit-ը արդեն ավարտված են։
**Մի փոխիր դրանց logic-ը և մի սկսիր նոր audit։**

Այս աշխատանքի scope-ը սահմանափակիր միայն **Quiz Result-ի աշակերտի էջով**։

### 1. Հիմնական ֆայլը

Աշխատիր առաջին հերթին այս ֆայլում՝

```text
myaiteacher/src/pages/quiz-result.tsx
```

Սա այն էջն է, որը աշակերտը տեսնում է թեստը ավարտելուց հետո։

Backend-ում փոփոխություն արա միայն այն դեպքում, եթե անհրաժեշտ է տվյալ հարցի բացատրությունը frontend հասցնելու համար։

---

# 2. Հայաֆիկացնել բոլոր տեխնիկական placeholder-ները

Quiz Result էջում օգտվողը չպետք է տեսնի տեխնիկական անգլերեն placeholder կամ enum։

Փոխիր դրանք բնական հայերենով։

Օրինակ՝

```text
STUDENT_RECOMMENDATIONS → Աշակերտի առաջարկություններ
TOPIC_BREAKDOWN → Թեմաների ամփոփում
LEARN_FULL → Ամբողջական ուսուցում
LEARN_TARGETED → Թիրախային ուսուցում
deeper → ավելի խորությամբ
REVIEW → Կրկնել
STUDY_FIRST → Նախ սովորել
TEACHER_RECOMMENDATIONS → Ուսուցչի առաջարկություններ
COMMON_ERROR → Տարածված սխալ
INDIVIDUAL_ERROR → Անհատական սխալ
CLASS_ANALYSIS → Դասարանի վերլուծություն
COMMON_ERRORS → Ընդհանուր սխալներ
RE_TEACH → Նորից ուսուցանել
MASTERY → Յուրացման մակարդակ
IN_PROGRESS → Ընթացքի մեջ է
NO_DATA → Տվյալ չկա
QUESTION → Հարց
QUESTIONS → Հարցեր
ANSWER → Պատասխան
ANSWERS → Պատասխաններ
STUDENT → Աշակերտ
STUDENTS → Աշակերտներ
```

Եթե էջում կան այլ անգլերեն տեխնիկական բառեր կամ placeholder-ներ, որոնք աշակերտը կարող է տեսնել, նույնպես փոխիր բնական հայերենով։

**Մի թող `UPPER_CASE` placeholder-ներ UI-ում։**

---

# 3. Յուրաքանչյուր հարցի համար ավելացնել բացատրություն

Ամեն հարցի result card-ում պետք է լինի ոչ միայն՝

* հարցը
* աշակերտի ընտրած պատասխանը
* ճիշտ պատասխանը
* ճիշտ/սխալ վիճակը

այլ նաև **մանկական, հասկանալի բացատրություն**։

### Եթե պատասխանը ՃԻՇՏ է

Ցուցադրել.

**Ինչու է ճիշտ**

և կարճ բացատրել՝ ինչու է ընտրված պատասխանը ճիշտ։

Օրինակ.

```text
✅ Ճիշտ պատասխան

Ինչու է ճիշտ․
Մեկ դաս կազմված է երեք հաջորդական կարգերից։
```

### Եթե պատասխանը ՍԽԱԼ է

Պետք է ցուցադրել երեք առանձին մաս.

```text
❌ Քո պատասխանը սխալ է

Քո պատասխանը․ 2

Ինչու է սխալ․
Մեկ դասը չի կազմվում երկու կարգից։

✅ Ճիշտ պատասխանը․ 3

Ինչու է ճիշտ․
Մեկ դասում կա երեք հաջորդական կարգ։
```

Այսինքն՝ աշակերտը պետք է հասկանա ոչ միայն **ինչն է սխալ**, այլ նաև **ինչու է ճիշտ պատասխանը ճիշտ**։

---

# 4. Շատ կարևոր — Չհորինել բացատրություն

Եթե database-ում տվյալ հարցի համար վստահելի explanation չկա՝

**AI-ով կամ frontend-ում ինքնուրույն բացատրություն մի հորինիր։**

Օգտագործիր արդեն գոյություն ունեցող տվյալները ըստ այս priority-ի.

1. Question-level explanation, եթե արդեն կա
2. `childFriendlyExplanation`
3. `commonMisconception`
4. Եթե վստահելի explanation չկա → explanation section-ը չցուցադրել

Չստեղծել կեղծ կամ ենթադրյալ բացատրություն։

---

# 5. Տվյալների կառուցվածքը չփչացնել

Եթե արդեն կա՝

```ts
feedback: {
  whyCorrect,
  whyWrong
}
```

պահպանիր այդ կառուցվածքը։

Frontend-ում օգտագործիր այն այս տրամաբանությամբ.

### Correct

```text
isCorrect === true
→ ցույց տալ whyCorrect
→ չցուցադրել whyWrong
```

### Wrong

```text
isCorrect === false
→ ցույց տալ whyWrong, եթե կա
→ ցույց տալ whyCorrect, եթե կա
```

Եթե երկուսն էլ `null` են՝

```text
→ ոչ մի դատարկ explanation container չցուցադրել
```

# 6. Question → Node կապը չփոխել

Յուրաքանչյուր հարցի վրա արդեն ցուցադրվում է համապատասխան Node/թեման։

Պահպանիր այդ կապը։

Օրինակ՝

```text
📌 Միլիոնների դասի ներածություն
```

Սա չփոխել և չվերագրել այլ Node-ի։

**Այս task-ի ընթացքում Node/MicroNode architecture չփոխել։**

# 7. Արդյունքի էջի վերջնական կառուցվածքը

Յուրաքանչյուր հարցի card-ը պետք է մոտավորապես ունենա այս կառուցվածքը.

```text
❌ / ✅

Հարց

📌 Թեմա

Քո պատասխանը
...

Ճիշտ պատասխանը
...

❌ Ինչու է սխալ
...

✅ Ինչու է ճիշտ
...
```

Correct answer-ի դեպքում՝

```text
✅

Հարց

📌 Թեմա

Քո պատասխանը
...

✅ Ինչու է ճիշտ
...
```

Բացատրությունները պետք է լինեն կարճ, պարզ և աշակերտին հասկանալի։

# 9. Verification

Փոփոխությունից հետո ստուգիր առնվազն այս դեպքերը.

### Case A — Correct + explanation exists

Պետք է երևա `Ինչու է ճիշտ`։

### Case B — Wrong + both explanations exist

Պետք է երևան և՛ `Ինչու է սխալ`, և՛ `Ինչու է ճիշտ`։

### Case C — Wrong + explanation missing

Չպետք է լինի դատարկ explanation box։

### Case D — Correct + whyWrong exists

`whyWrong` չպետք է ցուցադրվի։

### Case E — 10 հարց

Բոլոր հարցերը պետք է ունենան իրենց սեփական feedback-ը և չպետք է մեկ հարցի explanation-ը հայտնվի մյուս հարցի տակ։

### Case F — Armenian UI

Էջի տեսանելի UI-ում չպետք է մնան տեխնիկական placeholder-ներ՝

```text
STUDENT_RECOMMENDATIONS
LEARN_FULL
LEARN_TARGETED
TOPIC_BREAKDOWN
WHY_CORRECT
WHY_WRONG
COMMON_ERROR
```

կամ նմանատիպ այլ տեխնիկական անուններ։

---

# 10. Scope rule

Սա **միայն Quiz Result-ի UI + արդեն հասանելի question feedback-ի ճիշտ ցուցադրում է**։

Մի՛ սկսիր.

* նոր MicroNode architecture
* նոր scoring system
* նոր Knowledge State logic
* Personalization Engine
* quiz generation redesign
* database-ի լայն փոփոխություններ

Եթե explanation-ի համար schema migration է անհրաժեշտ, **մի արա migration առանց ինձ հարցնելու**։ Պարզապես report արա՝ ինչ schema gap կա։

Վերջում գրիր.

1. Որ ֆայլերն ես փոխել
2. Յուրաքանչյուր ֆայլում ինչ ես փոխել
3. Ինչպես է այժմ ճիշտ պատասխանի feedback-ը աշխատում
4. Ինչպես է սխալ պատասխանի feedback-ը աշխատում
5. Որ տեխնիկական բառերն ես հայաֆիկացրել
6. Verification-ի արդյունքները
7. Եթե որևէ explanation տվյալ չկա՝ կոնկրետ որ աղբյուրից է բացակայում

**Մի փոխիր ոչ մի բան այս scope-ից դուրս։**
