PART 2 — COGNITIVE TARGET / BLOOM SAFETY FIX
==================================================

The current real mapping exposed an important semantic problem.

A MicroNode whose Learning Objective requires application/problem solving
must NOT be reduced to a Remember-only Cognitive Path.

Example:

Learning Objective:
"Ուսանողները կհաշվեն օբյեկտի արագությունը՝ օգտագործելով տրված
ճանապարհի երկարությունը և ժամանակը։"

A generated path that only requires remembering the speed formula is NOT
sufficient.

Another example:

Learning Objective:
"Ուսանողները կկիրառեն արագության հասկացությունը՝ լուծելու շարժման
հետ կապված պարզ խնդիրներ։"

A path whose success criterion merely asks the learner to list measurement
units is NOT sufficient.

GENERAL RULE:

The generated Cognitive Path MUST NOT lower the demonstrated cognitive
requirement expressed by the canonical MicroNode Learning Objective.

The Learning Objective remains authoritative.

The generated:
- cognitive level
- performance objective
- success criterion
- preferred interaction types

must collectively measure the actual Learning Objective.

Examples:

define/name/identify
→ Remember may be appropriate.

explain/compare/classify with reasoning
→ Understand or appropriate demonstrated level.

calculate/use/apply/solve
→ Apply must not be reduced to Remember.

Do NOT blindly infer from verbs alone.
Use the full Learning Objective + grounded source context.

Keep existing canonical target-ceiling/safety semantics.
Do not weaken C1–C7 safety.

If generated Cognitive Path output violates the Learning Objective floor,
reject/repair it through the existing bounded repair mechanism rather than
persisting a weaker path.
