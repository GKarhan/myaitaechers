0. WHY THIS TASK EXISTS
============================================================

The V2-R1 report explicitly says:

the student still needs to send one message
to trigger the next teaching turn.

That violates the LOCKED product rule:

THE LEARNER MUST NOT NEED TO SEND
"շարունակենք", "օկ", "հաջորդը", etc.
when no real learner input is required.

Canonical rule:

NO WAITING FOR PROGRESSION COMMANDS.
WAIT ONLY WHEN REAL LEARNER INPUT IS REQUIRED.

Therefore V2-R1 is not fully closed until:

FEEDBACK
→ backend decision
→ next non-input-required action

can continue automatically.

============================================================
1. LOCKED TURN MODEL
============================================================

The canonical teaching flow is:

TEACH
→ ONE active MICRO_CHECK
→ WAIT_FOR_ANSWER
→ learner answers
→ FEEDBACK ONLY
→ BACKEND DECISION
→ NEXT ACTION automatically

The learner must only be required to act when the next state genuinely needs:

- an answer
- a choice
- a task submission
- Help interaction
- another real learner input

If the next action is:

TEACH_MORE
REMEDIATE
SHOW_EXAMPLE
EXPLAIN
TRANSITION_TO_NEXT_TEACHING_CHUNK

the system should continue automatically.

If the next action creates a NEW assessable task:

the system may automatically render that next task after the feedback/decision sequence,
but it must remain a separate pedagogical step and a separate active task.

Do NOT merge feedback + new question into one assistant message.

============================================================
2. IMPORTANT UX SEMANTIC
============================================================

We do NOT want:

Learner answer
→ AI FEEDBACK
→ silence
→ learner types "օկ"
→ AI continues

We want:

Learner answer
→ AI FEEDBACK
→ backend commits decision
→ system automatically produces next teaching action

No progression command.

However:

If a new assessable question/task is created,
the system then WAITs for the learner.

============================================================
5. SERVER-DRIVEN CONTINUATION
============================================================

Implement the smallest clean mechanism that allows the backend to continue
through states that require NO learner input.

Conceptually:

while nextState.requiresLearnerInput === false:
    perform next pedagogical step
    persist resulting assistant message/state
    continue

STOP automatically when:

- CHECK_WAITING
- EXERCISE_WAITING
- any state requiring actual learner input
- terminal lesson/node state

Add a hard safety bound to prevent accidental internal loops.

Example:
maximum 2–3 internal non-user continuation steps per learner submission.

Do NOT allow unbounded recursive AI calls.

Use the authoritative V2-R1 state machine.

============================================================
7. ACTIVE TASK RULE
============================================================

At the end of auto-progression:

If the system reaches a new assessable task:

- exactly one active task must exist
- task text persisted immediately
- lastQuestionAsked updated
- hasActiveTask = true
- backend stops auto-progression
- waits for learner answer

If the system ends on TEACH/REMEDIATION content with no task yet,
continue only if the next deterministic state requires no learner input.

Never create two active tasks.
