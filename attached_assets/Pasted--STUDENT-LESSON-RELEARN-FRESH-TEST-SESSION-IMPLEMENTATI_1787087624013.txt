# STUDENT LESSON RELEARN — FRESH TEST SESSION IMPLEMENTATION

## GOAL

Implement the smallest safe flow for repeated AI Teacher testing from the student subject page.

Desired behavior:

* If the student has never started the lesson:

  * show **«Սովորել»**
  * existing start flow remains

* If the student already has a lesson session:

  * show **«Կրկին սովորել»**
  * clicking it resets only the lesson-session-local runtime state and chat history
  * then navigates to the same lesson page for a fresh run

This is for our current experimental testing workflow.

Do not redesign session architecture.

Do not create multiple sessions yet.

---

# CONFIRMED AUDIT FINDINGS — DO NOT RE-AUDIT

Already established:

1. Student lesson-card button is in:

`artifacts/myaiteacher/src/components/StudentLessonCard.tsx`

2. Current button is only a `<Link>` to:

`/lessons/:lessonId`

3. `POST /api/lessons/:lessonId/start` reuses an existing session.

4. DB schema technically allows multiple sessions, but current application logic uses one session per user+lesson.

5. `chat_messages` has no session ID and is loaded by:

`userId + lessonId`

6. Therefore a second session alone would NOT create fresh chat history.

7. Persistent learner history must remain untouched:

   * `evidence_events`
   * `knowledge_nodes`
   * mastery / learner-state history

8. Safest minimal testing solution now:

   * reset existing session row in place
   * delete only chat messages for this user+lesson
   * preserve persistent learner evidence/mastery

Do not spend tool calls proving these again.

# PART 4 — CLEAR ONLY THIS LESSON CHAT

Because `chat_messages` are keyed by user+lesson, delete only:

`chat_messages`
WHERE:

* `userId = current authenticated user`
* `lessonId = requested lesson`

Do NOT delete other lesson chats.

Do NOT delete another user's messages.

---

# PERSISTENT LEARNER HISTORY — MUST NOT TOUCH

Absolutely do NOT delete, reset, or modify:

* `evidence_events`
* `knowledge_nodes`
* mastery
* confidence
* Knowledge Tree
* learner-state history
* quiz results
* any persistent evidence outside the lesson session/chat

Fresh test session means:

**fresh runtime + fresh conversation**

NOT:

**erase what the learner previously demonstrated**

---

# TRANSACTION SAFETY

The fresh-start operation should be atomic.

Use a DB transaction for:

1. session reset/update
2. lesson chat deletion

If one fails, do not leave a half-reset state.

Reuse existing DB transaction conventions in the repo.

---

# IF NO SESSION EXISTS

`POST /start-fresh` must behave safely if the student somehow calls it without an existing session.

Preferred behavior:

reuse the same initialization logic as normal first-session creation, or create the initial session safely.

Do not return a broken/null state.

Avoid duplicating large session-creation logic if an existing helper/path can be reused cleanly.

# FRONTEND FLOW

For `Կրկին սովորել`:

1. Disable button while request is running.
2. Call:

`POST /api/lessons/:lessonId/start-fresh`

3. On success:

   * invalidate/refetch relevant lesson/session queries if needed
   * navigate to `/lessons/:lessonId`

4. On failure:

   * do not navigate
   * preserve current page
   * use the existing error/toast pattern if available

No new UI system.
