PART 1 — CORE MODEL
TWO DIFFERENT COGNITIVE VALUES
════════════════════════════════════════════════════

This distinction is mandatory.

For every MicroNode we must distinguish:

1. CURRICULUM TARGET COGNITIVE LEVEL

Example:

remember
→ understand
→ apply 🎯

Target = apply.

This describes what the curriculum/teacher expects.

2. CURRENT DEMONSTRATED COGNITIVE LEVEL

Example:

remember ✅
understand ✅
apply ⚠ not confirmed

Current demonstrated level = understand.

These are NOT the same thing.

Never automatically lower the curriculum target because the learner struggles.

Never mark an unconfirmed target as achieved.

Never interpret repeated failure as a permanent ability limit.

Use the semantic concept:

CURRENT DEMONSTRATED COGNITIVE LEVEL

Armenian learner/teacher-facing meaning:

«Ներկայում հաստատված ճանաչողական մակարդակ»

This is a TEMPORARY learner state.

It may increase later.

════════════════════════════════════════════════════

The Cognitive Path created in Phase 2A must begin controlling runtime teaching.

Example:

remember
→ understand
→ apply 🎯

Example:

CURRENT LEVEL = remember

When required evidence confirms remember:

remember = CONFIRMED

Then:

CURRENT LEVEL = understand

Teacher now teaches/checks understand.

CURRENT LEVEL = apply

Continue until target ceiling is confirmed.

Do NOT allow the AI model to invent the next Bloom level.

Use canonical order:

understand
apply
analyze
evaluate
create

but respect the actual cognitive path stored for that MicroNode.

PART 4 — INDEPENDENCE MATTERS
════════════════════════════════════════════════════

These are NOT equivalent evidence:

A.
Student answers correctly independently.

B.
Student answers correctly after Hint 1.

C.
Student answers correctly after Hint 2.

D.
Student succeeds only after step-by-step support.

The system must preserve this distinction.

A heavily scaffolded correct response may be useful learning evidence,
but it must not automatically count as equivalent to independent confirmation.

After substantial help, the system should normally require
a NEW EQUIVALENT INDEPENDENT TASK before confirming the cognitive level.

Do not simply repeat the exact same task and call that independent evidence.

PART 5 — REMEDIATION BUDGET
NO INFINITE TEACHING LOOP
════════════════════════════════════════════════════

The AI Teacher must not retry forever.

Introduce a deterministic REMEDIATION BUDGET / POLICY.

IMPORTANT:
First audit whether equivalent counters/state already exist.
Reuse existing state where possible.

The policy must represent pedagogical escalation,
not merely "attempt 1, attempt 2, attempt 3".

Conceptual sequence:

INITIAL TEACH/CHECK

If learner cannot demonstrate the level:

1. RE-EXPLAIN / ALTERNATE REPRESENTATION
2. DIFFERENT EXAMPLE or CONTRAST EXAMPLE
3. GUIDED SUPPORT / PROGRESSIVE HELP
4. PREREQUISITE CHECK or simplified diagnostic task
5. NEW EQUIVALENT INDEPENDENT CHECK

The exact action must also depend on error taxonomy.

Do NOT blindly execute every step for every error.

Example:

CONCEPTUAL
→ EXTRA_EXAMPLE / CONTRAST_EXAMPLE

PREREQUISITE
→ RETURN_TO_PREREQUISITE

PROCEDURAL
→ STEP_BY_STEP

READING_LANGUAGE
→ SIMPLIFY_LANGUAGE

GUESSING_CONFIDENCE
→ REQUIRE_REASONING

INCOMPLETE_COMMUNICATION
→ GUIDED_QUESTION

TRANSFER_BLOOM
→ CHANGE_REPRESENTATION

COGNITIVE_LOAD_PACE
→ LOWER_DIFFICULTY / RAISE_DIFFICULTY

Reuse the actual existing taxonomy/action registry if present.

PART 6 — REMEDIATION EXHAUSTION
════════════════════════════════════════════════════

This is a CRITICAL rule.

Suppose:

Curriculum target:
remember → understand → apply

Learner successfully confirms:

remember ✅
understand ✅

but repeatedly cannot independently demonstrate:

apply ❌

after the allowed remediation policy has been meaningfully exhausted.

DO NOT:

- loop forever
- fabricate mastery
- mark apply as confirmed
- lower the curriculum target
- label the learner permanently incapable

Instead record conceptually:

currentDemonstratedLevel = understand

targetCognitiveLevel = apply

targetReached = false

MicroNode = PARTIALLY ACHIEVED / REVISIT REQUIRED

Exact DB representation must be proposed from the existing schema.
Do not invent columns before audit.

════════════════════════════════════════════════════
PART 7 — DEPENDENCY / PREREQUISITE GATE
WHEN MAY WE MOVE TO THE NEXT MICRONODE?
════════════════════════════════════════════════════

Failure to reach the target does NOT automatically mean:

"stay here forever"

and does NOT automatically mean:

"move on"

Backend must decide using dependencies/prerequisites.

CASE A — NEXT MICRONODE REQUIRES THE UNCONFIRMED KNOWLEDGE

Example:

Current node target = apply
Learner confirmed only understand.

Next node requires apply from current node.

RESULT:

DO NOT ADVANCE.

Choose remediation / prerequisite work.

CASE B — NEXT MICRONODE DOES NOT REQUIRE THAT DEPTH

Current node target = apply.
Learner confirmed understand.
Next node can safely begin with understand.

RESULT:

May advance to next MicroNode.

BUT current node remains:

targetReached = false
currentDemonstratedLevel = understand
revisitRequired = true

It must NOT become mastered merely because we advanced.

CASE C — prerequisite itself is missing

If learner fails because an earlier prerequisite MicroNode is weak:

RETURN_TO_PREREQUISITE

must reference the real dependency graph.

Do not invent a dependency.

════════════════════════════════════════════════════

multiple_choice / matching

classification / short_answer

Do not hardcode these examples as universal rules.
