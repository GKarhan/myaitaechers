==================================================
CURRENT BUG
==================================================

Current teacher flow:

1. AI proposes lesson Goal + Outcomes.
2. Teacher imports them as draft.
3. The Goal is persisted correctly.
4. The Outcomes are NOT reliably persisted/read back.
5. After refresh, the Goal may exist while the Outcomes are missing.

This is the primary bug to fix.

Do NOT solve this by changing validation rules or inventing fallback Outcomes.

Find the actual persistence/read-back problem.

==================================================
TARGET UX
==================================================

The Goal/Outcome section should have only this simple lifecycle:

NO GOAL/OUTCOMES
        ↓
CREATE / AI PROPOSE
        ↓
IMPORT AS DRAFT
        ↓
GOAL + ALL OUTCOMES PERSISTED
        ↓
EDIT or DELETE

If deleted:

NO GOAL/OUTCOMES
        ↓
CREATE becomes available again.

No separate Goal/Outcome approval step is required.

==================================================

AI proposal

→ Goal persistence

→ transaction behavior
→ API response

Determine exactly why:

Goal persists
BUT
Outcomes do not reliably persist.

Inspect the real canonical Goal/Outcome tables/models and existing relations.

Do not assume the cause.

Before changing code, identify the exact root cause.

Possible categories include, but are not limited to:

A. frontend sends Goal but not Outcomes;
B. API receives Outcomes but does not insert them;
C. transaction only persists Goal;
D. schema/field mismatch;
E. Outcomes persist but read API does not return them;
F. UI ignores persisted Outcomes;
G. later invalidation/delete logic removes them;
H. another proven cause.

Report the proven cause.

PART 2 — FIX ATOMIC GOAL + OUTCOME PERSISTENCE
==================================================

When teacher clicks:

“Ներմուծել որպես draft”

the operation must persist:

- current lesson Goal;
- ALL proposed Outcomes.

Treat this as one logical operation.

Do not report successful import if only the Goal was persisted.

After write:

READ BACK the canonical lesson Goal + Outcomes from the database.

Success requires:

persisted Goal == intended Goal

AND

persisted Outcomes == intended Outcome set.

If read-back fails or Outcomes are missing:

do not silently report success.

«Նպատակը պահպանվել է, բայց վերջնարդյունքների պահպանումը չի ավարտվել։ Խնդրում ենք կրկին փորձել»։

Prefer atomic transaction behavior if compatible with the existing architecture.

Do not create duplicate Outcomes on retry.
