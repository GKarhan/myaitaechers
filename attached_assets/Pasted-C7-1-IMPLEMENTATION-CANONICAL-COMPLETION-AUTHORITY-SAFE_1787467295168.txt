==================================================
0. CORE OWNERSHIP CONTRACT — NON-NEGOTIABLE
==================================================

Canonical authority is:

C1 = curriculum / MicroNode structure
C2 = accepted Cognitive Path
C3 = evidence qualification
C4 = demonstrated cognitive ceiling
C5 = Knowledge Tree state
C6 = what learner should work on next
C7 = how the selected target is taught

Therefore C7 MUST NOT authorize progression from its own counters,
model output, answer quality, or pedagogical-engine candidate alone.

Canonical successful progression order MUST be:

learner response
→ authoritative task evaluation
→ create evidence candidate
→ C3 qualifies/rejects evidence
→ persist qualified evidence
→ C4 projects demonstrated ceiling
→ determine whether current level/node is actually confirmed
→ C6 resolves next target
→ atomically update session target/state
→ C7 teaches that target.

Never:

C7 completion candidate
→ advance node/level
→ write evidence later.

2. FIX THE PROGRESSION ORDER
==================================================

Refactor the smallest possible boundary so a progression candidate
is only a CANDIDATE until C3/C4 have completed.

The pedagogicalDecisionEngine MAY still say things such as:

- evidence appears sufficient
- level confirmation candidate
- node completion candidate
- remediation
- revisit

But candidate != authorization.

No level/node advancement may be persisted until:

1. the current evidence has been processed by the canonical C3
   qualification rules;

2. qualifying evidence has been durably persisted;

3. C4 projection has run from canonical qualified evidence;

4. the resulting demonstrated ceiling/current state proves that the
   required target is actually confirmed;

5. only then C6 is invoked to resolve the next canonical target.

If C3 rejects the evidence:

NO ADVANCEMENT.

If C3 classifies the evidence below the required independence/strength:

NO ADVANCEMENT unless canonical C3/C4 state already independently
satisfies the target.

If C4 does not confirm the required ceiling:

NO ADVANCEMENT.

4. UNLINKED / FALLBACK TASK SAFETY
==================================================

The audit found an important risk:

A generated/unlinked/fallback task may currently satisfy runtime
progression counters even when C3 would not qualify it.

Fix this.

A task that does not satisfy canonical C3 qualification requirements
must NEVER cause:

- level confirmation
- node completion
- C4 advancement
- C6 next-target progression.

Micro-check evidence must continue to obey its existing evidence cap.

Do not weaken C3 qualification to make tests pass.

5. C4 MUST PRECEDE C6 RE-ENTRY
==================================================

This ordering is mandatory:

C3
→ C4
→ C6

Never:

C6
→ C3/C4.

When the current turn appears to complete a level/node:

FIRST process C3 evidence.

THEN project C4.

THEN ask C6 what happens next.

C6 must receive/read the updated learner state.

This is especially important for PARTIAL learners:

If demonstrated ceiling was UNDERSTAND and the learner now qualifies
at APPLY, C4 must first become APPLY before C6 resolves the next target.

==================================================

Then C6 selects the next target.

9. ADVANCE-NODE REJECTION CASES
==================================================

POST /advance-node MUST reject progression when:

- current node is still THEORY;
- task is required but not completed;
- an active task is unresolved;
- evidence is unqualified;
- C4 demonstrated ceiling is below the required target;
- current C2 path is invalid;
- dependency/C6 state is blocked;
- session target is stale;
- requested/current node does not match canonical session state.

Use an explicit safe conflict/status response.

Do not silently advance.
