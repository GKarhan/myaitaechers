# D. AUDIT MICRO-NODE GRANULARITY

Inspect the actual Pass 2 prompt/schema and determine what rules currently govern MicroNode creation.

For each rule, identify whether it is:

* explicitly required,
* weakly suggested,
* absent,
* or deterministically validated.

We specifically care about this target:

> **One MicroNode = one clear learning objective that can be taught and checked independently.**

Audit whether the current system prevents cases such as:

### Too broad

One MicroNode contains:

* definition
* classification
* rules
* exceptions
* examples
* application

when those represent multiple teachable objectives.

### Too narrow

Multiple MicroNodes split what is really one indivisible learning objective into trivial fragments.

### Correct

One MicroNode has:

* one coherent concept/skill,
* one clear learning objective,
* source evidence supporting it,
* teachable explanation,
* independently checkable understanding.

Find the actual code/prompt logic responsible for this.

# E. CHECK FOR THE SPECIFIC FAILURE MODES

Determine whether the current pipeline can produce each of these:

1. **ORPHAN BLOCK**
   A meaningful Pass 1 block is not represented by any MicroNode.

2. **MULTI-OBJECTIVE MICRONODE**
   One MicroNode contains multiple independent learning objectives.

3. **OVER-MERGING**
   Several conceptually distinct source blocks are merged into one MicroNode merely because they are adjacent.

4. **OVER-SPLITTING**
   One coherent learning objective is unnecessarily split into multiple MicroNodes.

5. **SOURCE-LESS MICRONODE**
   A MicroNode exists without traceable source evidence.

6. **DUPLICATE COVERAGE**
   The same source block is unnecessarily assigned to multiple unrelated MicroNodes.

7. **NON-LEARNING BLOCK CONFUSION**
   Examples, headings, exercises, objectives, or other source blocks are incorrectly treated as independent knowledge MicroNodes—or incorrectly discarded when they contain meaningful instructional information.

For each failure mode give:

* Can it happen? YES / NO / NOT VERIFIED
* Exact evidence
* Where it can happen
* Whether a deterministic guard exists
