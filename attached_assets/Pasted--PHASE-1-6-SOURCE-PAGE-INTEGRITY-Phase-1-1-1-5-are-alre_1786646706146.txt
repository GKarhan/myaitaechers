# 1. DEFINE SOURCE INTEGRITY CLASSES

The system now contains at least two fundamentally different content classes.

## A. SOURCE-DERIVED CONTENT

Content originating from the textbook/PDF.

Examples:

* mapped MicroNodes
* textbook exercises

Its provenance must survive teacher operations.

## B. MANUAL CONTENT

Content created manually by the teacher after mapping.

Manual content does NOT need fake textbook provenance.

Never invent:

* fake sourcePage
* fake sourceBlockIndex
* fake sourceQuote
* fake textbook sourceType

Clearly distinguish these two classes using the fields/schema that already exist.

Do not add schema unless absolutely necessary and proven unavoidable.

---

# 2. SOURCE EXERCISE INTEGRITY — HARD GATE

For every source/textbook exercise in Lesson 105 verify:

### A. Verbatim source

`exerciseTextVerbatim`

must match the authoritative original extracted source block exactly.

No fuzzy matching.

No semantic similarity.

No normalization that changes source wording.

Exact source fidelity is required.

### B. Page integrity

`sourcePage`

must match the authoritative source block/page.

### C. Block integrity

If `sourceBlockIndex` exists and is authoritative:

* it must point to the correct source EXERCISE block
* the referenced block must belong to this lesson/source
* its text must correspond exactly to `exerciseTextVerbatim`

### D. Provenance

`sourceType = textbook` or the repository's actual equivalent must remain intact.

### E. Teacher operations must NOT destroy provenance

Verify that these operations preserve source metadata:

1. MicroNode → another MicroNode reassignment
2. MicroNode → Additional
3. Additional → MicroNode
4. approve exercise
5. approve-all exercises
6. edit teacher-editable fields
7. MicroNode reorder
8. Topic reorder

Changing `relatedNodeId` is allowed during reassignment.

Changing status is allowed during approval.

Those actions must NOT silently erase/change:

* sourceType
* sourcePage
* sourceBlockIndex
* original source identity

# 3. IMPORTANT — EDITING SOURCE EXERCISE TEXT

Audit the current Teacher Review behavior carefully.

Phase 1.3 currently allows exercise text editing.

We need to know what that means for source fidelity.

If a teacher edits a textbook exercise's displayed text and the system overwrites:

`exerciseTextVerbatim`

then the original textbook wording is destroyed.

That is a source-integrity violation.

Determine the actual behavior.

## Required invariant

For SOURCE-DERIVED exercises:

**The original textbook verbatim text must never be silently destroyed.**

Do NOT choose an architecture before auditing.

Possible existing safe designs include:

* immutable `exerciseTextVerbatim` + separate editable override/display field
* source snapshot stored elsewhere + edited working copy
* another existing provenance mechanism

Use the current schema/architecture if it already supports this.

If the current schema has ONLY one text field and editing it destroys the only exact source copy:

STOP.

Report this as a structural gap before adding schema or redesigning the model.

Do NOT silently add a new DB column in Phase 1.6 without explicit approval.

This is especially important.
