## IMPLEMENT PHASE 4 — MICRONODE GRANULARITY

Իրականացրու **Phase 4 — MicroNode Granularity**-ը՝ հիմնվելով վերջին forensic audit-ի վրա։

### Գլխավոր նպատակը

Mapper-ի MicroNode-ների granularity-ն պետք է վերահսկվի հետևյալ contract-ով.

> **ONE CLEAR LEARNING OBJECTIVE**

Յուրաքանչյուր MicroNode պետք է ներկայացնի **մեկ հստակ, ինքնուրույն սովորեցվող և գնահատելի learning objective**։

Պետք է կանխել երկուսն էլ.

* **MEGA-NODE / over-merging** — տարբեր cognitive operations կամ անկախ skills մեկ MicroNode-ում
* **OVER-SPLITTING** — նույն underlying skill-ը բաժանված է մի քանի MicroNode-ի

Կենտրոնական diagnostic test-ը մնում է.

> **Could two separate test questions be written such that a student could answer one correctly while failing the other?**

Եթե՝ **YES → մեծ հավանականությամբ պետք է SPLIT**։

Եթե երկու MicroNode փաստացի նույն underlying skill-ն են ներկայացնում տարբեր ձևակերպումներով → **MERGE / OVER-SPLIT finding**։

# P4.4 — REVIEW MODEL CONTRACT

Ստեղծիր առանձին review prompt։

Review model-ը պետք է ստուգի.

### 1. MEGA_NODE

Flag արա միայն այն դեպքում, երբ MicroNode-ի LO-ն իրականում պարունակում է **երկու կամ ավելի independently assessable objectives**։

Օրինակ՝

❌

> Student can define a verb and identify verbs in text.

Սա երկու տարբեր operations է.

* define
* identify in context

→ `MEGA_NODE`

Բայց **մի flag արա միայն այն պատճառով, որ նախադասության մեջ կա `և`, `ու`, `and` կամ `or`**։

Օրինակ՝

> Student can decompose a number by grouping digits from right to left.

Սա մեկ coherent procedure է։

→ NOT MEGA_NODE։

Այս տարբերությունը պարտադիր պահիր։

---

### 2. ONE PROCEDURE EXCEPTION

Մի բաժանիր մեկ MicroNode-ը միայն նրա համար, որ գործողությունը ունի մի քանի քայլ։

Օրինակ՝

> Student can solve a multi-step equation using substitution.

Եթե բոլոր քայլերը նույն underlying procedure-ի մասն են՝

→ ONE MicroNode։

Չպետք է լինի mechanical over-splitting։

---

### 3. OVER_SPLIT

Փնտրիր նույն topic-ի MicroNode-ների միջև նույն underlying objective-ը։

Օրինակ.

```text
Student can find unknown addend using inverse operations.

Student can apply the rules for finding unknown addend.
```

Եթե դրանք փաստացի նույն skill-ն են՝

→ `OVER_SPLIT`

և առաջարկ.

```text
Merge with: [other MicroNode]
```

---

### 4. EXERCISE_MISMATCH

Flag արա միայն այն դեպքում, երբ exercise-ի պահանջվող հիմնական skill-ը ակնհայտորեն դուրս է MicroNode-ի learning objective-ի scope-ից։

Օրինակ.

MicroNode LO:

> Student can solve problems using addition and subtraction.

Exercise:

> Calculate a unit price using division and then multiply by quantity.

→ `EXERCISE_MISMATCH`

Սակայն «closest prerequisite» assignment-ը ինքն իրեն mismatch-ի ապացույց չէ։

# P4.5 — DETERMINISTIC COMPOUND-LO HEURISTIC

Ստեղծիր.

`artifacts/api-server/src/lib/granularity-heuristics.ts`

Ավելացրու.

```ts
detectCompoundLO(...)
```

Այն պետք է լինի **signal generator**, ոչ թե decision-maker։

Պետք է կարողանա հայտնաբերել հնարավոր compound LO-ներ՝ օրինակ.


```text

```

Բայց պետք է չflag անի legitimate single procedures։

Օրինակ՝

```text
group digits from right to left
```

կամ մեկ գործողության ներսում step-description։

### Կարևոր

Regex-ը երբեք ինքնուրույն չպետք է որոշի.

> MEGA_NODE

Այն միայն ասում է.

> possible compound LO

Վերջնական semantic որոշումը անում է Pass 2B review model-ը։

# P4.9 — EXERCISE ALIGNMENT
