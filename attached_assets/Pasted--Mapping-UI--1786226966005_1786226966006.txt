### Քարտեզագրման բլոկ — ամբողջ քարտեզագրման ջնջում

Պետք է փոփոխել Mapping UI-ն այնպես, որ պահպանվեն **երկու առանձին ջնջման գործողություններ**։

#### 1. Առանձին Node-ի ջնջում — ՊԱՀՊԱՆԵԼ

Ներկայիս յուրաքանչյուր Node-ի մոտ գտնվող 🗑️ «Ջնջել» գործողությունը պետք է մնա և շարունակի աշխատել ինչպես հիմա։

Այն ջնջում է միայն տվյալ Node-ը և դրա թույլատրելի կապված տվյալները։

**Այս ֆունկցիոնալությունը չհանել և չփոխարինել։**

---

#### 2. Ամբողջ քարտեզագրման ջնջում — ԱՎԵԼԱՑՆԵԼ

Mapping բլոկի վերևում կամ header-ի գործողությունների հատվածում ավելացնել առանձին գործողություն.

**🗑️ Ջնջել ամբողջ քարտեզագրումը**

Դրա նպատակն է՝

> ամբողջությամբ մաքրել տվյալ Lesson-ի ներկայիս mapping-ը, որպեսզի ես կարողանամ նոր քարտեզագրում ստեղծել կամ նույն դասի քարտեզագրումը նորից փորձարկել։

Այն **չպետք է ջնջի Lesson-ը, դասի վերնագիրը, էջերը կամ Lesson-ի այլ հիմնական տվյալները**։

Ջնջվում է միայն այդ Lesson-ին պատկանող mapping-ը։

### Backend

Ամբողջ mapping-ը ջնջելու համար ստեղծել **մեկ backend գործողություն**, որը աշխատում է `lessonId`-ով։

Չանել այսպես՝

```text
frontend
→ Node 1 delete
→ Node 2 delete
→ Node 3 delete
→ ...
```

Փոխարենը պետք է լինի մեկ ամբողջական գործողություն՝

```text
DELETE ENTIRE LESSON MAPPING
        ↓
      transaction
        ↓
delete mapping relations
delete dependencies
delete exercises
delete source blocks
delete microNodes
delete lesson-node relations
delete nodes
        ↓
      commit
```

Ճշգրիտ հերթականությունը որոշել repository-ի իրական database schema-ի և foreign key-ների հիման վրա։

**Չհորինել table/field անուններ։ Նախ ուսումնասիրել իրական schema-ն։**

---

### Շատ կարևոր սահմանափակում

`Lesson` entity-ն չջնջել։

Օրինակ՝

```text
Lesson
 ├── title
 ├── pages
 ├── textbook
 └── MAPPING
      ├── Nodes
      ├── MicroNodes
      ├── SourceBlocks
      ├── Exercises
      └── Dependencies
```

Ամբողջ քարտեզագրումը ջնջելու դեպքում պետք է ստացվի.

```text
Lesson
 ├── title
 ├── pages
 ├── textbook
 └── MAPPING
      └── EMPTY
```

Այս վիճակից հետո ես պետք է կարողանամ նույն Lesson-ի վրա նոր քարտեզագրում ստեղծել։

---

### UI-ից հետո

Հաջող ջնջումից հետո Mapping էջը պետք է անմիջապես ցույց տա դատարկ վիճակ, օրինակ՝

> **Քարտեզագրում չկա**
>
> Այս դասի համար քարտեզագրումը ջնջված է։
> Կարող եք ստեղծել նոր քարտեզագրում։

Եթե համակարգում արդեն կա «Ավտոմատ քարտեզագրել» կամ «Ձեռքով քարտեզագրել» գործողություն, դրանք պետք է հասանելի մնան, որպեսզի ջնջելուց հետո անմիջապես հնարավոր լինի նորից սկսել։

### Կարևոր՝ երկու գործողությունները չխառնել

UI-ում պետք է հստակ տարբերակված լինեն.

**Node-ի մակարդակ**

🗑️ Ջնջել Node

**Mapping-ի մակարդակ**

🗑️ Ջնջել ամբողջ քարտեզագրումը

Ամբողջ mapping-ի ջնջումը չպետք է փոխարինի Node-ի առանձին ջնջմանը։

---

### Նախքան փոփոխությունը

Սկզբում ուսումնասիրիր repository-ն և գտիր.

* Mapping UI component-ը
* ներկայիս Node delete implementation-ը
* mapping-ի backend endpoint/service-ը
* database schema-ն
* Node / MicroNode / SourceBlock / Exercise / Dependency հարաբերությունները
* foreign key constraints-ը
* գոյություն ունեցող cascade delete-ները

Հետո իրականացրու փոփոխությունը նախագծի ներկայիս architecture-ին համապատասխան։

Եթե արդեն կա համապատասխան service/helper, reuse արա այն և duplicate logic մի ստեղծիր։

Վերջում ստուգիր TypeScript/build/lint-ը և համոզվիր, որ.

1. առանձին Node delete-ը շարունակում է աշխատել,
2. ամբողջ Mapping delete-ը աշխատում է մեկ գործողությամբ,
3. Lesson-ը չի ջնջվում,
4. մյուս Lesson-ների mapping-ները չեն ազդվում,
5. partial delete չի մնում failure-ի դեպքում,
6. ջնջելուց հետո հնարավոր է նույն Lesson-ի վրա նոր mapping ստեղծել։
