T8.1 — SMALL TARGETED IMPLEMENTATION
TEACHER QUIZ CREATION — REMOVE DIFFICULTY AS EDUCATIONAL CHOICE

This is a SMALL, NARROW, REGRESSION-SAFE change.

Do not expand scope.

==================================================
GOAL
==================================================

The teacher must no longer choose:

- Պարզ / SIMPLE
- Միջին / MEDIUM
- Բարդ / HARD
- Խառը / MIXED

when creating a normal quiz.

The educational assessment authority is now:

MicroNode
→ confirmed Cognitive Path
→ canonical target Cognitive Level
→ generated assessment question

The teacher must NOT manually choose Bloom or use difficulty
as a substitute for Bloom.

Instead, the quiz-creation UI must clearly tell the teacher that
the quiz will assess the mapped target Cognitive Levels.

==================================================
IMPORTANT — INTERNAL DIFFICULTY IS NOT BEING REMOVED
==================================================

Do NOT remove:

- quizzes.difficultyMode
- quiz_questions.difficultyLevel
- LOW / MEDIUM / HIGH
- computeSplit()
- provider difficulty instructions
- async request snapshot difficultyMode
- difficulty persistence
- attempt snapshot difficulty
- evidence taskDifficulty
- teacher quiz-review difficulty metadata

No database migration.

For compatibility, the backend may continue normalizing an omitted
difficultyMode to MIXED.

Therefore:

Teacher no longer chooses difficulty.

Internally:

difficultyMode = MIXED

continues to produce the existing within-level complexity distribution.

This step changes ONLY the teacher-facing quiz creation contract.
