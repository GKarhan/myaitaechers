PART 3 — SIX-LEVEL OPERATIONAL CONTRACT
==================================================

Implement ONE explicit operational contract for:

remember
understand
apply
analyze
evaluate
create

This is NOT a second curriculum taxonomy.

It operationalizes the existing Cognitive Path taxonomy for assessment validation.

Each level contract must define at minimum:

1. requiredPerformance
2. validQuestionCharacteristics
3. rejectedLowerLevelSubstitutes
4. naturallyCompatibleInteractionTypes

Use the following educational contract.

--------------------------------------------------
REMEMBER
--------------------------------------------------

Required performance:

Retrieve or recognize an explicitly taught fact, term, definition, relationship, rule, or step.

Valid demands include:

- recall
- recognition
- direct identification

Reject:

- unrelated trivia
- content outside the MicroNode
- answer-revealing or malformed questions

--------------------------------------------------
UNDERSTAND
--------------------------------------------------

Required performance:

Interpret meaning, explain, paraphrase, classify, connect an example to a concept, or distinguish example/non-example.

Valid demands include:

- interpretation
- classification
- explanation selection
- example/non-example recognition
- conceptual relationship

Reject as insufficient:

A question answerable only by verbatim recall of a fact, definition, formula, or isolated statement.

--------------------------------------------------
APPLY
--------------------------------------------------

Required performance:

Use a mapped rule, method, relationship, procedure, or concept in a concrete case.

Valid demands include:

- calculation
- procedure execution
- scenario-based application
- problem solving
- applying a relationship to supplied values/conditions

Reject as insufficient:

- asking only for a formula
- asking only for a memorized unit relationship
- asking only for a definition
- asking for a worked answer copied from instructional content
- pure recognition without use

--------------------------------------------------
ANALYZE
--------------------------------------------------

Required performance:

Decompose information, identify relationships, compare components using evidence, distinguish structure/cause, infer relationships, or analyze an error.

Valid demands include:

- relationship analysis
- evidence comparison
- error analysis
- decomposition
- structured classification
- determining why/where a solution or claim differs

Reject as insufficient:

Routine one-step application of a rule that requires no decomposition, comparison, relationship reasoning, or structural analysis.

--------------------------------------------------
EVALUATE
--------------------------------------------------

Required performance:

Make and justify a judgment using explicit criteria, evidence, correctness conditions, or competing approaches.

Valid demands include:

- critique
- defensible choice
- evaluating a claim
- evaluating a method
- selecting a better solution AND justifying why
- evidence-based judgment

Reject as insufficient:

- simple comparison
- identifying differences
- analysis without judgment
- selecting an answer without requiring a defensible criterion

--------------------------------------------------
CREATE
--------------------------------------------------

Required performance:

Produce, design, construct, formulate, synthesize, or propose a new valid artifact/solution/plan/model under constraints.

Valid demands include:

- design
- compose
- construct
- formulate
- propose
- synthesize

Reject as insufficient:

- selecting among already completed answers
- merely judging an existing solution
- ordinary recognition-only multiple choice

PART 6 — DETERMINISTIC VALIDATOR
==================================================

Implement a PURE deterministic validator.

No provider call.
No database call.
No mutation.

Suggested contract:

validateGeneratedQuestionCandidate(
  candidate,
  context
)

Return a structured result such as:

{
  passed: boolean,
  reasonCodes: QualityReasonCode[]
}

It must deterministically validate what CAN be known deterministically.

At minimum:

1. question text is non-empty and usable
2. no placeholder question text
3. current multiple-choice candidate has exactly 4 usable options
4. options are non-empty
5. options are distinct after normalized comparison
6. correctOptionIndex is valid
7. optionExplanations shape is valid when present
8. candidate node identity cannot contradict canonical node identity
9. candidate Cognitive Level identity cannot contradict canonical target identity
10. difficulty enum is valid but MUST NOT influence Cognitive Level
11. current delivery compatibility is explicit
12. preferred interaction incompatibility is reported
13. duplicate/near-duplicate detection can be invoked against already accepted questions

DO NOT attempt to determine Bloom semantics with string keyword heuristics.

For example:

Question contains "բացատրիր"

MUST NOT automatically mean Understand.

Question contains "կիրառիր"

MUST NOT automatically mean Apply.

Semantic Cognitive Level judgment belongs to the future semantic-review layer.
