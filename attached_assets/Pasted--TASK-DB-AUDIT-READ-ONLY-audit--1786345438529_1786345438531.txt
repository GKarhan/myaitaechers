## TASK — «Միլիոնների դաս» քարտեզագրման ամբողջական DB AUDIT

Կատարիր **READ-ONLY audit**։ ՈՉ ՄԻ տվյալ չփոխես, չավելացնես, չջնջես, migration չանես և code չփոփոխես։

Քո նպատակն է պարզել՝ «Միլիոնների դաս» դասի համար **իրական PostgreSQL բազայում ինչ mapping-related տվյալներ են պահպանված**, նույնիսկ եթե դրանք platform-ի UI-ում չեն ցուցադրվում։

### Դասը, որը պետք է գտնես

Դասի վերնագիր՝ **Միլիոնների դաս**

Էջեր՝ **8–11**

Բաժին / §՝ **1.1**

Հարթակում այս դասը երևում է մոտավորապես այս կառուցվածքով.

* Միլիոնների դասի ներածություն
* Թվերի կարդալու կանոններ
* Թվերի տրոհում և մեկնաբանություն
* textbook exercises 17, 18, 19, 20, 21, 22, 25, 26, 27, 28

Եթե վերնագրով մի քանի record կա, գտիր այն record-ը, որի pages-ը համապատասխանում է 8–11-ին և որի nodes/exercises-ը համապատասխանում են վերևի բովանդակությանը։

---

# 1. Սկզբում գտիր Lesson-ի իրական ID-ն

Փնտրիր `lessons` table-ում «Միլիոնների դաս» դասը։

Ցույց տուր ամբողջ matching lesson row-ը՝ **բոլոր սյունակներով**, ոչ միայն հիմնական դաշտերով։

Եթե կան մի քանի matching rows, ցույց տուր բոլորը և նշիր՝ որն ես համարում հիմնականը և ինչու։

---

# 2. Այդ Lesson-ի համար հանիր ԲՈԼՈՐ Lesson-level mapping fields

Գտած `lessonId`-ով հանիր ամբողջ lesson row-ն։

Յուրաքանչյուր field-ի համար ցույց տուր՝

FIELD | VALUE | STATE

որտեղ STATE-ը լինի՝

* FILLED — իրական արժեք կա
* NULL — database value = NULL
* EMPTY — դատարկ string/array/object
* DEFAULT — default արժեք է
* NOT_PRESENT — տվյալ table-ում այդ field-ը գոյություն չունի

**Մի թաքցրու NULL դաշտերը։**

# 7. Փնտրիր MicroNode-specific տվյալները

Ստուգիր՝ ներկայիս DB architecture-ում MicroNode-ը.

ա) առանձին table է,

* microNodeId
* microNodeType

* sourceRef
* sourceBlockIds
* confidenceScore

և տվյալ «Միլիոնների դասի» համար դրանց արժեքները։

# 10. Ամենակարևոր կանոնը

Սա **ոչ թե mapping quality audit է**, այլ **physical DB state audit**։

Չգնահատես՝ ճիշտ է, սխալ է, լավ է, վատ է։

Միայն արձանագրիր.

**ինչ կա DB-ում, ինչ չկա DB-ում, ինչն է NULL, և ինչն է UI-ում չերևում։**

Մի՛ փորձիր բացակայող տվյալները վերականգնել կամ ենթադրել։

# 11. Վերջնական ամփոփում

Վերջում տուր միայն այս 4 բաժինը.

### A. LESSON

Lesson ID + ամբողջ իրական DB state-ը

### B. NODES

Բոլոր nodes + բոլոր mapping-related fields

### C. EXERCISES

Բոլոր exercises + բոլոր mapping-related fields

### D. DB vs UI GAP

Որ fields-ը **կա DB-ում, բայց UI-ում չի երևում**։

Հատուկ առանձնացրու.

`DB HAS VALUE → UI DOES NOT SHOW`

Սա է audit-ի հիմնական նպատակը։

**Կրկնում եմ՝ READ-ONLY։ Ոչ մի փոփոխություն repository-ում կամ database-ում։**
