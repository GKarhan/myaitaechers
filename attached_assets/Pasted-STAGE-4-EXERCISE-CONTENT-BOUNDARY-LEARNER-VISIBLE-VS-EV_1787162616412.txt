1. CANONICAL CONTENT-AUDIENCE CONTRACT
==================================================

Make the content ownership explicit.

The intended contract is:

A. exerciseTextVerbatim

Purpose:
- source-fidelity / provenance record
- preserve the original source exercise as faithfully as possible

Audience:
- teacher
- audit/provenance/backend

It is NOT automatically learner-safe.

It must NOT be treated as inherently safe merely because it came from a
textbook or mapper.

--------------------------------------------------

B. exerciseTextEdited

Purpose:
- approved learner-facing task representation

Audience:
- learner delivery
- student-facing exercise APIs
- bounded EVALUATION as the effective learner task

This is the preferred learner-safe delivery field when present.

--------------------------------------------------

C. successCriteria

Purpose:
- evaluator-only semantic rubric
- expected-response guidance
- criteria needed to judge constructed responses

Audience:
- backend
- teacher
- bounded EVALUATION only

MUST NOT be returned to learners.

MUST NOT be appended to learner-facing task text.

--------------------------------------------------

D. correctAnswer

Purpose:
- canonical hidden answer metadata for deterministic evaluation

Audience:
- backend deterministic evaluator
- teacher authoring/review

MUST NOT be returned to learners.

MUST NOT be embedded into learner-facing task text.

--------------------------------------------------

E. interactionType

Purpose:
- authoritative response/evaluation format

Audience:
- backend
- teacher authoring
- bounded task/evaluation logic where required

Do not expose it merely because it exists.

3. SOURCE FIDELITY MUST NOT BE DESTROYED
==================================================

Do NOT sanitize or rewrite exerciseTextVerbatim destructively.

If source material literally contains:

"Ճիշտ պատասխան՝ ..."

or

"Սպասվող պատասխանի հիմնական միտքը՝ ..."

The system must separate:

SOURCE RECORD
from
LEARNER DELIVERY

Do not solve the leak by deleting provenance.

4. LEARNER-SAFE TASK REQUIREMENT
==================================================

A source exercise must have a learner-safe representation before normal
student delivery.

The backend must not blindly assume:

exerciseTextEdited || exerciseTextVerbatim

is safe.

Define one authoritative helper/contract for learner-facing exercise text.

Avoid multiple inconsistent implementations.

The helper must distinguish:

- safe edited learner text
- source/verbatim fallback eligibility
- content that requires review because it appears to contain evaluator-only
  answer/rubric guidance

Do NOT silently remove arbitrary words from a contaminated exercise at runtime.

Do NOT use naive string deletion to manufacture a question.

If the backend cannot establish a learner-safe representation:

→ do not deliver contaminated text
→ do not activate an unsafe task
→ return/use the existing controlled safe-failure behavior appropriate to the
  route
→ preserve session consistency

No fabricated task.
