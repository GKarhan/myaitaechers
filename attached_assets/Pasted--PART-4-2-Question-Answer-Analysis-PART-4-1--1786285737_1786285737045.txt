# PART 4.2 — Question Answer Analysis / Պատասխանների ուսումնական բացատրություն

PART 4.1-ը արդեն իրականացված է, բայց ներկայիս Quiz Result էջը դեռ չի տալիս այն ուսումնական վերլուծությունը, որն անհրաժեշտ է։

**Մի՛ վերափոխիր PART 1, PART 2, PART 3 կամ արդեն աշխատող scoring / Knowledge Tree / Evidence Mapping logic-ը։**

Այս task-ի նպատակը միայն այն է, որ **Quiz Result էջում յուրաքանչյուր հարցի համար ցույց տրվի՝ ինչու է ճիշտ պատասխանը ճիշտ, և եթե աշակերտը սխալ է պատասխանել՝ ինչու է իր ընտրած պատասխանը սխալ։**

---

## 1. Հիմնական ֆայլը

Աշխատանքի հիմնական frontend ֆայլը՝

```text
myaiteacher/src/pages/quiz-result.tsx
```

Backend-ը ուսումնասիրիր միայն այն դեպքում, եթե ներկայիս API-ն անհրաժեշտ տվյալը չի փոխանցում։

Եթե backend փոփոխություն անհրաժեշտ է, փոխիր միայն այն նվազագույն հատվածը, որը անհրաժեշտ է այս feature-ի համար։

---

# 2. Ինձ պետք է ոչ թե պարզապես "feedback", այլ ANSWER ANALYSIS

Ներկայիս էջում արդեն կա.

* հարցը
* բոլոր պատասխանների տարբերակները
* աշակերտի ընտրած պատասխանը
* ճիշտ պատասխանը
* Node / թեման

Սա պահպանիր։

Բայց յուրաքանչյուր հարցի տակ պետք է ավելացնել **կարճ տեսական բացատրություն**, որը բացատրում է պատասխանի իմաստը։

### Ամեն հարցի համար պետք է լինի առանձին analysis։

Օրինակ.

```text
Հարց․
Քանի՞ հաջորդական կարգ կազմում է մեկ դաս։

📌 Միլիոնների դասի ներածություն

A. 1
B. 2  ← աշակերտի պատասխանը
C. 3  ← ճիշտ պատասխան
D. 4
```

Արդյունքը պետք է լինի.

```text
❌ Քո պատասխանը՝ B. 2

Ինչու է սխալ․
Մեկ դասը կազմված չէ երկու կարգից։ Այն կազմված է երեք հաջորդական կարգերից։

✅ Ճիշտ պատասխան՝ C. 3

Ինչու է ճիշտ․
Մեկ դասը կազմված է երեք հաջորդական կարգերից։
```

---

# 3. Եթե աշակերտը ՃԻՇՏ է պատասխանել

Այդ դեպքում պետք է ցույց տալ **ճիշտ պատասխանի կողքին/տակ նրա տեսական բացատրությունը**։

Օրինակ.

```text
✅ Քո պատասխանը՝ B. Հազարների քանակը

Ինչու է ճիշտ․
Հազարների դասում գրված թիվը ցույց է տալիս, թե քանի հազար կա տվյալ թվի մեջ։
```

Այս դեպքում սխալ պատասխանի explanation պետք չէ։

---

# 4. Եթե աշակերտը ՍԽԱԼ է պատասխանել

Պետք է ցույց տալ **երկու բացատրություն**.

### A. Աշակերտի ընտրած սխալ պատասխանի բացատրությունը

```text
❌ Քո պատասխանը՝ B. 2

Ինչու է սխալ․
Մեկ դասը կազմված չէ երկու հաջորդական կարգից։
```

### B. Ճիշտ պատասխանի բացատրությունը

```text
✅ Ճիշտ պատասխան՝ C. 3

Ինչու է ճիշտ․
Մեկ դասը կազմված է երեք հաջորդական կարգից։
```

Այս երկուսը պարտադիր պետք է լինեն **միմյանցից առանձին**։

---

# 5. Շատ կարևոր տարբերություն

Չշփոթել հետևյալ երկու բաները.

### Սխալ մոտեցում

```text
❌ Ինչու է սխալ
Դու սխալ ես ընտրել 2-ը։
```

Սա բավարար չէ։

### Ճիշտ մոտեցում

```text
❌ Ինչու է սխալ
Մեկ դասը կազմված չէ երկու կարգից, որովհետև յուրաքանչյուր դասում կա երեք հաջորդական կարգ։

✅ Ինչու է ճիշտ
Ճիշտ պատասխանը 3-ն է, որովհետև մեկ դասը կազմված է երեք հաջորդական կարգից։
```

Այսինքն explanation-ը պետք է լինի **ուսուցողական տեսական փաստ**, ոչ թե պարզապես "դու սխալ ես"։

---

# 6. Յուրաքանչյուր option-ի համար պետք է հնարավոր լինի ունենալ explanation

Տվյալների մակարդակում ցանկալի կառուցվածքը սա է.

```ts
answerOptions: [
  {
    text: "...",
    isCorrect: false,
    explanation: "..."
  },
  {
    text: "...",
    isCorrect: true,
    explanation: "..."
  }
]
```

Կամ եթե ներկայիս schema-ն այլ է, օգտագործիր դրա համապատասխան կառուցվածքը։

Գլխավոր պահանջը՝

**Յուրաքանչյուր պատասխան option պետք է կարողանա ունենալ իր սեփական explanation-ը։**

Ոչ թե ամբողջ հարցին մեկ ընդհանուր explanation։

---

# 7. Ինչ պետք է ցույց տրվի UI-ում

Յուրաքանչյուր հարցի համար.

### Correct case

```text
✅ Հարց

📌 Node / թեմա

A. ...
B. ... ← աշակերտի ընտրած
C. ...
D. ...

💡 Ինչու է ճիշտ
[կարճ տեսական բացատրություն]
```

### Wrong case

```text
❌ Հարց

📌 Node / թեմա

A. ...
B. ... ← աշակերտի ընտրած
C. ... ← ճիշտ

❌ Քո պատասխանը՝ B. ...

Ինչու է սխալ
[կոնկրետ տեսական բացատրություն, թե ինչու B-ն սխալ է]

✅ Ճիշտ պատասխանը՝ C. ...

Ինչու է ճիշտ
[կոնկրետ տեսական բացատրություն, թե ինչու C-ն ճիշտ է]
```

---

# 8. Բացատրության բովանդակության կանոնները

Explanation-ը պետք է լինի.

* հայերեն
* կարճ
* աշակերտին հասկանալի
* տեսականորեն ճիշտ
* կոնկրետ տվյալ option-ի վերաբերյալ
* առանց ավելորդ ընդհանուր խոսքի
* առանց աշակերտին ամոթանք տալու
* առանց "դու չգիտես" ձևակերպումների

Այն պետք է պատասխանի հարցին.

> **"Ի՞նչ կանոնի կամ գիտելիքի պատճառով այս պատասխանը ճիշտ/սխալ է։"**

---

# 9. Չհորինել explanation

Սա շատ կարևոր է։

Explanation-ը պետք է ստացվի **վստահելի source-ից**։

Առաջնահերթությունը.

1. Question/answer-specific explanation, եթե արդեն կա
2. Quiz question-ի source/content
3. Կապված lesson node-ի տեսական բովանդակությունը
4. `childFriendlyExplanation`
5. `commonMisconception`
6. Source material / textbook content

Եթե տվյալ պատասխան option-ի համար վստահելի բացատրություն չկա՝

**մի հորինիր փաստ։**

Այդ դեպքում report արա, որ տվյալ option-ի explanation-ի source-ը բացակայում է։

# 11. Ամեն հարցի համար անկախ տվյալ

Շատ կարևոր է, որ explanation-ը չխառնվի նույն Node-ի մյուս հարցերի հետ։

Օրինակ՝ եթե նույն Node-ի տակ կա 7 հարց.

```text
Q1 → explanation 1
Q2 → explanation 2
Q3 → explanation 3
...
Q7 → explanation 7
```

Չի կարելի Node-level մեկ explanation օգտագործել բոլոր 7 հարցերի համար, եթե դա չի համապատասխանում տվյալ հարցի կոնկրետ պատասխանին։

# 12. Քո ներկայիս թեստի օրինակով

Այս հարցի համար.

```text
Քանի՞ հաջորդական կարգ կազմում է մեկ դաս։

A. 1
B. 2
C. 3 ✓
D. 4
```

Եթե աշակերտը ընտրել է B.

պետք է ստացվի մոտավորապես.

```text
❌ Քո պատասխանը՝ B. 2

Ինչու է սխալ․
Մեկ դասը կազմված չէ երկու հաջորդական կարգից։ Յուրաքանչյուր դասում երեք հաջորդական կարգ է ընդգրկվում։

✅ Ճիշտ պատասխանը՝ C. 3

Ինչու է ճիշտ․
Մեկ դասը կազմված է երեք հաջորդական կարգից։
```

Եթե աշակերտը ընտրել է C.

```text
✅ Քո պատասխանը՝ C. 3

Ինչու է ճիշտ․
Մեկ դասը կազմված է երեք հաջորդական կարգից։
```

Նույն տրամաբանությունը կիրառիր **բոլոր 10 հարցերի համար**։

# 13. Existing Armenian UI

Միաժամանակ վերջնական UI-ում չպետք է մնան տեխնիկական placeholder-ներ, օրինակ.

```text
[LEARN_FULL]
[LEARN_TARGETED]
[TOPIC_BREAKDOWN]
[WHY_CORRECT]
[WHY_WRONG]
```

Դրանք պետք է լինեն բնական հայերեն։

Օրինակ.

```text
LEARN_FULL → Ամբողջական ուսուցում
LEARN_TARGETED → Թիրախային ուսուցում
TOPIC_BREAKDOWN → Թեմաների ամփոփում
WHY_CORRECT → Ինչու է ճիշտ
WHY_WRONG → Ինչու է սխալ
```

# 14. Backend / Schema

Նախ ստուգիր՝ ներկայիս API/database-ը արդյոք կարող է ապահովել **option-level explanation**։

Եթե կարող է՝ օգտագործիր գոյություն ունեցող տվյալները։

Եթե չի կարող՝

1. միանգամից migration մի արա,
2. մի փոխիր schema-ն առանց անհրաժեշտության,
3. report արա՝ կոնկրետ որ table/column-ն է պակասում,
4. առաջարկիր նվազագույն schema փոփոխությունը։

**Առանց իմ հաստատման migration չանել։**

# 16. Verification

Փորձարկել առնվազն.

### Test 1 — Correct answer

Ստուգել, որ.

```text
ճիշտ պատասխան
+
ինչու է ճիշտ
```

երևում են։

### Test 2 — Wrong answer

Ստուգել, որ.

```text
աշակերտի սխալ պատասխան
+
ինչու է սխալ
+
ճիշտ պատասխան
+
ինչու է ճիշտ
```

բոլորը երևում են։

### Test 3 — Same Node

Միևնույն Node-ի տակ գտնվող տարբեր հարցերի explanations-ը չպետք է խառնվեն։

### Test 4 — 10 questions

Բոլոր 10 հարցերը պետք է ունենան իրենց սեփական answer analysis-ը։

### Test 5 — Missing explanation

Եթե տվյալ option-ի համար source չկա, UI-ում չցուցադրել կեղծ կամ հորինված explanation։

# 17. Վերջնական report

Վերջում ինձ ցույց տուր.

1. Որ ֆայլերն ես փոխել
2. Ինչ backend/frontend փոփոխություն ես արել
3. Որտեղից է գալիս յուրաքանչյուր answer explanation-ը
4. Ինչպես է աշխատում Correct case-ը
5. Ինչպես է աշխատում Wrong case-ը
6. Ինչպես ես ապահովել Question-level isolation-ը
7. Որ հարցերի/option-ների համար explanation source չկա
8. Schema փոփոխություն պահանջվո՞ւմ է, թե ոչ
9. Verification-ի արդյունքները

**Կարևորագույն պահանջը՝ ինձ պետք է ոչ թե պարզապես "Why correct / Why wrong" UI label, այլ յուրաքանչյուր պատասխան տարբերակի վերաբերյալ կարճ, կոնկրետ, ուսուցողական տեսական բացատրություն։**
