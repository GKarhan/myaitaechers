1. CONFIRMED PRODUCT WORKFLOW
════════════════════════════════════════════════════

There are TWO valid entry paths.

PATH A — TEACHER PROVIDES GOAL/OUTCOMES

Teacher enters:
- Lesson Goal
- zero or more draft Outcomes

The system must still analyze the lesson source.

AI may:
- preserve good teacher wording
- improve wording
- add missing Outcomes
- merge duplicates
- split overly broad Outcomes
- identify source coverage gaps

The resulting proposal is still DRAFT.

Teacher reviews/edits it.

Teacher explicitly confirms the final canonical Goal + Outcomes.

ONLY THEN may detailed mapping proceed.


PATH B — TEACHER PROVIDES NOTHING

Teacher leaves Goal/Outcomes empty.

Teacher requests source-based proposal.

AI analyzes the lesson source and proposes:
- one Lesson Goal
- all appropriate Lesson Outcomes

The proposal is DRAFT, not approved.

Teacher imports/accepts the proposal into canonical draft state.

Teacher may then:
- edit Goal
- edit Outcomes
- add Outcomes
- delete Outcomes
- reorder Outcomes

Teacher explicitly confirms final Goal + Outcomes.

ONLY THEN may detailed mapping proceed.


Both paths converge to:

SOURCE
→ Goal/Outcome proposal
→ canonical draft
→ teacher review/edit
→ TEACHER CONFIRMATION
→ detailed mapping
→ Topic/MicroNodes
→ Outcome↔MicroNode alignment
→ validation
→ final mapping approval

This is the canonical C1 workflow.

not a PRE-MAPPING Goal/Outcome confirmation requirement.
