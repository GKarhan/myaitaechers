1. CRITICAL DISTINCTION — LINKED TEST ≠ RELEASED TEST
==================================================

This distinction is mandatory.

A test can be LINKED to a Lesson without being RELEASED to the student.

Example:

Lesson A has:

Test 1
Test 2
Test 3

All three may belong to / be linked to Lesson A.

But the teacher may decide:

- Test 1 should be available before or early in the lesson
- Test 2 should become available later
- Test 3 should become available at the end

We are NOT implementing automatic pedagogical timing in Phase 1.12.

The teacher controls release manually.

Therefore:

LINKAGE answers:

"Which tests belong to this lesson?"

RELEASE / ASSIGNMENT answers:

"Which of those tests may this student solve right now?"

These MUST NOT be treated as the same state.

7. LINKED TESTS TRAVEL WITH THE LESSON — BUT LOCKED
==================================================

This requirement is subtle and mandatory.

When Lesson A is assigned to Student S:

the student may be able to SEE that the Lesson has linked tests if the current UI/product model supports showing them.

BUT:

A linked test MUST NOT automatically become solvable merely because the Lesson was assigned.

Example:

Linked tests:

Test 1 — not released
Test 2 — released
Test 3 — not released

Student state must behave like:

visible if appropriate

Սկսել = enabled

Test 3
visible if appropriate
Սկսել = disabled / unavailable

8. TEACHER RELEASE CONTROL
==================================================

Teacher must be able to release linked tests independently.

Example:

Lesson assigned today.

Teacher initially releases no tests.

Later:

Teacher clicks "Ուղարկել" on Test 1.

Only Test 1 becomes startable.

Later:

Teacher releases Test 2.

Now Test 1 + Test 2 are startable.

Test 3 remains locked.

This release must be student-specific if the existing quiz assignment model is student-specific.

Do not globally unlock the quiz for every student unless that is explicitly how the existing assignment architecture works and is intended.

Audit this carefully.
