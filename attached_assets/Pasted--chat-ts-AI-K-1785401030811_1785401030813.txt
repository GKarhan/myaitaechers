ԽՆԴԻՐ. chat.ts-ի AI-ուսուցչի ամբողջ տրամաբանությունը վերակառուցել, որպեսզի այն
հավատարիմ լինի մեր Karhanyan AI Learning OS-ի P0-P7 սպեցերի արդյունավետ մասերին
(P4 վարքային կանոններ, P5 մանկավարժական որոշում, P7 հաջորդ քայլի ձևակերպում,
P6 դասի ավարտ), բայց cost-ի պատճառով P4/P5/P7-ը միացնել ՄԵԿ model-կանչի մեջ per-turn
(ոչ թե 3 առանձին կանչ), իսկ P6-ը մնա առանձին կանչ, բայց միայն դասի ավարտին
(մեկ դասում մեկ անգամ)։ P0-ի ողջ տրամաբանությունը (routing, session state, node
queue) իրականացվում է ՄԱՔՈՒՐ ԿՈԴՈՎ, ոչ model-կանչով։

3.1. ՆՈՐ single structured-output model-կանչ (P4+P5+P7 միասին, մեկ կանչով)

Փոխարինիր rawAiResponse-ի string-parsing մոտեցումը (###EVAL:### tag) մեկ
JSON-output կանչով, որ callAI-ից պահանջում ես (function calling կամ
response_format json_schema, եթե OpenRouter/DeepSeek-ը թույլ է տալիս, հակառակ
դեպքում խիստ պահանջիր JSON-only output prompt-ում).

{
  "student_message": string,           // սա է P7-ի ելքը, ցուցադրվում է ուսանողին
  "progress_indicator": {
    "current_node_name": string,
    "step": number,
    "total_steps": number,             // = node-երի քանակը այս դասում
    "completed_nodes": number,
    "total_nodes": number
  },
  "teaching_mode": "TEACH" | "MICRO_CHECK" | "FEEDBACK" | "TRANSITION",
  "is_micro_check": boolean,
  "answer_evaluation": {               // սա է P5-ի decision-ը, ՄԻԱՅՆ եթե ուսանողը հենց նոր պատասխանել է
    "status": "CORRECT" | "PARTIALLY_CORRECT" | "INCORRECT" | "UNCLEAR" | "NO_RESPONSE" | "NOT_APPLICABLE",
    "evidence_quality": "NONE" | "WEAK" | "MODERATE" | "STRONG",
    "error_family": string | null
  },
  "node_decision": {
    "action": "CONTINUE_SAME_NODE" | "COMPLETE_NODE" | "REPAIR",
    "reason": string
  },
  "source_fidelity": {
    "type": "SOURCE_EXACT" | "SOURCE_PARAPHRASED" | "AI_ADAPTED" | "AI_GENERATED",
    "exercise_id": string | null
  }
}

Prompt-ի մեջ, ինչպես նախկինում, մուտքագրիր ՆԵՐԿԱ node-ի childFriendlyExplanation/
basicExamples/commonMisconception-ը, ԲԱՅՑ ՀԻՄԱ ՆԱԵՎ.
  - Այս node-ին կապված lessonExercisesTable-ի տողերը (exerciseTextVerbatim-ը,
    եթե կա) — հստակ ասա մոդելին. "եթե exerciseTextVerbatim-ը լցված է,
    օգտագործիր ԲԱՌ ԱՌ ԲԱՌ, մի փոփոխես ոչ մի թիվ, ավելացրու (Էջ X, վարժ. Y)"
  - TEACH → MICRO_CHECK ցիկլի հստակ հրահանգ (P4 §11). ամեն նոր տեսության
    հատվածից անմիջապես հետո՝ 1-2 հարց, ≤25 բառ, նախքան հաջորդ tas/exercise-ին անցնելը
  - Progress Indicator-ի հաշվարկման տվյալները (քանի node է ընդհանուր
    այս դասում, քանիսն են completed_node_ids-ում)
  - MICRO_CHECK-ի հատուկ գնահատման կանոն (P5 §17.13). CORRECT → evidence_quality
    = MODERATE (ոչ STRONG), երբեք մի առաջարկիր node_decision.action =
    COMPLETE_NODE միայն մեկ MICRO_CHECK-ի հիման վրա. դրա համար պետք է առնվազն
    մեկ STRONG-mastery practicalTask/exercise լուծված լինի

3.2. ՆՈՐ. node-ի ինքնաշխարժ առաջընթաց (կոդով, ոչ model-կանչով — սա P0-ի դերն է)

Ուսանողի պատասխանից հետո, callAI-ի structured output-ը ստանալուց հետո.

  a) Թարմացրու lessonNodesTable-ի/lessonSessionsTable-ի tracking դաշտերը՝
     ըստ answer_evaluation.status-ի (consecutiveCorrect++, կամ reset to 0,
     masteryEvidenceCount++ եթե evidence_quality != NONE)

  b) Ստուգիր model-ի node_decision.action-ը ԵՎ անկախ դրանից, կոդով ստուգիր
     հետևյալ pragmatic gate (սա P6-ի Core Node Outcome կանոնի պարզեցումն է).
       նվազագույնը 2 STRONG-quality evidence այս node-ի վրա (ոչ միայն MICRO_CHECK)
       ԵՎ consecutiveIncorrect < 2 վերջին փորձերում
     → եթե բավարարված է, կանչիր (ներքին ֆունկցիա, ոչ HTTP endpoint) այն նույն
       տրամաբանությունը, ինչ հիմա lessons.ts routes.ts-ի /advance-node-ն ունի.
       currentNodeId = հաջորդ sequence-ով node, կամ null եթե վերջինն էր
     → resetացրու nodeAttemptCount, consecutiveCorrect/Incorrect, masteryEvidenceCount

  c) ԱՆՎՏԱՆԳՈՒԹՅԱՆ CAP. եթե nodeAttemptCount > 6 այս node-ի վրա և դեռ
     չենք հասել shrïktun-ին, ինքնաշխարժ advance արա node-ը REVIEW_NEEDED
     նշումով (փոխարեն anվերջ կպչելու)՝ սա ուղղակի կիրառում է P6-ի
     "REVIEW_NEEDED" outcome-ը, առանց ամբողջ P6 կանչի սպասելու

  d) Երբ currentNodeId → null (բոլոր node-երն սպառված են), ավտոմատ
     փոխանցիր session-ը «ready for macro-phase-advance» վիճակի (ոչ մի
     UI-ից կախված բան), որ գործող advance-phase-ի gate-ը հիմա հաստատ անցնի
