SYSTEMIC ARCHITECTURE CHANGE — NOT A LESSON-SPECIFIC PATCH

Fundamentally fix the C2 Cognitive Path architecture so that the AI/provider is no longer responsible for deciding the cognitive route structure.

1. resolved target cognitive level,
2. required prerequisite cognitive levels,
3. minimal ordered progression route,
4. which lower levels are omitted,
5. exact final target level,
6. route ordering.

The provider must ONLY generate pedagogical content inside the deterministic route selected by the backend.

This is a systemic C2 architecture change.

DO NOT special-case Mathematics, Physics, Armenian, or any subject.
DO NOT weaken validators to make current provider output pass.
DO NOT modify C1, Mapping Core, M3-1/M3-2, lesson mapping, AI Teacher/chat, quizzes, Knowledge Tree, or unrelated UI.

────────────────────────────────────────────
4. DO NOT USE A MECHANICAL BLOOM LADDER
────────────────────────────────────────────

This is CRITICAL.

The deterministic planner must NOT simply generate:

remember
→ understand
→ apply
→ analyze
→ evaluate
→ create

up to the target.

That would reproduce the exact architecture problem deterministically.

The planner must construct the MINIMAL JUSTIFIED ROUTE.

Example:

target = analyze

does NOT automatically imply:

remember → understand → apply → analyze

It may legitimately be:

analyze

or:

apply → analyze

or another bounded route ONLY when the lower competency is actually required.

Every included lower level must have deterministic justification.

Every omitted lower level must be safe to omit according to the existing target/prerequisite evidence model.

────────────────────────────────────────────
5. PREREQUISITE DECISION RULE
────────────────────────────────────────────

Before adding any lower cognitive level, the planner must answer:

“Is competence at this lower level independently necessary for the learner to demonstrate the target capability?”

NOT:

“Does this level come before the target in Bloom taxonomy?”

Taxonomic order alone is NOT sufficient justification.

Use the strongest deterministic signals already available in the current C2 architecture.

Examples may include existing:

- target-demand analysis,
- source relationship evidence,
- objective/performance demand,
- canonical outcome relationships,
- prerequisite/dependency metadata,
- existing readiness logic,
- current deterministic progression evidence.

Do not invent semantic relationships unsupported by current canonical data.

If the system cannot deterministically justify a prerequisite level, do not silently invent it.

Prefer:

minimal route + review signal

over:

speculative expanded route.

────────────────────────────────────────────
6. TARGET LEVEL MUST BE EXACTLY FINAL
────────────────────────────────────────────

The resolved target cognitive level must appear:

- exactly once,
- as the final route level.

The deterministic planner must prevent:

- duplicate target levels,
- levels above target,
- levels after target,
- provider-added levels,
- provider-removed required levels,
- provider-reordered levels.

These become structural invariants.
