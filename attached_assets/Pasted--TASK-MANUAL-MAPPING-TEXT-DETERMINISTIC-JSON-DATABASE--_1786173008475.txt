# ՊԱՐՏԱԴԻՐ TASK — MANUAL MAPPING TEXT → DETERMINISTIC JSON → DATABASE

Դու աշխատում ես արդեն գոյություն ունեցող կրթական հարթակի վրա։

Հարթակում կա դասագրքերի քարտեզագրման համակարգ՝

* 🗺️ Ավտոմատ քարտեզագրում
* ✍️ Ձեռքով քարտեզագրում

Այս task-ի նպատակն է **փոխել միայն ✍️ Ձեռքով քարտեզագրման ներմուծման մեխանիզմը**։

## ԳԼԽԱՎՈՐ ԳԱՂԱՓԱՐԸ

Ուսուցիչը ցանկացած AI chat-ում օգտագործում է մեր առանձին հաստատված KNOWLEDGE BASE MAPPER prompt-ը։

AI chat-ը դասագրքի էջերից ստեղծում է **ստանդարտ TEXT քարտեզագրում**։

Ուսուցիչը այդ TEXT-ը copy-paste է անում այս հարթակի.

**✍️ Ձեռքով քարտեզագրում**

դաշտում։

Հարթակը պետք է այդ TEXT-ը վերածի գործող համակարգի JSON/object structure-ի և պահի database-ում։

Վերջնական flow-ը պետք է լինի.

```text
AI CHAT
   ↓
STANDARD MAPPING TEXT
   ↓
✍️ MANUAL MAPPING INPUT
   ↓
DETERMINISTIC CODE PARSER
   ↓
DETERMINISTIC VALIDATOR
   ↓
STRUCTURED OBJECT / JSON
   ↓
PREVIEW
   ↓
TEACHER CONFIRMATION
   ↓
DATABASE TRANSACTION
   ↓
KNOWLEDGE BASE
   ↓
AI TEACHER
```

## ՇԱՏ ԿԱՐԵՎՈՐ

Այս flow-ի ընթացքում **ՈՉ ՄԻ AI ՉՊԵՏՔ Է ՄԱՍՆԱԿՑԻ**։

Parser-ը և Validator-ը պետք է լինեն 100% deterministic code։

Չօգտագործել.

* OpenAI
* OpenRouter
* callAI
* callAIStructured
* LLM
* AI parsing
* AI correction
* AI validation
* AI-generated fallback
* որևէ արտաքին AI API

Նույն input TEXT-ը պետք է ամեն անգամ տա նույն structured output-ը։

# ՄԱՍ 3 — MANUAL MAPPING INPUT

Գործող manual mapping modal-ը պետք է ընդունի plain TEXT mapping։

Ուսուցիչը պետք է կարողանա copy-paste անել երկար քարտեզագրում։

Չպետք է պահանջվի, որ ուսուցիչը ձեռքով JSON գրի։

Input-ը plain text է։

Օրինակային կառուցվածքը կարող է լինել.

```text

Դասագիրք: Հայոց Լեզու 7
Հեղինակ: Փ. Մեյթիխանյան
Դասարան: 7
Առարկա: Հայոց լեզու
Թեմա: Ձևաբանություն
Դասի վերնագիր: Գոյական անուն
Բաժին / §: §1.1
Էջեր: 22–24

NODE 1
Վերնագիր: Գոյական անվան ներածություն
```

### ՇԱՏ ԿԱՐԵՎՈՐ

Վերևի օրինակը միայն structural example է։

Parser-ը չպետք է սահմանափակվի այդ կոնկրետ դասով։

Այն պետք է աշխատի մեր հաստատված ընդհանուր mapping TEXT FORMAT-ի համար։

# ՄԱՍ 4 — ՍՏԵՂԾԵԼ ՄԵԿ ՊԱՇՏՈՆԱԿԱՆ TEXT FORMAT

Parser-ի համար սահմանիր **մեկ canonical TEXT FORMAT**։

Format-ը պետք է ունենա հստակ section markers և field names։

Օրինակ.

```text

Դասագիրք: ...
Հեղինակ: ...
Դասարան: ...
Առարկա: ...
Թեմա: ...
Դասի վերնագիր: ...
Բաժին / §: ...
Էջեր: ...

NODE N1
Վերնագիր: ...

MICRONODE MN-1.1
Վերնագիր: ...
Տեսակ: ...
Նպատակ: ...
Աղբյուրներ: ...
Վարժություններ: ...
Նախապայմաններ: ...
Կապեր: ...
Վստահություն: ...
Կարգավիճակ: ...

SOURCE BLOCK B1
Տեսակ: ...
Կարգավիճակ: ...
Էջ: ...
Պարբերություն: ...
Դիրք: ...

EXERCISE EX-1

Պատճառ: ...

```

### ՊԱՐՏԱԴԻՐ

Canonical format-ը պետք է լինի deterministic և machine-parseable։

Չօգտագործել fuzzy natural-language parsing։

Չփորձել «հասկանալ» ինչ է նկատի ունեցել ուսուցիչը։

Եթե format-ը սխալ է՝ ցույց տալ error։

# ՄԱՍ 5 — PARSER

Ստեղծիր առանձին deterministic parser։

Օրինակ.

```text
mapTextParser.ts
```

կամ repository-ի architecture-ին համապատասխան անվանում։

Parser-ի հիմնական API-ն պետք է մոտավորապես լինի.

```ts
parseMappingText(text: string): ParsedMappingResult
```

Parser-ը պետք է կատարի միայն syntax parsing։

Այն պետք է վերածի TEXT-ը structured object-ի։

Parser-ը չպետք է.

* լրացնի բաց թողնված տվյալներ
* գուշակի
* վերաձևակերպի բովանդակությունը
* ստեղծի նոր MicroNode
* ստեղծի նոր exercise
* ստեղծի source block
* փոխի sourceQuote
* փոխի textbook text-ը
* օգտագործի AI

# ՄԱՍ 14 — DATABASE TRANSACTION

Միայն validation success-ից և teacher confirmation-ից հետո։

Database write-ը կատարել transaction-ով։

Եթե transaction-ի ընթացքում որևէ insert/update ձախողվեց՝ rollback։

Չպետք է ստացվի.

```text
Lesson inserted
Node 1 inserted
Node 2 inserted
Exercise 1 failed
```

և մնա կիսատ data։

Կամ ամբողջ mapping-ը մտնում է, կամ ոչինչ չի մտնում։

# ՄԱՍ 21 — SECURITY

Pasted text-ը երբեք չուղարկել external API։

Parser-ը պետք է աշխատի server-side deterministic code-ով։

Validate արա input length-ը, որպեսզի չափազանց մեծ payload-ները չխափանեն server-ը։

Օգտագործիր existing authentication/authorization middleware-ը։

Teacher-ը պետք է կարողանա import անել միայն այն lesson-ը, որի նկատմամբ ունի համապատասխան permission։

# ՄԱՍ 24 — ԱՐԴՅՈՒՆՔԸ ՊԵՏՔ Է ՀԱՄԱՏԵՂԵԼ ԳՈՐԾՈՂ MAPPING MODEL-Ի ՀԵՏ

Ամենակարևոր պահանջներից մեկը.

**TEXT mapping-ը և platform-ում ձեռքով ստեղծվող mapping-ը պետք է ունենան նույն վերջնական բովանդակային structure-ը։**

Այսինքն՝

```text
AI-generated mapping TEXT
        ↓
deterministic parser
        ↓
same structured mapping
        ↓
same DB tables
        ↓
same Knowledge Base
```

Չպետք է լինի.

```text
Auto Mapping → մեկ schema
Manual Mapping → ուրիշ schema
```

Manual Text Import-ը պետք է օգտագործի նույն վերջնական mapping model-ը, որը օգտագործում է platform-ի մնացած համակարգը։
