1. INVENTORY CURRENT PHASE-2 INVARIANTS
==================================================

Create a concise source-of-truth test contract for the following CURRENT invariants.

Do not change their behavior.

Required invariants:

1. No active MICRO_CHECK without a visible answerable task.

2. Feedback-only response:
   teaching_mode = FEEDBACK
   is_micro_check = false
   must NOT activate a MICRO_CHECK.

3. Phase 2 THEORY uses the server-owned envelope:
   final teaching_mode = TEACH
   final is_micro_check = true
   but only valid learner-answerable content may activate a task.

4. Failed structured generation must fail closed:
   - no phantom task
   - no phantom evidence
   - no progression mutation
   - no plain-text fallback for controlled Phase-2 teaching.

5. Exact source-exercise identity:
   selected/delivered source exercise
   === persisted activeLessonExerciseId.

6. Source-exercise delivery is single-owner:
   no duplicate P11.1 + V2-R1.1 visible delivery.

7. Typed source exercise deterministic scoring:
   multiple_choice / true_false
   correctness is backend-owned.

8. AI-generated objective MICRO_CHECK deterministic scoring:
   activeObjectiveTaskPayload is authoritative.

9. Source and generated objective task authorities stay separate.

10. Cognitive Path progression owns:
    - current cognitive level
    - ADVANCE_COGNITIVE_LEVEL
    - target-ceiling completion.

11. A Cognitive Path node cannot complete merely because legacy
    stageBecomesVerified became true.

12. Phase 2 → Phase 3 only occurs after legitimate MicroNode completion.

13. Evidence thresholds remain authoritative.

14. Time/budget exhaustion is not learner failure.

15. Source exercise answer keys are never exposed to student-facing APIs.

16. Source verbatim exercise text remains protected.

17. Fresh/relearn reset behavior remains exactly as currently implemented:
    session-local state resets;
    durable learning evidence/mastery remains preserved.

18. Frontend remains a thin client:
    it sends message + lessonId;
    backend/session state remains authoritative.
