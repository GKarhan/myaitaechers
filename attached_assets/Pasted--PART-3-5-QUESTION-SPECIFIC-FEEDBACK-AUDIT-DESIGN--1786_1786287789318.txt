# PART 3.5 — QUESTION-SPECIFIC FEEDBACK AUDIT & DESIGN

## Նպատակ

Մենք ուզում ենք, որ ավարտված թեստից հետո սովորողը **յուրաքանչյուր հարցի համար** տեսնի ոչ միայն՝ իր պատասխանը ճիշտ է, թե սխալ, այլ նաև՝

### Եթե պատասխանը ճիշտ է

**Ինչու՞ է ճիշտ։**

Կարճ, հստակ, երեխային հասկանալի բացատրություն, որը վերաբերում է հենց այդ կոնկրետ հարցին և ճիշտ պատասխանին։

### Եթե պատասխանը սխալ է

**Ինչու՞ է քո պատասխանը սխալ։**

Բացատրել՝ ինչն է սխալ սովորողի ընտրած կոնկրետ տարբերակում։

**Ինչու՞ է ճիշտ պատասխանը ճիշտ։**

Բացատրել՝ ինչ կանոնի, փաստի կամ տրամաբանության պատճառով է ճիշտ տարբերակը ճիշտ։

---

# ABSOLUTE RULE

Այս փուլում **ոչ մի code/schema/UI/database փոփոխություն չանել**։

Մի արա migration։

Մի ավելացրու column։

Մի փոխիր prompt։

Մի փոխիր API։

Մի փոխիր frontend։

Մի փոխիր quiz generation-ը։

Մի փոխիր existing feedback logic-ը։

Մի փոխիր Knowledge Tree-ը։

Միայն **audit + architecture/design report**։

Վերջում կանգ առ և սպասիր հաստատման։

---

# 1. Audit-ի սահմանները

Ուսումնասիրիր ամբողջ chain-ը, որը կապված է question-specific feedback-ի հետ.

```text
Quiz generation
↓
quiz_questions
↓
question text
↓
options
↓
correct_option_index
↓
student selected_option_index
↓
quiz_answers
↓
quiz result API
↓
quiz-result.tsx
```

Ու պարզիր՝ ներկայում որտեղ կարող է պահպանվել կամ ստեղծվել տվյալ հարցի բացատրությունը։

---

# 2. Ներկայիս տվյալների audit

Ստուգիր `quiz_questions` schema-ն։

Պարզիր՝ ներկայում կա՞ն.

* question text
* options
* correct option
* explanation
* correct answer explanation
* wrong answer explanation
* option-specific explanation
* misconception
* learning objective
* source/reference
* node_id

Յուրաքանչյուրի համար գրիր.

```text
Field
Current existence
Where stored
Question-specific?
Can explain why correct?
Can explain why wrong?
```

---

# 3. Ամենակարևոր տարբերությունը

Պարզիր՝ ներկայիս համակարգը կարո՞ղ է տարբերել.

```text
Question A
Node = X

Question B
Node = X
```

և տալ տարբեր բացատրություններ։

Օրինակ.

```text
Node X
 ├── Question 1
 ├── Question 2
 ├── Question 3
```

Եթե բոլոր երեք հարցերը օգտագործում են նույն

```text
lesson_nodes.child_friendly_explanation
lesson_nodes.common_misconception
```

ապա պարզիր՝ արդյոք դա հանգեցնում է նույն բացատրության օգտագործմանը տարբեր հարցերի համար։

---

# 4. Option-specific feedback

Սա պարտադիր audit է։

Պարզիր՝ համակարգը կարող է պահպանել յուրաքանչյուր տարբերակի համար առանձին բացատրություն, օրինակ.

```text
Question:
Ո՞րն է ճիշտ տարբերակը։

A → սխալ է, որովհետև ...
B → ճիշտ է, որովհետև ...
C → սխալ է, որովհետև ...
D → սխալ է, որովհետև ...
```

Ստուգիր՝ ներկայիս schema-ում կա՞ նման հնարավորություն։

Եթե չկա՝ գրիր հստակ.

```text
OPTION-SPECIFIC FEEDBACK = NOT CURRENTLY STORED
```

---

# 5. Ինչ պետք է տեսնի սովորողը

Սահմանիր վերջնական desired data contract-ը։

Յուրաքանչյուր question result-ի համար մեզ պետք է տրամաբանորեն ստացվի.

```text
question
options
correctAnswer
studentAnswer
isCorrect

feedback:
  whyCorrect
  whyWrong
```

Բայց եթե անհրաժեշտ է ավելի ճշգրիտ architecture, առաջարկիր նաև.

```text
optionFeedback:
  A: ...
  B: ...
  C: ...
  D: ...
```

և բացատրիր՝ որն է ավելի ճիշտ մեր համակարգի համար։

---

# 6. Correct answer feedback

Ստուգիր՝ ինչպես պետք է աշխատի ճիշտ պատասխանի դեպքում։

Օրինակ.

```text
Student answer = B
Correct answer = B
```

Պետք է վերադարձվի.

```text
whyCorrect = "..."
```

իսկ

```text
whyWrong = null
```

UI-ում չպետք է երևա «ինչու է սխալ» հատվածը։

---

# 7. Wrong answer feedback

Ստուգիր՝ ինչպես պետք է աշխատի սխալ պատասխանի դեպքում։

Օրինակ.

```text
Student answer = A
Correct answer = C
```

Պետք է հնարավոր լինի ստանալ.

```text
whyWrong:
Ինչու է A-ն սխալ։

whyCorrect:
Ինչու է C-ն ճիշտ։
```

Այս երկու բացատրությունները պետք է լինեն **կոնկրետ այդ հարցի և այդ ընտրության մասին**։

---

# 8. Same Node / Different Questions

Սա critical test է։

Վերցրու նույն Node-ին պատկանող առնվազն 3 իրական հարց։

Օրինակ.

```text
Node X

Question 1
Question 2
Question 3
```

Պարզիր՝ ներկայիս architecture-ը թույլ տալի՞ս է ունենալ.

```text
Question 1 → Explanation 1
Question 2 → Explanation 2
Question 3 → Explanation 3
```

թե բոլորի համար օգտագործվում է նույն Node-level explanation-ը։

Եթե երկրորդն է՝ նշիր որպես schema/data-model limitation։

---

# 9. Wrong option specificity

Պարզիր՝ կարելի՞ է տարբերել սխալ տարբերակները։

Օրինակ.

```text
Question:
Ո՞րն է ճիշտ։

Student A → ընտրել է B
Student B → ընտրել է C
Student C → ընտրել է D
```

Կարո՞ղ է համակարգը յուրաքանչյուրին տալ.

```text
B → ինչու B-ն սխալ է
C → ինչու C-ն սխալ է
D → ինչու D-ն սխալ է
```

թե բոլորին կտա նույն ընդհանուր.

> «Ճիշտ պատասխանը A-ն է»։

Եթե երկրորդն է՝ դա գրիր որպես կարևոր սահմանափակում։

---

# 10. AI generation audit

Գտիր quiz generation-ի իրական code-ը։

Պարզիր՝ AI-ն quiz question ստեղծելիս ներկայում ստանում է բավարար context, որպեսզի ստեղծի.

```text
question
options
correct answer
why correct
why each wrong option is wrong
```

թե ներկայում generation prompt/schema-ն վերադարձնում է միայն.

```text
question
options
correct_option_index
difficulty
node_id
```

Տուր կոնկրետ code locations։

---

# 11. Source fidelity

Սա շատ կարևոր է։

Բացատրությունը չպետք է լինի AI-ի ազատ հորինած ընդհանուր բացատրություն։

Պարզիր՝ ինչպես կարող ենք ապահովել.

```text
Question
↓
Source Node / MicroNode
↓
Theory / learning objective
↓
Explanation
```

և բացատրությունը համապատասխանի դասագրքի/Knowledge Base-ի բովանդակությանը։

Պարզիր՝ ներկայիս համակարգում կա՞ բավարար source context։

---

# 12. Hallucination / fabrication protection

Պարզիր՝ ինչ է տեղի ունենում, եթե AI-ն վստահելի բացատրություն չունի։

Desired behavior:

```text
Reliable explanation exists
→ show explanation

No reliable explanation
→ do NOT invent
→ return null
```

Ստուգիր՝ ներկայիս համակարգը սա ապահովո՞ւմ է։

---

# 13. Existing implementation audit

Քանի որ PART 2-ում արդեն իրականացվել է.

```text
feedback:
  whyCorrect
  whyWrong
```

ստուգիր ներկայիս implementation-ը։

Պարզիր.

1. Որտեղ է կառուցվում `feedback` object-ը։
2. Որտեղից է վերցվում `whyCorrect`։
3. Որտեղից է վերցվում `whyWrong`։
4. Արդյոք դրանք question-specific են։
5. Արդյոք դրանք option-specific են։
6. Արդյոք null fallback-ը ճիշտ է աշխատում։
7. Արդյոք teacher result-ը նույն feedback-ն է ստանում։

# 14. Real Quiz Verification

Օգտագործիր առնվազն մեկ իրական ավարտված quiz։

Ցույց տուր առնվազն.

### Case A — Correct

```text
Question ID
Student answer
Correct answer
Current feedback source
whyCorrect
whyWrong
```

### Case B — Wrong

```text
Question ID
Student answer
Correct answer
Current feedback source
whyCorrect
whyWrong
```

### Case C — Same Node / Different Questions

Առնվազն 2–3 հարց նույն Node-ից։

Պարզիր՝ բացատրությունները տարբերակելի՞ են։

### Case D — Different wrong options

Եթե տվյալներում կա հնարավորություն, ցույց տուր երկու տարբեր սխալ ընտրություններ և դրանց feedback-ը։

# 15. Desired Architecture

Առաջարկիր՝ մեր համակարգի համար որն է լավագույն model-ը։

Համեմատիր առնվազն.

### Model A

```text
quiz_questions.explanation
```

մեկ ընդհանուր բացատրություն հարցի համար։

### Model B

```text
quiz_questions.why_correct
quiz_questions.why_wrong
```

### Model C

```text
quiz_questions.option_explanations[]
```

որտեղ յուրաքանչյուր option ունի իր բացատրությունը։

### Model D

Hybrid

```text
question explanation
+
option-specific explanations
```

Գնահատիր ըստ.

* accuracy
* personalization
* storage
* generation complexity
* teacher editing
* future analytics
* maintainability

Եվ ընտրիր՝ **որ model-ն է լավագույնը մեր համակարգի համար և ինչու**։
