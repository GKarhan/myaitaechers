2. CANONICAL COGNITIVE MODEL
============================================================

Use revised Bloom cognitive levels:

remember
understand
apply
analyze
evaluate
create

But DO NOT assume every MicroNode needs all six levels.

Each MicroNode must have its own applicable cognitive path.

Examples:

Definition-type MicroNode:
remember → understand

Procedural MicroNode:
remember → understand → apply

Concept requiring comparison/analysis:
remember → understand → apply → analyze

Higher-order task:
understand → apply → analyze → evaluate

Creation-oriented MicroNode:
understand → apply → analyze → evaluate → create

Therefore:

applicable cognitive path ≠ always six levels.

The system must support a variable path per MicroNode.

One level in that path is the curriculum TARGET CEILING.

Example:

MicroNode: Մոլեկուլներ

Applicable path:
remember → understand → apply

Target ceiling:
apply

4. TARGET CEILING CONTRACT
============================================================

Exactly one applicable cognitive level SHOULD normally be the target ceiling for an enriched MicroNode.

The target ceiling means:

"The highest cognitive demand that the curriculum expects the learner to demonstrate for this MicroNode."

It does NOT mean:

- current learner ability
- mastery percentage
- confidence
- task difficulty

For backward compatibility:

lesson_nodes.target_bloom_level currently exists.

DO NOT delete or rename it in this task.

Define and document a compatibility strategy between:

lesson_nodes.target_bloom_level

and

lesson_node_cognitive_levels.is_target_ceiling

The NEW child-table structure is to become canonical for Phase 2A.

Do not silently create conflicting sources of truth.

Report exactly how synchronization/backward compatibility will work.

5. PERFORMANCE OBJECTIVE PER LEVEL
============================================================

Each applicable level must support a concrete observable performance objective.

Bad:

"Understand molecules."

Good:

"Ուսանողը կարող է սեփական բառերով բացատրել, թե ինչ է մոլեկուլը և ինչ կապ ունի այն նյութի հատկությունների հետ։"

The objective must describe what the learner can DO at that cognitive level.

Different levels must represent genuinely different cognitive demands.

Do not generate these objectives yet unless explicitly required for fixture/testing purposes.

This round builds the DATA FOUNDATION.

============================================================
6. SUCCESS CRITERION PER LEVEL
============================================================

Each applicable cognitive level must support a successCriterion.

This describes what counts as acceptable evidence at that level.

Example:

remember:
correctly identifies/recalls the concept.

understand:
correctly explains or classifies the concept in a new wording/context.

apply:
uses the concept correctly in an appropriate new case/problem.

The success criterion is curriculum/evidence design metadata.

It is NOT the learner's score.

8. SOURCE EXERCISE → AI EQUIVALENT VARIANTS
============================================================

This requirement is LOCKED for the architecture.

A textbook/source exercise may serve as a SEED TASK.

Example:

Cognitive level = Apply

Available source exercises = 1

Evidence design requires = 3 independent task opportunities

The future AI Teacher must be able to generate 2 additional equivalent variants.

Those variants must:

- assess the SAME MicroNode

9. MINIMUM INDEPENDENT EVIDENCE
============================================================

Each cognitive level must be able to define how much independent evidence is expected before that level can later be considered demonstrated.

Add/support a field such as:

minimumIndependentEvidence

Use an integer with a sensible validation rule.

This is NOT confidence.

It means:

"How many independent evidence opportunities should normally be available/required for this cognitive level?"

Example:

Apply:
minimumIndependentEvidence = 3

Available source tasks = 1

Future task-generation system can infer:

missing equivalent opportunities = 2

DO NOT implement learner demonstrated-level calculation yet.

============================================================
10. MINIMUM-EFFORT STUDENT INTERACTION
============================================================

LOCKED DESIGN PRINCIPLE:

"Minimum-effort interaction, maximum-valid evidence."

The learner should write as little as reasonably necessary,
BUT interaction convenience must never weaken the validity of evidence.

Each cognitive-level design must be able to specify preferred interaction types.

Support an extensible representation for interaction types such as:

multiple_choice
multi_select
true_false
matching
classification
ordering
numeric_answer
short_answer
constructed_response
problem_solving

Do not assume multiple-choice is always sufficient.

Examples:

Remember:
multiple_choice may be sufficient.

Understand:
classification/matching/short explanation may be required.

Apply:
learner may independently solve a problem and then:
- enter the final numeric/text answer, OR
- select the correct final answer,
provided the task design still demonstrates application.

Analyze/Evaluate/Create:
may require more constructed learner output when necessary.

The architecture should support preferredInteractionTypes per cognitive level.

Do NOT redesign the current quiz UI in this round.

============================================================
11. INDEPENDENT PROBLEM SOLVING
============================================================

The future system MUST support tasks where:

1. learner independently solves a problem;
2. system does not require unnecessary typing;
3. learner can submit evidence through:
   - final answer entry, OR
   - correct-answer selection,
   depending on task validity;
4. evidence still records that this was an independent problem-solving task.

Therefore cognitive/task architecture must distinguish:

interaction format

from

cognitive demand.

Example:

A multiple-choice response MAY still assess Apply if the learner had to independently solve a novel problem before selecting the answer.

Likewise:

a written response is NOT automatically a higher cognitive level.

Do not infer Bloom from UI format.

============================================================
12. BLOOM ≠ DIFFICULTY ≠ INTERACTION TYPE
============================================================

These are THREE separate dimensions.

A task has:

A. Cognitive demand
   remember / understand / apply / analyze / evaluate / create

B. Difficulty
   LOW / MEDIUM / HIGH
   or the repository's canonical equivalent

C. Interaction format
   multiple_choice / numeric_answer / matching / etc.

Never derive one automatically from another.

Examples:

HIGH-difficulty Remember is possible.

LOW-difficulty Apply is possible.

Multiple-choice Apply is possible.

Constructed-response Remember is possible.

Document this explicitly in code/schema comments where appropriate.
