════════════════════════════════════════════════════
3. TEACH RULE
════════════════════════════════════════════════════

When the canonical stage is TEACH:

C7 may:

- explain the current C6-selected target
- give a short example
- clarify the current concept
- prepare the learner for one check

C7 must NOT:

- mark evidence as if a learner response occurred
- complete the level
- complete the MicroNode
- jump to another target
- ask multiple checks
- skip directly to a second question/task

After appropriate teaching, the next assessment interaction must be
ONE MICRO_CHECK.

Server controls this transition.

The model may not output:

“let's move to the next topic”

and thereby change the state.

════════════════════════════════════════════════════
4. MICRO_CHECK RULE
════════════════════════════════════════════════════

MICRO_CHECK must be:

- exactly ONE check/question
- tied directly to the just-taught point
- tied to current MicroNode
- tied to current Cognitive Level
- short; target ≤25 words where practical
- not a multi-part sequence
- not followed by another question in the same response

After a MICRO_CHECK has been presented:

the session MUST remember that a learner response is expected.

The next learner response MUST be processed as the answer to that
micro-check.

The AI must not issue another micro-check before FEEDBACK.

════════════════════════════════════════════════════
5. MICRO_CHECK → FEEDBACK IS MANDATORY
════════════════════════════════════════════════════

This is the central C7.2 requirement.

After learner answers an active MICRO_CHECK:

NEXT pedagogical action MUST be FEEDBACK.

Not:

TEACH
not another MICRO_CHECK
not another exercise
not node transition
not unrelated explanation.

FEEDBACK must occur even when the learner answer is:

- correct
- incorrect
- incomplete
- uncertain
- partially correct

The server state machine must enforce this.

Do not rely only on prompt wording.

════════════════════════════════════════════════════
6. FEEDBACK RULE
════════════════════════════════════════════════════

FEEDBACK should:

- acknowledge/evaluate the learner's response
- remain tied to current target
- be concise
- expose no fake mastery claim
- prepare the deterministic next action

If wrong/incomplete:

feedback may communicate the issue and prepare remediation.

If correct:

feedback may acknowledge correctness.

BUT:

FEEDBACK itself does not authorize C3/C4/C6 progression.

C7.1 remains authoritative.

After FEEDBACK, the system enters TRANSITION decision.

════════════════════════════════════════════════════
7. TRANSITION RULE
════════════════════════════════════════════════════

TRANSITION is server-owned.

After FEEDBACK, determine the allowed next execution action from
canonical backend state.

Possible outcomes include:

A. TEACH
More explanation/remediation on SAME C6 target.

B. MICRO_CHECK
A new independent short check, only when pedagogically allowed.

C. EXERCISE
Present a real appropriate exercise when required.

D. C6 HANDOFF
Only after C7.1/C3/C4 confirms progression and C6 selects a new target.

E. REVISIT / BOUNDED STOP
If existing deterministic remediation/time policy requires it.

Do not implement the full C7.4 remediation redesign here.

Use current deterministic engine behavior where possible.

The critical C7.2 requirement:

TRANSITION must select the next stage;
the model cannot select it freely.
