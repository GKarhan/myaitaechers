==================================================
STEP 2 — DEPENDENCY SCOPE
==================================================

Dependencies should be created only where sequence is structurally defensible.

Preferred rule for v1:

Within the same lesson:

- sort MicroNodes by their real teaching sequence
- create dependency from each MicroNode to the next

BUT first inspect Topic boundaries.

Do NOT automatically create a dependency across unrelated Topics if the current mapper/topic structure makes that unsafe.

Use the smallest deterministic rule supported by the existing structure.

Preferred hierarchy:

A. If node sequence is globally meaningful for the lesson:
   sequential chain across lesson nodes is acceptable.

B. If sequence is only meaningful inside Topic:
   create dependencies only inside each Topic.

Document which one is true in the current code/schema.

Do not invent semantics.

STEP 4 — DETERMINISTIC CREATION
==================================================

Implement or verify a deterministic dependency builder.

It should accept the final persisted/approved MicroNode ordering and produce stable edges.

Required properties:

- deterministic
- idempotent
- no duplicates
- no self-edge
- valid node IDs only
- same lesson only
- stable across repeated execution
- respects actual sequence

Example:

nodes:
1 seq=1
2 seq=2
3 seq=3

output:

1 → 2
2 → 3

Running it twice must NOT produce four rows.
