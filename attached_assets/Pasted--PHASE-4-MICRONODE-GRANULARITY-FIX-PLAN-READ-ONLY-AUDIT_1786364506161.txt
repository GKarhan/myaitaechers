# 3. AUDIT — ONE CLEAR LEARNING OBJECTIVE

Ստուգիր ներկայիս MicroNode prompt-ը։

Գտիր՝ արդյոք այն արդեն ունի կանոններ նման.

* one coherent learning objective
* one action
* one concept/skill
* split when separately assessable
* merge duplicate objectives
* one procedure with multiple steps remains one node

Բայց մի բավարարվիր նրանով, որ կանոնները prompt-ում գրված են։

Պարզիր՝

> **արդյոք այդ կանոնները իրականում enforce են արվում։**

Տարբերակիր.

```text
PROMPT RULE
vs
SERVER ENFORCEMENT
vs
ACTUAL PRODUCTION BEHAVIOR
```

# 5. COGNITIVE OPERATION

Ստուգիր՝ ներկայիս համակարգը հաշվի առնո՞ւմ է cognitive operation-ը։

Օրինակ՝

```text
define
identify
classify
compare
explain
apply
calculate
solve
construct
analyze
```

Հատուկ ստուգիր՝ արդյոք հետևյալ կառուցվածքը պետք է flag արվի.

```text
define X AND identify X
classify X AND use X
explain X AND calculate Y
recognize X AND produce Y
memorize rule AND apply rule
```

Բայց կարևոր է.

**Մի համարիր `և` / `and` բառի առկայությունը ավտոմատ ապացույց, որ պետք է split անել։**

Օրինակ՝ մեկ procedure-ի մեջ մի քանի քայլ կարող են մնալ մեկ MicroNode։

Պետք է տարբերակել.

```text
compound grammatical sentence
```

և

```text
compound learning objective
```

# 6. OVER-SPLITTING AUDIT

Գտիր՝ ներկայիս համակարգը չափից շատ մանրացնո՞ւմ է նույն skill-ը։

```text
MicroNode A
MicroNode B
Shared objective
Why separate?
Why merge?
Final recommendation
```

# 7. EXERCISE → MICRONODE ALIGNMENT

Սա Phase 4-ի պարտադիր մաս է։

Ստուգիր՝ exercise-ը իրականում համապատասխանում է իր MicroNode-ի learningObjective-ին։

Օրինակ՝ եթե node-ի LO-ն է.

> Student can solve addition and subtraction problems.

ապա exercise-ը չպետք է պահանջի multiplication/division, եթե դա node-ի stated objective-ի մեջ չկա։

Ստուգիր.

```text
MicroNode LO
       ↓
Exercise
       ↓
Does exercise test the stated skill?
```

Առանձին նշիր.

* aligned
* prerequisite
* unrelated
* requires broader/different skill

Հատուկ ուսումնասիրիր ներկայիս `closest prerequisite` logic-ը։

Պարզիր՝ արդյոք այն թույլ է տալիս exercise-ը սխալ MicroNode-ի տակ դնել։

# 9. SECOND-PASS DESIGN

Ուսումնասիրիր՝ արդյոք լավագույն լուծումը կլինի MicroNode generation-ից հետո առանձին semantic review pass ավելացնել։

Առաջարկվող architecture-ը գնահատիր.

```text
PASS 1
  ↓
SOURCE BLOCKS
  ↓
PASS 2 — TOPIC GROUPING
  ↓
PASS 2 — MICRONODE GENERATION
  ↓
PASS 2B — MICRONODE SEMANTIC REVIEW
  ↓
SERVER STRUCTURAL VALIDATION
  ↓
SOURCE COVERAGE VALIDATION
  ↓
EXERCISE ALIGNMENT
  ↓
FINAL MAPPING
```

Երկրորդ pass-ը պետք է ստուգի ամբողջ արդեն ստեղծված MicroNode list-ը, այլ ոչ թե model-ին խնդրի իր իսկ generation-ի ընթացքում ինքն իրեն ստուգել։

Ուսումնասիրիր.

* որտեղ է լավագույն insertion point-ը,
* ինչ input պետք է տրվի,
* ինչ output schema պետք է լինի,
* արդյոք պետք է `PASS`, `REVIEW`, `SPLIT`, `MERGE` decisions,
* ինչպես պետք է պահպանվեն sourceBlockIndices-ը,
* ինչպես պետք է պահպանվեն exercises-ը,
* ինչպես պետք է փոխանցվի decision-ը final mapping report-ին։

# 10. DO NOT AUTOMATICALLY SPLIT FROM "AND"

Սա պարտադիր constraint է։

Չառաջարկես այսպիսի պարզ logic.

```ts
if (learningObjective.includes("և")) split();
```

Փոխարենը գնահատիր semantic review-ի կամ ավելի ապահով heuristic-ի տարբերակը.

```text
compound signal
      ↓
semantic review
      ↓
independent cognitive operations?
      ↓
YES → SPLIT REVIEW
NO  → KEEP
```
