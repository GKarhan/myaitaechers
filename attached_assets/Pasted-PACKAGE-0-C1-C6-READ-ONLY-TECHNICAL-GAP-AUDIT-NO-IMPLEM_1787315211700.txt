────────────────────────────────────────────────────
C1 — MAPPING CONTRACT
────────────────────────────────────────────────────

Canonical hierarchy:

Subject
→ Lesson
→ Topic
→ MicroNode

MicroNode = atomic, independently assessable knowledge unit with one
clear learning objective.

Lesson must preserve the large pedagogical picture:

Lesson Goal
→ measurable Lesson Outcomes
→ Topics
→ MicroNodes

Each curriculum-relevant MicroNode must be explicitly traceable to at
least one Lesson Outcome.

Outcome ↔ MicroNode relation must be able to express:

- REQUIRED
- SUPPORTING
- required cognitive depth

MicroNode canonical passport includes conceptually:

- title
- learningObjective
- sourceContent
- sourcePage/sourceBlock
- knowledgeBoundary
- Topic
- Outcome links
- targetCognitiveLevel
- status/approval
- order
- provenance

Each MicroNode must also support a Teaching Package sufficient for
predictable low-generation teaching:

- main explanation
- key facts/rules/formulas
- examples
- counterexamples / contrast examples where relevant
- known misconceptions
- alternative explanations
- guiding questions
- hint bank
- teaching resources
- exercises/tasks

AI Teacher should reuse approved teaching content whenever possible,
not invent the lesson at runtime.

Approved content authority must be distinguishable conceptually:

- source material
- teacher-created
- AI-generated + teacher-approved
- bounded runtime equivalent variant

Source Coverage must remain auditable.

Teacher Review must ultimately allow CRUD/reorder/review/approval across
the important mapping layers.

MAPPING CREATION CHANNELS:

All must converge to the SAME canonical mapping contract:

1. internal AI mapping
2. external AI → structured TEXT import
3. teacher manual authoring

External TEXT import target flow:

structured TEXT
→ deterministic parse
→ structural validation
→ semantic validation
→ preview
→ teacher review
→ confirm
→ transactional DB write

External temporary IDs are NOT DB IDs.

Do not make JSON the required human/external-AI interchange contract.

────────────────────────────────────────────────────
C2 — COGNITIVE PATH CONTRACT
────────────────────────────────────────────────────

Cognitive Path is NOT a list of exercises.

It represents cognitive progression for a MicroNode.

Supported conceptual levels:

Remember
→ Understand
→ Apply
→ Analyze
→ Evaluate
→ Create

A MicroNode has a curriculum Target Cognitive Level.

Target must be approved during mapping/review.
Runtime AI must NOT invent or change it.

Teacher must be able to:
- change target
- add/remove levels
- add higher enrichment levels

Distinguish:

REQUIRED/TARGET level
vs
ENRICHMENT level

For each cognitive level the system must support conceptually:

- level-specific teaching content
- performance objective
- success criterion
- Evidence Requirement Profile
- eligible task types

IMPORTANT:

Remember ≠ automatically 2 exercises.
Understand ≠ automatically 3 exercises.

Evidence Requirement is semantic, not simply a count.

It should be able to represent:

- required cognitive operation
- required independence
- success criterion coverage
- acceptable task/task-family types
- minimum evidence quality
- confirmation policy

Higher-level evidence may support lower-level requirements ONLY when
the task actually demonstrates them.

Lower-level evidence never automatically confirms a higher level.

Assisted success ≠ independent confirmation.

Remediation is bounded.

────────────────────────────────────────────────────
C3 — UNIFIED EVIDENCE CONTRACT
────────────────────────────────────────────────────

All learning/assessment systems must converge into ONE evidence model.

Evidence producers include at least current/future:

- Quiz/Test
- AI Teacher
- Quick Practice
- Flashcards when evidence-eligible
- Homework when evidence-eligible
- Human Teacher structured observation
- traditional/hybrid learning activities
- retention checks

Evidence producer ≠ mastery authority.

Canonical evidence identity must conceptually resolve to:

Learner
+ MicroNode
+ Cognitive Level
+ Task/Activity
+ Attempt
+ Source/Provenance

Canonical result statuses:

- CORRECT
- PARTIAL
- INCORRECT
- UNCLEAR
- NO_RESPONSE

UNCLEAR and NO_RESPONSE are NOT automatically "does not know".

Evidence must preserve assistance context:

- independent vs assisted
- help count
- assistance level/type
- attempt identity/history

Evidence Strength belongs to the evidence event.

Confidence does NOT.

Evidence Strength conceptually depends on components such as:

- cognitive alignment
- success-criterion coverage
- independence
- task diagnostic quality / guessability
- response evidence quality

Evidence history must be append-only/auditable.

New evidence must not overwrite historical evidence.

Task provenance should be traceable:

- SOURCE_EXERCISE
- TEACHER_CREATED
- APPROVED_GENERATED
- BOUNDED_VARIANT

Bounded variants should preserve parent/template relation.

Minimum telemetry should be captured now where technically appropriate:

- readiness
- timestamps
- response latency
- attempts
- hints/help
- assistance
- strategy
- task difficulty/context
- workload/context
- completion
- progression
- retention-check timestamps

Do NOT calculate P/L/R/K now.

We only need raw longitudinal observables preserved.

────────────────────────────────────────────────────
C4 — LEARNER MODEL CONTRACT
────────────────────────────────────────────────────

Atomic learner knowledge model:

Learner × MicroNode

Learner state is NOT one mastery percentage.

Keep conceptually separate:

- Coverage
- Target Cognitive Level
- per-level Cognitive State
- Current Demonstrated Ceiling
- 4-state MicroNode Mastery
- Confidence
- Assistance Profile
- Reconfirmation Requirement
- Unresolved Requirement
- retention context

Per-level states:

- NOT_ATTEMPTED
- IN_PROGRESS
- PARTIAL
- ASSISTED
- CONFIRMED
- RECONFIRMATION_REQUIRED

Current Demonstrated Ceiling:

highest currently CONFIRMED cognitive level.

Example:

Target = Apply
Remember = CONFIRMED
Understand = CONFIRMED
Apply = ASSISTED

Then:

Demonstrated Ceiling = Understand

and target is NOT mastered.

Canonical 4-state MicroNode mastery:

1. Գիտի
2. Մասնակի գիտի
3. Չգիտի
4. Դեռ չի ուսումնասիրել

Canonical semantics:

Գիտի
= curriculum Target Cognitive Level CONFIRMED.

Մասնակի գիտի
= meaningful lower knowledge exists but target is not confirmed.

Չգիտի
= studied/evaluated and sufficient evidence shows even the necessary
  foundational requirement is currently not confirmed.

Դեռ չի ուսումնասիրել
= insufficient learning exposure/evidence.

One incorrect answer ≠ Չգիտի.

One later incorrect answer must NOT immediately erase a previous
CONFIRMED state.

Conflicting recent evidence may lead to:

RECONFIRMATION_REQUIRED.

Confidence ≠ mastery.

Remediation budget exhaustion must preserve the real demonstrated
ceiling; never fabricate mastery.

AGGREGATION:

MicroNode remains atomic source of truth.

Topic/Outcome/Lesson do not create independent evidence.

Outcome achievement derives from REQUIRED MicroNode × required
cognitive depth.

Some integrative Outcomes may require integrated evidence.

Lesson Coverage ≠ Lesson Mastery.

Lesson Mastery should derive from required Lesson Outcomes, not a
simple average percentage.

────────────────────────────────────────────────────
C5 — KNOWLEDGE TREE CONTRACT
────────────────────────────────────────────────────

Knowledge Tree is a presentation/diagnostic projection of C4.

It must NOT own separate mastery/scoring logic.

Main hierarchy:

Subject
→ Lesson
→ Topic
→ MicroNode

Lesson Outcomes are a complementary achievement view, NOT necessarily
another hierarchy level between Lesson and Topic.

Student view should remain simple.

Teacher view should be diagnostic.

Knowledge Tree must support:

- the 4 learner states
- Lesson Outcome state
- Target vs Demonstrated Ceiling
- Topic/MicroNode drill-down
- teacher evidence drill-down
- individual learner diagnosis
- whole-class diagnosis
- Outcome-level class diagnosis
- cognitive-level gaps

Teacher must NOT directly overwrite mastery from Knowledge Tree.

Teacher observation must enter through C3 Evidence.

Knowledge Tree must produce/represent four learning queues:

Գիտի
→ Retention / Repetition queue

Մասնակի գիտի
→ Targeted Learning queue

Չգիտի
→ Foundational Learning queue

Դեռ չի ուսումնասիրել
→ New Learning queue

Queues must be dynamic based on new C4 state.

Past knowledge does not "disappear" after mastery.
Mastered knowledge enters retention/repetition lifecycle.

C5 answers:
WHERE ARE THE GAPS?

It does NOT decide the final intervention.

────────────────────────────────────────────────────
C6 — RECOMMENDATION / PERSONALIZATION CONTRACT
────────────────────────────────────────────────────

C6 answers:

WHAT SHOULD HAPPEN NEXT?

C6 must NOT calculate mastery.

Recommendation scope:

- INDIVIDUAL
- GROUP
- CLASS

Main learning directions:

Գիտի
→ Retention

Մասնակի գիտի
→ Targeted Learning

Չգիտի
→ Foundational Learning

Դեռ չի ուսումնասիրել
→ New Learning

But recommendation must also consider:

- Target Cognitive Level
- Demonstrated Ceiling
- unresolved requirement
- assistance profile
- confidence
- prerequisite state
- Outcome REQUIRED/SUPPORTING role
- evidence recency/history
- reconfirmation state

Priority:

- HIGH
- MEDIUM
- LOW
- NONE

NONE is valid:
no intervention may currently be required.

Blocking prerequisites should be handled before dependent targets.

Grouping must be based on meaningful shared learning need, not merely
the same "partial" label.

Approved-content-first policy:

1. existing approved content
2. teacher-created approved content
3. constrained generated equivalent only when needed

Bounded generation must preserve:

- MicroNode
- knowledge boundary
- cognitive level
- performance objective
- success criterion
- task intent
- approximate difficulty

System recommends.
Teacher decides/edits/postpones/rejects in teacher workflows.

Teacher decision alone does NOT change learner state.

Keep conceptually separate:

Recommendation
vs
Actual Intervention.

Future traceability must support:

Before State
→ Recommendation
→ Teacher Decision
→ Intervention
→ New Evidence
→ After State

C6 recommendation decisions should initially be deterministic/rule-based
whenever possible.

Do NOT use LLM where deterministic state/rule logic is sufficient.
