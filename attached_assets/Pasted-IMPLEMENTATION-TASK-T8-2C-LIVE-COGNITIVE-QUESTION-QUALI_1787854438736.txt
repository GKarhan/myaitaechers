==================================================
2. DETERMINISTIC VALIDATION FIRST
==================================================

Every candidate must first pass the existing T8.2B deterministic validator.

Examples of deterministic rejection include:

- malformed/empty question
- placeholder content
- invalid options
- duplicate options
- invalid correct index
- malformed explanations
- node mismatch
- cognitiveLevelId mismatch
- unsupported current delivery format
- target/format incompatibility
- duplicate/near-duplicate question

Do NOT call semantic review for a candidate that already deterministically fails unless there is a concrete architectural reason.

Preserve bounded reason codes.

==================================================
3. INDEPENDENT SEMANTIC REVIEW
==================================================

Implement ONE semantic-review service using the existing T8.2B semantic-review contract.

IMPORTANT:
This review must be logically independent from the generation request.

It evaluates the generated question against authoritative context:

- MicroNode
- canonical target Cognitive Level
- six-level operational contract
- performanceObjective
- successCriterion
- preferredInteractionTypes
- instructional/source context
- question text
- options
- correct answer
- explanation

The reviewer returns ONLY bounded structured output.

At minimum:

verdict:
PASS | FAIL | REVIEW_ERROR

reasonCodes[]

measuredCognitiveLevel

nodeAligned

objectiveAligned

criterionAligned

interactionCompatible

sourceGrounded

Do not persist free-form chain-of-thought.

Do not request or expose hidden reasoning.

A short optional diagnostic summary may be used internally if needed,
but it is not authoritative and must not be exposed to users.

==================================================
4. REVIEW AUTHORITY RULE
==================================================

The semantic reviewer may say:

Target = Apply
Measured = Remember
→ FAIL

It may NOT cause:

Apply → Remember

or:

persist question as Remember.

Likewise:

Target = Analyze
Measured = Apply
→ FAIL

Canonical target remains immutable.

The quality gate can reject the generated QUESTION.

It cannot change the mapped Cognitive Path.

==================================================
5. OPERATIONAL BLOOM CHECK
==================================================

Use the approved T8.2B six-level contract.

Examples:

REMEMBER
→ direct recall/recognition can pass.

UNDERSTAND
→ pure verbatim recall must fail.

APPLY
→ pure recall of a formula/fact must fail.
→ learner must use the rule/method in a concrete case.

ANALYZE
→ routine one-step application must fail.
→ question must require decomposition, comparison, relationship/error analysis, etc.

EVALUATE
→ analysis without justified judgment must fail.

CREATE
→ selection among completed alternatives alone must fail.
→ genuine construction/design/synthesis is required.

Do not implement keyword heuristics as the semantic authority.

==================================================
6. FAILED-SLOT-ONLY RETRY
==================================================

Do NOT regenerate the whole quiz when one question fails.

For each per-node requested batch:

1. Generate requested candidate count.
2. Validate each candidate.
3. Keep PASS questions in memory.
4. Track failed/missing slots.
5. Regenerate only the failed slot count.
6. Retry against the SAME:
   - MicroNode
   - canonical target
   - performanceObjective
   - successCriterion
   - preferred interactions
   - internal complexity requirements

Do not alter the target during retry.

==================================================
7. BOUNDED RETRY BUDGET
==================================================

Keep retry bounded.

Use the smallest safe retry budget.

Preferred:

- initial generation
- up to 2 replacement attempts per failed slot

If current architecture makes 1 retry clearly safer, explain and use it.

Do NOT retry forever.

Do NOT exceed a small bounded provider cost.

==================================================
8. RETRY INSTRUCTIONS
==================================================

When regenerating failed slots, pass only bounded failure information.

Example reason codes:

COGNITIVE_DEMAND_TOO_LOW
MICRONODE_MISALIGNED
PERFORMANCE_OBJECTIVE_MISALIGNED
SUCCESS_CRITERION_MISALIGNED
SOURCE_GROUNDING_FAILED
DUPLICATE_QUESTION
TARGET_FORMAT_MISMATCH

Do NOT feed raw reviewer reasoning back into generation.

Do NOT expose previous provider hidden reasoning.

The retry instruction should say conceptually:

"Regenerate this failed slot for the SAME canonical target.
Previous candidate failed for reason(s): X, Y."

==================================================
9. PASSING QUESTIONS MUST NOT BE REGENERATED
==================================================

This is mandatory for:

- cost
- latency
- stability
- determinism

If 4 requested questions are:

PASS
FAIL
PASS
PASS

only 1 replacement question should be generated.

The 3 passing questions remain unchanged.

==================================================
10. EXACT QUESTION COUNT
==================================================

At the end of the quality/retry cycle:

accepted valid questions for each node
must equal
requested allocated count.

If the system cannot obtain the exact count within the retry budget:

FAIL THE NORMAL QUIZ GENERATION.

Do NOT:

- persist partial quiz
- lower question count silently
- accept failed questions
- change target level
- substitute another MicroNode

==================================================
11. SEMANTIC REVIEW FAILURE
==================================================

If semantic review returns malformed output or times out:

- retry semantic review once for that candidate
- if still unavailable:
  REVIEW_ERROR
  → fail that candidate slot

Then normal failed-slot regeneration rules apply.

If the review service remains unavailable and exact valid count cannot be obtained:
fail closed.

Do not persist unreviewed questions.
