3. ADD SOURCE MATERIAL DISPOSITION CONTRACT
==================================================

Introduce an internal SourceMaterialDisposition model sufficient to distinguish at least:

- CORE_EVIDENCE
- SUPPORTING_MATERIAL
- EXERCISE
- ACTIVITY_OR_HOMEWORK
- STRUCTURAL_MATERIAL
- UNRESOLVED_VISUAL_OR_FORMULA
- UNRESOLVED_INSTRUCTIONAL_REVIEW
- EXCLUDED_WITH_REASON

Names may follow existing project conventions if there is a strong reason, but semantics must remain explicit.

A source block's blockType alone MUST NOT determine whether it becomes knowledge.

Examples:

RULE → may be core evidence.
NOTE → may be core, supporting, or unresolved.
EXAMPLE → usually supporting, but may be core if it directly introduces independently teachable knowledge.
EXERCISE → never becomes a MicroNode merely because it represents deeper cognition.
Unreadable formula/diagram fragment → unresolved material, not automatic knowledge.

4. IMPLEMENT A PURE PROMOTION DECISION
==================================================

Add a deterministic/pure promotion predicate or decision function.

It must evaluate the candidate against these conceptual requirements:

A. direct readable source support
B. meaningful knowledge identity
C. independent teachability
D. independent assessability
E. atomicity
F. non-duplication state
G. supporting-material distinction
H. source-ownership integrity

The function should NOT call AI.

It should return a structured decision rather than only boolean.

Conceptually:

PROMOTE
REVIEW_REQUIRED
SUPPORT_ONLY
UNRESOLVED
REJECT_NON_KNOWLEDGE

Use project-appropriate naming if needed.

IMPORTANT:

Do not pretend deterministic code can solve semantic questions that require later semantic review.

If atomicity/non-duplication is unresolved, return REVIEW_REQUIRED rather than guessing.

Do NOT change current production coverage persistence yet.

Phase 1 only defines/tests this contract.

==================================================
6. IMPORTANT SEMANTIC RULES
==================================================

Encode/test these rules:

1. Source Block != Knowledge Candidate.
2. Knowledge Candidate != MicroNode until promotion.
3. Topic identity does not define knowledge identity.
4. Cognitive level does not define MicroNode identity.
5. Example/NOTE/visual material does not automatically become a node.
6. Exercises do not create nodes.
7. Same knowledge used at Remember/Understand/Apply remains one candidate/MicroNode.
8. Weak/unreadable source must not be silently discarded.
9. Weak/unreadable source must not automatically become trusted knowledge.
10. Review uncertainty must remain explicit.

7. FOCUSED REGRESSION TEST MATRIX
==================================================

Add focused tests for at least:

A. Clean definition/rule
→ PROMOTE candidate.

B. Definition + explanation + example
→ one candidate;
definition/explanation core as appropriate;
example supporting;
not three nodes.

C. NOTE introduces a genuinely new readable rule
→ may qualify for promotion.

D. NOTE only clarifies an existing rule
→ SUPPORT_ONLY;
no independent node.

E. Unreadable formula/diagram fragment
→ UNRESOLVED;
never automatic promotion.

F. Same knowledge appears under two provisional Topics
→ Topic difference alone must NOT establish distinct knowledge identity.
The contract must allow later lesson-wide consolidation.

G. Similar wording but independently assessable knowledge
→ contract must permit distinct candidates.

H. One source paragraph directly supports two independently assessable rules
→ contract must permit two atomic candidates if source support is valid.

I. Remember / Understand / Apply representations of same knowledge
→ one knowledge identity;
cognitive depth does not create three candidates.

J. Exercise uses several concepts
→ exercise does not create a new candidate.

K. Supporting-only material
→ preserved disposition;
no automatic node.

L. Uncertain semantic duplicate/atomicity decision
→ REVIEW_REQUIRED;
do not guess PROMOTE or MERGE.
