TASK — BUILD A SIMPLE VISUAL MANUAL MAPPING EDITOR

GOAL

Create a reliable manual fallback for lesson mapping.

The teacher must be able to build the SAME canonical lesson map manually
that Automatic Mapping normally creates.

This is NOT a new mapping engine.

This is NOT a new schema.

This is NOT an AI/manual-text parser.

It is a visual CRUD editor over the EXISTING canonical lesson mapping data.

IMPORTANT:
Keep the existing Automatic Mapping flow unchanged.

The teacher must have two independent choices:

🗺️ Ավտոմատ
✍️ Ձեռքով

If Automatic Mapping fails, Manual Mapping must still allow the teacher
to create the lesson map and continue the workflow.

==================================================
0. WORK STYLE — IMPORTANT
==================================================

Keep this task focused and inexpensive.

Do NOT perform a broad architecture audit.
Do NOT enter a long redesign/review cycle.
Do NOT redesign the mapping pipeline.
Do NOT modify Automatic Mapping.
Do NOT modify Quiz.
Do NOT modify Knowledge Tree.
Do NOT modify AI Teacher runtime.
Do NOT redesign Goal/Outcome workflow.
Do NOT add a new parallel curriculum schema.

First inspect only the existing fields, enums, CRUD routes, and UI components
already used by the current mapped-lesson editor.

Reuse them wherever possible.

Prefer the smallest implementation that exposes existing canonical fields
through a teacher-friendly visual form.

Do NOT add a DB migration unless an existing required canonical field
literally cannot be persisted without one.

==================================================
1. CURRENT MANUAL MAPPING UI
==================================================

Currently clicking:

✍️ Ձեռքով

opens a modal with a large TEXT input / manual mapping contract import.

That is NOT the primary teacher-facing manual workflow we want anymore.

Replace the normal teacher-facing manual mapping action with a visual editor.

Do not delete legacy parsing/backend functionality if other code depends on it.
Simply stop using the large TEXT-contract input as the normal teacher workflow.

==================================================
2. GOAL / OUTCOMES
==================================================

Goal and Outcomes remain in the existing:

🎯 Նպատակ և վերջնարդյունքներ

section.

Do NOT duplicate Goal/Outcome editing inside the new Manual Mapping editor.

Expected flow:

1. Teacher creates/imports Goal + Outcomes using the existing workflow.
2. Teacher can edit them using the existing editor.
3. Teacher chooses:

   🗺️ Ավտոմատ
   OR
   ✍️ Ձեռքով

Manual Mapping must NOT require another Goal/Outcome approval gate.

If Goal/Outcomes already exist, use the current canonical records.

==================================================
5. EDIT EXISTING DATA TOO
==================================================

The Manual Mapping editor is not only for empty lessons.

If canonical Topics / MicroNodes / exercises already exist,
opening ✍️ Ձեռքով must load them into the editor.

Teacher must be able to:

- add
- edit
- delete
- reorder

using the existing canonical records.

Therefore Manual Mapping can also be used to repair an imperfect
Automatic Mapping result.

Do NOT automatically delete or replace an existing map when opening
Manual Mapping.

==================================================

Inside each Topic allow:

IMPORTANT:

==================================================
8. FIELD CONTROL RULE
==================================================

This rule applies throughout the Manual Editor:

IF the existing system has a fixed set of allowed values:
→ show a selector.

IF the field contains authored instructional content:
→ show text input / textarea.

IF it is a relation:
→ show a selector from existing canonical records.

IF it is numeric:
→ use appropriate numeric input.

Examples:

Bloom / cognitive level:
→ SELECT from existing allowed levels.

Exercise type:
→ SELECT from existing allowed types.

Topic:
→ SELECT existing Topic.

MicroNode relation:
→ SELECT existing MicroNode.

Page:
→ numeric/text input according to existing schema.

Learning Objective:
→ textarea.

Theory/source context:
→ textarea.

Do not make the teacher memorize internal enum strings.

Show human-readable Armenian labels where the UI already has them.

==================================================
12. COPY/PASTE FRIENDLY
==================================================

The editor must be optimized for teachers who prepare the mapping
externally and copy/paste it field by field.

Therefore:

- textareas should be reasonably large;
- labels must be clear;
- Topic and MicroNode cards should be visually separated;
- avoid tiny nested popup windows where possible;
- use one wide workspace;
- long theory/Teaching Content fields should be easy to edit;
- Save/Cancel controls should remain obvious.

The teacher should be able to receive a mapping from ChatGPT and quickly
paste each block into the corresponding field.

==================================================
13. SAVE BEHAVIOR
==================================================

Manual work must be saveable incrementally.

Example:

Teacher creates:

1 Topic
1 MicroNode
title
Learning Objective

and clicks:

Պահպանել սևագիր

This must save successfully.

Do NOT require:

- complete Cognitive Paths
- complete Teaching Content
- exercises
- Outcome relations
- full source alignment
- AI validation
- all Topics to be finished

just to save a manual draft.

Manual Draft Save is CRUD persistence, not final approval.

==================================================
14. VALIDATION UX
==================================================

Do NOT run the Automatic Mapping all-or-nothing validators as a prerequisite
for every manual save.

Instead, show simple actionable warnings.

Examples:

⚠️ Այս MicroNode-ը չունի ճանաչողական ուղի։

⚠️ Ուսուցման բովանդակությունը լրացված չէ։

⚠️ Աղբյուրային էջը նշված չէ։

Warnings must not erase teacher work.

Warnings must not prevent draft save.

==================================================
15. TEACHER AUTHORITY
==================================================

The teacher is the author of manual mapping data.

Therefore teacher-created MicroNodes must NOT be forced through an AI
atomicity-repair loop before they can be saved.

If an existing validator detects a possible quality issue,
show it as review information where safe.

Do not silently change teacher-authored text.

Do not automatically split teacher-authored MicroNodes.

Do not automatically delete teacher-authored records.

Final learner-delivery safety remains handled by the existing
assignment/preflight system.
