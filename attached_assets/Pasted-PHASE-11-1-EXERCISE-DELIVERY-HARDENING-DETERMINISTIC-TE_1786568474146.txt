PHASE 11.1 — EXERCISE DELIVERY HARDENING
DETERMINISTIC TEXTBOOK EXERCISE DELIVERY

GOAL

Phase 11 proved that the complete Knowledge Base pipeline works, but it exposed one remaining runtime gap:

A real CLASS exercise is correctly:
- preserved from the textbook,
- stored in lesson_exercises,
- linked to the correct MicroNode,
- selected by chat.ts,
- inserted into AI context as exerciseTextVerbatim,

BUT the model may still fail to show that verbatim exercise in student_message.

This must NOT remain model-dependent.

For V1, when the backend has selected a real textbook CLASS exercise with a non-empty exerciseTextVerbatim, the student-visible exercise delivery must be deterministic.

The backend — not model compliance alone — must guarantee that the selected textbook exercise is actually presented to the student.

This is a narrow hardening task.

DO NOT redesign the AI Teacher.
DO NOT change mapping.
DO NOT change Phase 5–9 logic.
DO NOT change Knowledge Base structure.
DO NOT modify quiz flow.
DO NOT change exercise attribution.
DO NOT perform unrelated refactoring.

═══════════════════════════════════════════════════
STEP 1 — DEFINE THE HARD GUARANTEE
═══════════════════════════════════════════════════

The invariant must be:

IF:

- the current teaching flow is delivering a CLASS exercise,
- the backend has selected a specific exercise,
- exerciseTextVerbatim is non-empty,

THEN:

the final student-visible response MUST contain the exact
exerciseTextVerbatim string.

This must remain true even if the AI model:

- ignores the prompt directive,
- paraphrases the exercise,
- returns only a transition sentence,
- returns a different question,
- omits the exercise entirely.

The backend is authoritative.

The model must not be the final authority over whether the real
textbook exercise appears.

═══════════════════════════════════════════════════
STEP 2 — IMPLEMENT MINIMAL BACKEND ENFORCEMENT
═══════════════════════════════════════════════════

Implement the smallest safe fix in the existing chat runtime.

Preferred architecture:

AI response
    ↓
existing structured validation
    ↓
exercise-delivery enforcement
    ↓
final student_message
    ↓
HTTP response

When a specific CLASS exercise is being delivered:

const expectedExercise =
  selectedExercise.exerciseTextVerbatim?.trim();

If expectedExercise is non-empty:

A. If student_message already contains expectedExercise exactly:
   → leave student_message unchanged.

B. If student_message does NOT contain expectedExercise:
   → backend must ensure the final student-visible response contains it.

Do NOT ask the AI again merely to reproduce the exercise.

Prefer deterministic backend insertion/fallback.

For example, conceptually:

if (
  isExerciseDeliveryTurn &&
  expectedExercise &&
  !studentMessage.includes(expectedExercise)
) {
    studentMessage = expectedExercise;
}

OR, if preserving a useful short transition is clearly safe:

studentMessage =
  existingTransitionText +
  "\n\n" +
  expectedExercise;

But the exact textbook exercise MUST remain byte-for-byte / character-for-character unchanged.

Choose the safest minimal implementation based on the existing response architecture.

Do not duplicate the exercise if the model already returned it correctly.
