## Rule

Never hardcode a bcrypt hash without verifying it was actually generated by bcryptjs. The code_execution sandbox cannot import bcryptjs from the workspace pnpm store, so inline hash generation there silently produces wrong output.

**Why:** During myaiteacher build, a hardcoded hash was inserted for seed user `student1`. The hash was incorrect (likely copied or guessed), causing login to always return "invalid credentials" even with the right password.

**How to apply:** To generate a real bcryptjs hash for DB seed data, run:

```bash
node -e "const b = require('/home/runner/workspace/node_modules/.pnpm/bcryptjs@3.0.3/node_modules/bcryptjs'); b.hash('yourpassword', 10).then(h => console.log(h))"
```

Then paste the output hash directly into the SQL INSERT or UPDATE. Do not use code_execution for this — it lacks access to the pnpm-installed bcryptjs package.
